## 1. 最后追加要求

### 开战边界

持续交涉仅限未开战遭遇。战斗面板移除交涉按钮，服务端在旧动作回放之前拒绝战内交涉；旧消息点击后只提供战斗面板和操作面板。启动升级会释放旧版战内交涉占用，保留心情、失败记忆和账本。

### 消息排版

- 行为文案使用引用并加粗。
- “已交付：”单独成段，物品名称和数量另起引用；拒收则显示“对方未收下：”及“仍在背包”。
- 每条背包物品的圈号、名称、数量在引用中加粗，蓝色 `[交涉]` 命令链接紧随其后，位于同一引用行。
- 客观分类另起引用行，物品之间空行，避免“草药 ② …”粘连。
- 每页最多十条，保留上一页、搜索、翻页、下一页；交谈与刷新在下一行，主动开战与离开在末行。
- 点击物品后进入数量确认，默认一件，可修改数量；查看和返回不消耗物品。

### 拒收物品

| 偏好 | 库存 | 心情 | 开战 |
| --- | --- | --- | --- |
| 喜好 | 实际收下才扣未绑定数量 | 按价值提升 | 提升动作不会触发 |
| 一般 | 不收下，仍在背包 | 不变 | 按当前心情动态判定，低于同心情厌恶风险 |
| 厌恶 | 不收下，仍在背包 | 按价值降低 | 按降低后的心情动态判定 |
| 满心情下继续送喜好 | 拒收，不扣物 | 保持满值 | 不触发，提示交谈 |

一般与厌恶物品即使触发开战保护或真的开战也不扣物。拒收仍校验实际持有量与绑定数量，不能伪造库存试探。重复回调重放同一结果，不重复扣物、判定或结算。

30 类生物的共 120 条一般/厌恶行为已改为观察、回避、拒绝和示警；不再描写把拒收材料碾碎、吞下、溶解或丢失。喜好反应保留收取动作。

## 2. 规则实现

| 功能 | 实现口径 |
| --- | --- |
| 幸运、魅力 | 独立生成的永久隐藏整数，范围 -100～100，按 μ=0、σ=30 的离散正态权重抽取；幂等补齐，不重抽已有值 |
| 隐藏边界 | 保存于独立表；人物面板及管理 DTO 不增加数值字段，没有查看指令 |
| 心情 | 默认 0%“戒备”，允许降到 -100%；八档展示，保存精度为百万分之一，支持单模板初始值覆盖 |
| 容量 | 按怪物基础战斗掉落的参考期望价值估算，不计玩家幸运和组队增益；首次交涉冻结快照 |
| 喜好提升 | 交付价值÷容量，每次最多 +25 个百分点；小数余值保留 |
| 厌恶下降 | 交付价值÷容量×1.5，每次最多 -35 个百分点；拒收不免除冒犯 |
| 交谈成功 | `p=max(m,0)^(ln(0.2)/ln(0.5))`，魅力修正 `0.5×charm/100×p×(1-p)`；中性魅力下 50% 心情为 20%，满心情必成 |
| 一般风险 | `min(0.9,0.08×(1-m)^2)`，使用动作后心情；8% 只是 0% 心情的取值 |
| 厌恶风险 | `min(0.95,0.25×(1-m)^1.5)`，使用动作后心情；25% 只是 0% 心情的取值 |
| 交谈失败 | 心情 -2 个百分点、失败次数增加，随次数与负心情提高激怒风险 |
| 善意保护 | 不降心情期间累计三次真实提升兑换一层，可重复累积；一般不打断，下降重置未兑换进度；只拦截原本会触发的开战 |
| 心情记忆 | 同一怪物生命共享上次心情，接手者继承；与当前队员历史取最低值；换队和避战不能重置 |
| 失败名单 | 真实交涉失败开战记录当次参与玩家；以后包含任一失败者的队伍直接失败，优先于礼物和保护；新参与者同步记录 |
| 主动结束 | 主动开战、离开、超时不额外写交涉失败名单 |
| 交涉掉落 | 心情倍率 `2×max(m,0)`；50% 为既有交涉基准，100% 为其两倍，过早成功降低产出 |
| 队伍幸运 | `Π(1+0.2×luck/100)`，四人极端值为 0.4096～2.0736；普通战斗与交涉结算接入 |
| 队内分配 | 各真实获奖成员使用 0.8～1.2 权重再归一化；原掉率加成的参考成员仍均匀选取 |
| 超额掉落 | 整数批次加小数概率批次；互斥组每批独立选一种，数量在批次内抽一次，再按件分配 |

这里的 `m` 是心情比例，例如 50% 对应 0.5。50% 的“基础”保留原交涉渠道的 20% 系数，不擅自替换成完整击杀产出。原个人 `dropBonus` 仍在该系数之后相加；原交涉经验折算、固定任务奖励不受新幸运倍率影响。

## 3. 战斗与事务接入

- 遭遇交涉首先只读预览；第一项有效动作才锁定参与者并消费遭遇体力。交涉转战斗沿用体力凭证。
- 已开战时禁止预览、交谈、贿赂和旧赠物结果回放，回合尚未行动也不例外。
- 战前交涉失败或主动开战后，敌方完整先手一次；离开与 120 秒超时只释放会话。
- 页面版本和动作账本防止重复提交；库存、心情、保护、成员记忆、战斗转移与奖励在同一事务内。
- 交涉期间相关移动、组队、配置、用物、PVP 和自动行动入口阻止穿透会话状态。
- 战前说服部分敌人后，可以另行与其余敌人开战，生命奖励账本避免重复领取。
- 城镇执法遭遇和平离开不清除通缉、债务或罚款且无交涉奖励；试炼及测试和平退出不当作击杀通过。
- Boss 部位委托本体，临时召唤物不独立收买发奖；国王组合按关联在场成员共同处理。
- 更新前已开始的战斗继续旧奖励版本，下一场新战斗才使用新幸运和交涉规则。

## 4. 数据与文案覆盖

最后一次只读数据库审计：13,356 种物品中允许 11,904 种，禁止 1,452 种；204 个怪物模板归入 30 类形态。数量为当时快照，动态模板及物品变化后可重新生成。

实例装备、装置、地图、重要任务物、进化材料、技能书、凭证等优先排除；普通掉落材料与十二类粒子使用同一准入函数。普通任务收集材料不因被任务引用就一律禁用。零收购价怪材复用已有炼金固定成本；家园专用木材、石料、金属暂因缺少统一交涉估值而拒绝，逐项写入清单。

怪物模板 × 八档心情 × 三种偏好 × 两个变体，共 9,792 个组合通过覆盖检查。行为主体按形态共享，粒子与材料的感官细节参与组合；这不等于每个模板都独立手写整套句子。哥布林耳朵、活木等单品例外优先于类别偏好，但不能放行全局禁用物。

## 7. 2026-09-09 组队战斗掉落归属修复

战斗结算接入天赋掉落包后，生成前抽取的参照成员同时成了整包固定收件人，导致同一只怪物掉落的不同物品及整组材料全部归该成员。问题位于 `finishPartyVictory`，交涉结算仍然使用逐件分配。

修复保留一次掉落包生成及其现有天赋、概率、数量规则，生成后每件物品重新按合资格队员的幸运权重抽签。同一物品按最终收件人归并入库，装备按件创建实例；不把一份战利品复制给多人，也不强制平均分配。

新增四人实际冒险服务回归：固定归属抽签覆盖四个权重区间，执行真实掉落生成、战斗结算和临时 MySQL 入库，核对材料与实例装备分给多人、总量守恒、每人结算与实际库存一致。冒险集成测试的六个子测试及父测试通过；类型检查通过。测试库已清理，本次未重启或部署机器人，未补发历史奖励。
