# 战斗交涉与隐藏幸运、魅力系统设计方案 V1

> 日期：2026-09-07。状态：已按本次确认需求接入源码，数据库及客户端部署状态见第 18 节。
>
> 本文已对照当前工作区的遭遇交涉、战斗胜利结算、怪物模板、库存绑定和自动战斗入口，并纳入追加要求：失败开战的玩家被该怪物记住、后续所在队伍必定交涉失败；其他人接手同一怪物继承其上次心情。方案已进入实现阶段；第 2 节保留实施前基线，其余章节说明规则和边界。实际表、入口、验证范围与采用默认值以第 18 节及实施验收记录为准，不代表正式服务已经升级。

## 1. 设计目标与规则总览

将当前“一次交涉、失败立即开战”的操作，扩展为能够观察、试探、赠物和持续交谈的交涉会话。玩家通过怪物的动作、声音和措辞判断其态度，用物品改善心情，再决定何时交谈达成协议。

### 1.1 必须满足的需求

1. 玩家新增基础隐藏维度：幸运、魅力，均在整数 `[-100,100]` 内按正态形状的概率分布独立抽取，任何时间不可查看。
2. 所有怪物具备心情体系，心情容量与综合掉落价值挂钩，心情按百分比分档展示；默认初始心情为 0%，对应“戒备”档，允许配置为负数，实际心情也允许下降至负值。
3. 所有怪物具备喜好、厌恶物品清单；清单之外为一般物品。
4. 交涉分为交谈、物品贿赂；喜好提高心情，厌恶降低心情，一般物品不提高心情。
5. 在具备交涉资格的前提下，成功率随心情按曲线上升：前段慢、后段快；50% 心情约 20%，100% 心情必成。失败开战记录的必败规则优先于该曲线。
6. 未触发开战或成功前，可以持续交涉。一般、厌恶物品的开战概率按每次动作后的实际心情动态计算，不使用固定概率；同一心情下，一般物品明显低于厌恶物品。
7. 交谈直接进行一次成功判定，魅力影响该次概率；交谈反复失败会越来越容易开战。
8. 交涉成功时，50% 心情对应基础掉落；低于 50% 降低产出，高于 50% 才提供额外提升，100% 心情为基础的两倍，心情来源的额外提升上限为 100%。
9. 怪物记录交涉过的玩家；躲避、逃跑、换队之后，按当前队伍最低心情同步，不能换队洗掉恶劣态度。
10. 每名玩家幸运对全队掉落的贡献为 `-20%～+20%`，对其自身队内分配权重的影响也为 `-20%～+20%`。
11. 每只怪物每个心情档位，对喜好、厌恶、一般物品至少各有两条描述；不同物品种类有不同反应。
12. 交涉失败并触发开战时，记录当次全体实际参与玩家；以后同一怪物面对包含任一被记录玩家的队伍，必定直接交涉失败，不掷概率、不允许先送礼洗白。
13. 同一怪物保留上一轮结束时的共享心情，其他玩家或队伍接手继承该值；再与新队伍既有个人心情记录取最低值。陌生队伍不将怪物重置为初始心情。
14. 已通过交涉资格检查的动作，只要实际提升心情，就不会触发开战；此规则适用于所有提升心情的举动，不限于赠送喜好物品。
15. 心情未下降期间，每累计 3 次实际提升心情的动作，获得 1 次开战保护，可重复获得和生效；心情不变的动作不增加也不打断累计。保护可拦截一次原本会发生的交涉激怒开战，但不免除本次心情下降。一般与厌恶物品本就拒收，不扣库存。
16. 全量已有物品必须建立交涉分类与准入结果；实例物品、任务重要物品、地图等禁止用于交涉，主要接收普通掉落材料、粒子等安全堆叠资源。准入与怪物喜好是两套独立判断。
17. 点击交涉后直接显示交涉页面及本人背包中的可交涉物品，每页 10 条，以 ①～⑩ 编号；每条右侧为蓝色行内命令链接 `[交涉]`。列表下方提供上一页、搜索、翻页、下一页按钮，再下方提供交谈按钮。
18. 每种怪物都要配置倾向和厌恶的物品类型；粒子必须进一步按元素/能量类别区分倾向与厌恶，不能将所有粒子视为同一种反应。具体物品清单由类型规则展开，并允许明确的单品例外。

## 3. 幸运与魅力：终身隐藏的基础维度

### 3.1 取值及生命周期

| 属性 | 内部字段建议 | 范围 | 作用 |
| --- | --- | --- | --- |
| 幸运 | `luck` | -100～100 整数 | 全队物品产出、自身分配权重 |
| 魅力 | `charm` | -100～100 整数 | 本人发起交谈时的成功概率 |

- 使用服务端安全随机源，按第 3.3 节有界离散正态权重分别抽取两个独立值，不用角色 ID 取模，不采用均匀分布。
- 数值属于角色身份，以稳定的 `character_id` 为键；昵称、平台绑定、队伍、职业、装备变化均不重生成。
- 升级、进化、属性重算、转职不更改隐藏基础值；不进入可分配属性点池。
- 本期不新增洗练、查询、鉴定、增减道具、付费重置或管理命令。
- 老角色补齐是幂等迁移，已有合法值不得覆盖。生成失败则本次事务失败，不能每次请求临时重掷。
- 合成 NPC 队友不参加幸运贡献与分配，也不能担任交谈者。

### 3.2 “任何时间不可查看”的落实

隐藏不仅是状态面板不显示，还包括以下出口：

- 角色面板、详细属性、战斗面板、鉴识、怪物/玩家图鉴、队伍信息、排行榜。
- 管理网页、管理员游戏命令、导出报表、活动预览、调试接口、错误信息。
- 网络响应、图片渲染输入、按钮参数、消息缓存、全量角色对象序列化。
- 结算说明中的“幸运 +x%”“个人权重 x”“本次成功率 x%”等间接精确展示。
- 普通日志不能记录真实属性、加成分解或可以逆推属性的明细；错误日志采用允许字段列表。

建议独立 `character_hidden_attributes` 表，并由内部计算函数读取；公共 `CharacterRow` 和玩家展示 DTO 不包含这两个字段，避免 `SELECT c.*` 自动扩散。

数据库管理员对底层存储的技术访问不能靠游戏界面规则消除；本设计保证产品和业务接口没有查询能力，不声称拥有数据库全部权限的人无法读取数据。长期统计战果可能让玩家猜测运气好坏，也不等同于系统直接展示数值。

### 3.3 有界正态概率抽取

用户已明确按正态分布抽取；由于属性必须为有限范围的整数，本方案采用**在 -100～100 上归一化的离散正态权重分布**。建议中心参数 `μ=0`、尺度参数 `σ=30`，使大多数角色接近中间值、正负极值稀少。μ、σ 是建议参数，不是用户已指定数值；截断后的实际标准差不严格等于 σ。

```text
k ∈ {-100,-99,...,99,100}
weight(k) = exp(-(k-μ)² / (2σ²))
P(X=k) = weight(k) / Σ[j=-100..100] weight(j)

建议 μ=0，σ=30
luck 和 charm 各自独立抽取一次
```

按上述离散公式计算：

| 取值区间/单点 | 概率约 |
| --- | ---: |
| -30～30（含端点） | 69.1269% |
| -60～60（含端点） | 95.7052% |
| -90～90（含端点） | 99.8252% |
| 恰好 +100 | 0.005145% |
| 恰好 -100 | 0.005145% |

生成方式：按固定版本预计算 201 项归一化概率和累计分布，读取服务端安全随机源产生的 `[0,1)` 均匀随机数，以累计分布反查整数值。最后一项累计概率设为 1，仅吸收浮点舍入误差。禁止把超界正态样本直接钳制到 ±100，避免端点堆积；也不要先均匀抽整数再声称结果服从正态分布。

两属性不共用同一次抽取值、不绑定正负、也不要求相加为 0。分布中心为 0 不等于每一批创建的角色必须正负人数相等。保存初始化分布版本，参数调整只影响后续尚未生成的角色；幂等迁移不得重抽已有数值。

本次仅变更设计，尚无本功能已经上线的均匀分布属性需要重掷。新角色与老角色首次补齐都使用正式批准的同一分布。

## 4. 怪物心情容量与综合掉落价值

### 4.1 固定价值表

使用服务端、可版本化的参考价值 `v(item)`，单位为“价值点”，数值尺度可与铜币参考价值一致。

建议取值顺序：

1. 明确配置的交涉参考价值覆盖值。
2. 非零、经策划确认的基础 `trade_price`。
3. 无可用价格的物品必须人工补值；不能默认为高价值，也不能用交易行当前成交价。

该价值表同时用于掉落估值与贿赂估值，防止同一种物品在两端价格倒挂。装备仅按定义基础价值计入掉落估值，随机强化和附加属性不加价。禁止贿赂的物品仍可有掉落估值。

### 4.2 综合掉落期望价值

对怪物实例解析最终有效掉落清单后，定义：

```text
V = Σ [p_j × E(q_j) × v(item_j)]
M = max(1, V)

p_j = 单人、无玩家增益、无全服活动时，该实例该条掉落的有效基础概率
E(q_j) = 固定数量，或均匀整数区间的 (min_quantity + max_quantity) / 2
M = 心情满值容量（价值点）
H = 当前心情价值点，范围 [-M, M]
m = H / M，范围 [-1, 1]，负值表示需要先修复的敌意
```

必须包含怪物自身的掉落词条、等级解析、材料代码映射、固定补充掉落等真实掉落逻辑。条件性、互斥掉落不能简单当作全部必出相加，应由同一掉落解析层返回期望项。可重复的额外随机物品纳入估值；任务一次性奖励、经验、玩家幸运、组队加成、丹药、全服活动不计入。

“同等”在本文指 `M = V`，零掉落实例用 1 作数值安全下限。不是所有怪物同一个容量，也不是把所有掉落最大数量、100% 概率相加。

例如：

| 掉落 | 基础概率 | 平均数量 | 单价 | 期望价值 |
| --- | ---: | ---: | ---: | ---: |
| 材料甲 | 100% | 2 | 20 | 40 |
| 材料乙 | 50% | 2 | 60 | 60 |
| 材料丙 | 25% | 1 | 400 | 100 |
| 合计 | | | | 200 |

该怪物 `M=200`，默认初始 `H=0`，即 0%。若档案配置初始 -30%，则 `H=-60`。价值 20 的喜好物品，在喜好系数为 1 时可提高 10 个百分点；从 -30% 提升到 -20%，不是直接从 0% 开始累积。

### 4.3 精度、快照与配置变化

- `M` 保留高精度定点值；`m` 建议用有符号百万分位整数 `mood_ppm ∈ [-1000000,1000000]` 持久化，显示档位不能反过来参与计算。初始化必须使用显式缺失判断或 `??`，不能用 `value || default` 把合法的 0 当作未设置。
- 一次贿赂按整批价值计算并统一舍入；保留低于百万分之一的正向余数，不能每件保底加 1 点或 1%，否则低价拆单可刷心情。
- 价值表、掉落定义、偏好、文案配置均记录版本。实例第一次进入新系统时冻结该生命期配置；后续进入会话不能重新估价。
- 活着的怪物词条变动不重置心情容量；该次生命的交涉奖励基准使用冻结快照。实际战斗击败奖励仍按战斗结算规则处理。
- 热更新只影响新生命实例；旧配置保留到引用实例结束。若需修正错误，显式迁移并保留心情百分比，不能悄悄重新随机。

### 4.4 心情档位

所有可交互怪物都显示心情词条，不依赖玩家学习鉴识；高阶鉴识仍不能透视偏好清单或玩家隐藏属性。

| 档位代码 | 百分比范围 | 玩家显示 | 行为基调 |
| --- | --- | --- | --- |
| `furious` | -100% ≤ m < -50% | 暴怒 | 强烈排斥、随时扑击、拒绝靠近 |
| `resentful` | -50% ≤ m < -20% | 愤懑 | 烦躁、低吼、对礼物充满怀疑 |
| `hostile` | -20% ≤ m < 0% | 敌意 | 护住要害、逼近、排斥 |
| `wary` | 0% ≤ m < 40% | 戒备 | 审视、保留距离、试探；包含默认初始状态 |
| `hesitant` | 40% ≤ m < 60% | 迟疑 | 停顿、比较、敌意松动 |
| `receptive` | 60% ≤ m < 80% | 缓和 | 收敛威胁、靠近、回应 |
| `pleased` | 80% ≤ m < 100% | 欣悦 | 主动接近、珍视赠物、愿意听话 |
| `trusting` | 恰好 100% | 信任 | 明确愿意达成协议 |

0% 是“尚未建立信任但愿意观察”的戒备起点，不标为敌意。心情跌至负数才进入敌意、愤懑或暴怒；例如初始 0% 交谈失败后变为 -2%，显示“敌意”。所有档位区间连续且不重叠，边界按表中左闭右开处理，100% 单独归入信任。档位只负责表现，不重映射真实心情：0% 仍使用 0% 的基础成功率，50% 仍为 20%，不会因名称调整改变概率曲线。

档位属于交涉状态，不混入会影响攻击、血量的随机战斗词条乘算。同一怪物生命实例有唯一的共享当前心情，不同队伍依次接手都会继承它；它不是整个物种、整个地图或全服务器怪物共用的一个数值。存在更低个人历史记录的队伍会使有效心情进一步降低，实际动作接受后写回共享状态。

失败开战记录是独立的资格状态，不属于心情档位。怪物可以对陌生人心情良好，但仍拒绝和曾经激怒自己的玩家及其队伍交涉；面板此时以“拒绝交涉”作为主提示，不能显示成已获信任。

## 5. 偏好清单与物品种类

### 5.1 配置方式

每个 `monster_template_code` 必须绑定经过展开校验的独立交涉档案：

```typescript
type PreferenceRule = {
  kind: 'item' | 'subtype' | 'category' | 'tag';
  value: string;             // 稳定物品 code、交涉子类型、大类或语义标签
  strength?: number;         // 喜好默认 1，厌恶默认 1.5
};

type MonsterNegotiationProfile = {
  monsterCode: string;
  version: number;
  initialMoodPpm: number;    // 默认 0，允许 -1000000～1000000
  likes: PreferenceRule[];
  dislikes: PreferenceRule[];
  voiceProfile: string;
  categoryReactionKeys: Record<string, string>;
  completionPolicy: string; // 普通退出、Boss 整体退出、特殊脚本结果等
};
```

匹配优先级为“精确物品 code → 明确子类型 → 语义标签 → 物品大类 → 一般”。例如火粒子子类型的厌恶覆盖笼统的粒子大类喜好。同层级同时命中喜好与厌恶是配置错误，发布校验直接失败，不由运行时随机选择；单品覆盖类型的例外必须明确标注。多个同性质规则命中只取最高优先级的一条，不把喜好倍率相乘。一个物品的高优先级最终结果决定它是喜好、厌恶还是一般，不能同时加减心情。

标签建议包括：鲜肉、植物食材、甜食、草药、金属矿物、晶石、火性、寒性、腐败、机械零件、骨质、同族遗骸、圣性、暗性。标签是策划配置，不按物品名称模糊包含关系判断。

“倾向”在本版表示匹配该类型即按喜好规则处理，不是每次送同一物品重新抽签决定喜恶。没有配置倾向或厌恶的类型才按一般物品处理。这样玩家可以通过行为文案形成稳定判断。

### 5.2 全怪物覆盖要求

- 每个怪物至少有 2 个可实际获得的喜好物品、2 个厌恶物品；允许先用标签配置，再展开为真实物品 ID 清单验收。
- 每个怪物必须有非空的倾向物品类型与厌恶物品类型；不能只填两个孤立物品 code 来代替类型设计。
- 每个怪物必须完成粒子子类型矩阵，至少明确一种倾向粒子类型和一种厌恶粒子类型；若当前物品库确实缺少该类型的可交涉实物，需在覆盖报告列为待补内容，不能用不存在的物品冒充完成。
- 每个怪物至少有 2 类可区分的喜好反应，例如食物与晶石；如果设定确实只喜欢一种类别，需以两个有明显差异的子类落实反应。
- 厌恶清单必须也有当前规则允许给予的物品，不能全部由禁止贿赂的任务物组成。
- 普通、巨型、精英、Boss、迷宫怪、动态事件怪、试炼怪、执法者均进入覆盖清单，不能靠通用“它看起来很高兴”回退冒充完成。
- 动态模板可以继承生态族群的标签基础，但必须生成经过审核的自身清单和物种动作覆盖。
- 喜好、厌恶清单仅服务端持有。面板按背包类别展示物品，不能自动按“推荐礼物”“不喜欢”排序泄露答案。

### 5.3 物品可用性

**所有已有物品都要有分类结果，但不代表全部可用于交涉。** 可交涉清单以普通掉落材料、粒子、常规加工原料等为主；实例物品、任务重要物品、地图明确禁止。物品分类在所有怪物间统一，怪物的喜好/厌恶只在通过准入后再判定。

仅允许明确标记 `negotiation_usable=true`、通过所有硬性排除规则且本人有可用数量的堆叠物进入页面。`is_tradeable=1`、名称包含“材料”、能从怪物掉落、存在交易价格，均不能单独作为准入依据。

全部实例行都拒绝，不论是否绑定、装备、生效、寄售；装备、异械、机巧等即使历史上错误存入堆叠背包，也按定义类型拒绝。不存在“先给实例做估值就可以贿赂”的例外。本期不设计任何实例交付入口；奖励端仍可正常获得装备实例，与输入限制分开。

仅喜好物品使用未绑定数量扣除：`consumeInventory(..., true)`。一般与厌恶物品只锁定并校验实际持有的未绑定数量，不扣除、不改变绑定状态。个人绑定和交易绑定物品暂不接收，避免绑定材料通过怪物兑换为可交易奖励。该项为本次采用的物品边界，普通绑定材料不会被错误地兑换成自由流通奖励。

### 5.4 已有分类的全覆盖矩阵

当前背包有装备、道具、材料三大类，以下覆盖当前源码声明的全部子分类，并补充别名、独立实例资产和保护状态。此表是全量分类的规则，不代表已完成正式数据库每个 item ID 的审核。

| 现有类型/分类 | 交涉分类 | 默认准入 | 判定说明 |

| 武器、副手 | 装备实例 | 禁止 | 包含历史堆叠存储异常项 |

普通材料被某个任务要求收集，不自动变成“任务重要物品”，否则大量怪材都会被误禁。需要排除的是任务专用、唯一/限次推进、消耗后可能破坏剧情或明确标记为重要的物品；已经被任务托管/预留的普通材料数量也不能交付。

已核对到的边界示例：

- `healing_herb` 在现有 bootstrap 中有被归为“药剂”的逻辑，应按普通草药真实用途审查，不能仅因子分类不同漏掉。
- `map_*` 和带地图功能的物品统一禁止，现有区域地图即使 `stackable=1` 也不例外。
- `celestial_judicator_imitation` 是主线专用装置，明确禁止；同样处理任务重要凭证和专用推进物。
- `sky_dust`、`evolution_seed` 在背包有主线交互，必须核对真实用途和保护属性，未完成逐项审核前不因“粉尘/材料”名称自动允许。不能据此将所有普通元素粒子一并禁止。
- 怪物掉落的图纸、技能书、任务物仍禁止；怪物掉落的普通材料可以允许。掉落来源只提供分类证据，不能覆盖禁止规则。

### 5.5 全量物品分类清单与准入顺序

实施阶段必须将已有 `item_definitions`、动态注册材料、地图生成项、配方生成项及相关保护规则合并，按稳定 item code 输出**一物一行**的完整分类清单，不只列热门物品。清单至少包含：

```text
item_id / item_code / 中文名 / 原 item_type / 原 item_category
是否实例类型 / 是否可堆叠 / 交涉用途分类 / 偏好语义标签
允许或禁止 / 中文原因 / 重要或任务保护依据
参考价值及来源 / 配置版本 / 审核状态
```

分类配置建议以稳定 code 保存，不能在代码里按生产库自增 ID 手写名单。展示分类与物品准入互相独立，避免为交涉调整标签而顺带改坏普通背包分类。生产库历史项目和未知 code 也必须进入报告，未审核项禁止交付，不允许静默遗漏。

服务端统一执行以下顺序，列表、搜索、物品选择、最终交付必须共用同一个策略函数：

1. 目标/玩家交涉资格通过。
2. 数据来源确为本人堆叠背包，排除实例来源、装备/异械等实例定义、非堆叠定义。
3. 排除任务重要、地图、图纸、技能书、货币、剧情、锁定/托管等强保护项；显式允许项不得覆盖这些排除条件。
4. item code 已完成分类且标记可交涉；未知项禁止。
5. 价值和偏好类别配置完整，数值合法。
6. 本人可用未绑定数量扣除预留/锁定后大于零。
7. 最终交付事务内重验相同规则并按稳定 item ID 扣量，不接受客户端传入的分类或 `usable` 布尔值。

验收统计要求：全量定义数 = 已审核允许数 + 已审核禁止数，未分类数为 0；所有动态生成入口也有显式策略。只有完整清单和检查报告具备证据，才能宣称“所有已有物品已分类”。本次设计文档未连接生产数据库，不把当前源码分类矩阵冒充这份全量实物清单。

### 5.6 每种怪物的类型倾向与粒子偏好

交涉类型是独立于背包粗分类的语义分类。普通物品可分为兽肉/食材、植物/草药、骨质/兽材、金属/矿石、木石/建材、机械零件、炼金原料等；粒子大类进一步分为具体元素和能量性质。同一大类内可以喜欢一部分、厌恶另一部分。

粒子分类建议覆盖项目现有的火、水、土、木、风、冰、雷、光、暗九种元素语义，另对确实存在的无属性、混合或特殊能量物品逐项登记。下列类别标识为拟议配置值，不代表现有物品 code：

| 交涉子类型 | 展示名称 | 反应细节 |
| --- | --- | --- |
| `particle.fire` | 火性粒子 | 热浪、火星、灼烧感 |
| `particle.water` | 水性粒子 | 水纹、湿润、流动感 |
| `particle.earth` | 土性粒子 | 沉重、砂砾、稳定感 |
| `particle.wood` | 木性粒子 | 草木气息、生机、枝叶舒展 |
| `particle.wind` | 风性粒子 | 轻旋、气流、毛羽摇动 |
| `particle.ice` | 冰性粒子 | 霜痕、寒气、凝结 |
| `particle.thunder` | 雷性粒子 | 电弧、噼啪声、震颤 |
| `particle.light` | 光性粒子 | 明亮、净化、灼目感 |
| `particle.dark` | 暗性粒子 | 阴影、幽光、魂性共鸣 |

以物品真实配置的元素、效果与用途映射，不用英文 code 或中文名称猜元素。普通金属矿物不自动等于土性粒子，普通结晶也不自动归到任一元素；需要明确的分类数据。

每种怪物配置 `preferredTypes`、`dislikedTypes` 和 `particleAffinity`；`particleAffinity` 对每个已有粒子子类型明确填 `like / dislike / neutral`，不允许漏填后静默当作一般。它们是同一偏好档案的作者侧配置，编译成第 5.1 节的统一规则后运行，不能再维护一套互相矛盾的判定逻辑。

以下为生态方向样例，具体强度和全怪物矩阵仍需逐种审核：

| 怪物 | 倾向的普通类型 | 厌恶的普通类型 | 倾向粒子 | 厌恶粒子 |
| --- | --- | --- | --- | --- |
| 森林史莱姆 | 草药、植物原料 | 腐败原料、刺激性材料 | 木、水 | 火、雷 |
| 树精 | 草木养分、普通植物材料 | 污染物、焦化材料 | 木、水 | 火、暗 |
| 幽狼 | 鲜肉、兽性材料 | 腐败食材、刺激性药材 | 暗、风 | 光、火 |
| 球兔 | 鲜嫩食材、植物原料 | 血腥原料、辛烈材料 | 木、风 | 火、雷 |
| 哥布林 | 金属、普通机械零件 | 同族遗骸、腐败残料 | 火、土 | 光、冰 |
| 骷髅 | 骨质、普通魂性材料 | 圣性净化材料 | 暗 | 光、火 |

未列出的粒子子类型在样例中按一般处理；正式配置仍需显式填写。所有条目先受准入规则约束：即使某怪物偏爱圣性或魂性，也不能收取对应的任务重要物品。稀有度和价值影响数量收益，不将厌恶元素自动改成喜好。

偏好类型必须进入文案选择键。例如森林史莱姆收到木粒子时表现为绿光融入胶层，收到水粒子时表现为水纹舒展；收到火粒子时胶面冒汽，收到雷粒子时胶层急缩。不能四种物品仅替换名称而复用同一段反应。每个有实物的“怪物 × 心情档位 × 反应子类型”至少有两条适用表达。

交涉页面可以显示客观物品类别，如“火性粒子”，但不能显示“它喜欢火”“推荐木粒子”或喜好排序。玩家仍通过每次给予后的表现识别偏好。

## 6. 交谈成功率与反复失败

### 6.1 基础曲线

```text
a = ln(0.2) / ln(0.5) ≈ 2.3219280949
p_base(m) = max(0,m)^a
```

它通过 `(0,0)`、`(0.5,0.2)`、`(1,1)`，在正心情区间连续递增，后段斜率更大；负心情至 0% 的建议成功率为 0%，整个心情区间单调不减。必须先将负值截为 0 再做非整数幂，避免负数运算得到 NaN。

因此在默认初始 0% 或负心情时直接交谈仍会进行一次判定，但必定未成，并可能激怒；建议先送合意物品改善到正心情。高魅力也不能把 0% 基础概率变为正数。这是沿用原曲线端点后的明确玩法结果，不新增暗中的保底成功率。

| 心情 | 基础成功率，约 |
| ---: | ---: |
| -100%～负心情 | 0% |
| 0% | 0% |
| 10% | 0.48% |
| 20% | 2.38% |
| 30% | 6.11% |
| 40% | 11.91% |
| 50% | 20.00% |
| 60% | 30.54% |
| 70% | 43.68% |
| 80% | 59.56% |
| 90% | 78.30% |
| 95% | 88.77% |
| 100% | 100% |

表格是设计数据，不进入玩家界面。实现必须通过公式计算，不能用四舍五入后的表格查值。

### 6.2 魅力影响

只使用本次实际交谈者的魅力，队长身份无额外优势，不能取全队最大值代替。

```text
c = charm / 100                  // [-1,1]
p_talk = p_base + 0.5 × c × p_base × (1 - p_base)
```

| 心情 | 魅力 -100 | 魅力 0 | 魅力 +100 |
| ---: | ---: | ---: | ---: |
| 0% | 0% | 0% | 0% |
| 50% | 12% | 20% | 28% |
| 100% | 100% | 100% | 100% |

幸运不影响交谈概率；魅力不影响掉落和物品估值。该式保持所有魅力取值下的概率单调性和两个端点，不再套 Boss 8% 上限或迷宫 0.25 折扣。高价值怪物更难讨好由更高的容量和偏好成本体现。公式只适用于未命中失败开战名单的队伍；名单命中时不进入概率计算。

### 6.3 一次交谈的处理顺序

1. 锁定会话、目标与参与者，复验状态和动作版本；先检查失败开战名单，命中任一真实参与玩家则直接交涉失败，按第 9.5 节开战，不进入后续随机判定。
2. 读取本次交谈前的心情 `m_before`，计算 `p_talk`。
3. 生成一次成功随机结果；满心情直接成功，不先进行激怒判定。
4. 成功：用 `m_before` 结算掉落，会话结束。
5. 失败：累计失败数 `f += 1`，心情降低 2 个百分点，最低为 -100%。例如默认 0% 交谈失败后变为 -2%。
6. 使用降低后的心情 `m_after` 计算开战概率：

```text
r_talk = clamp(0.08 + 0.07f + 0.01f² + 0.35 × (1-m_after)², 0, 0.95)
```

7. 开战随机命中：先检查第 7.4 节的开战保护，有保护则消耗 1 次、继续交涉；无保护才记录全体实际参与玩家的失败开战标记，结束交涉并转入或恢复战斗。未命中时继续交涉，不消耗保护、不写必败标记。

其中 `f` 为怪物共享累计失败次数与当前队伍个人记录取最大值后的次数；不是按钮点击次数，也不是仅当前发言者的次数。接手、换人交谈或改队伍不会清零。共享耐心计数随心情一并保留为本文建议规则；失败开战名单则是已明确的硬规则。

例如交谈后心情为 50% 时，第 1、3、5 次失败的开战率分别约 24.75%、46.75%、76.75%；第 8 次达到 95% 上限。整体开战概率是 `(1-p_talk) × r_talk`，不能把失败后的条件开战率直接称为该次总开战率。

“可以持续进行”表示未结束前没有固定对话次数强制截止；随着失败累积，继续空谈会越来越危险。95% 上限不是保证最终能无限试出成功。一旦失败开战，被记录玩家在该怪物生命期内就不再拥有重试概率；逃跑回来也直接失败。

## 7. 贿赂数值、消耗与风险

### 7.1 贿赂动作

一次交付一种物品、一个明确数量；先选择物品和数量，再显示确认按钮。提交前可取消且不扣物品。

失败开战名单检查必须早于库存扣除与偏好判定。名单命中的队伍没有贿赂资格，不能让未被记录的新队友代送，也不能先把心情喂满再让被记录玩家加入。

```text
B = 本批数量 × v(item)
g = B / M

喜好：Δm = min(0.25, strength_like × g)
厌恶：Δm = -min(0.35, strength_dislike × g)
一般：Δm = 0
```

默认喜好系数 1，厌恶系数 1.5；最终心情收敛到 `[-1,1]`。每次喜好最多提高 25 个百分点、厌恶最多降低 35 个百分点。负心情不截为 0 后再加礼物收益，例如 -20% 获得 10 个百分点后为 -10%。两者单次上限为建议调参项。

- 一般物品再贵也不增加心情；价值不能覆盖偏好匹配。
- 贿赂不自动掷成功率，所以玩家可以继续赠礼以追求更高结算心情。
- 到达信任档后，仍需点击交谈才能达成协议；面板给出“它已经愿意听完你的提议”提示。
- 满心情不允许继续消耗喜好礼物；按钮提交前服务端检查，返回“对方已经接受了你的善意”。厌恶物品仍可降低满心情。
- 不根据隐藏偏好计算并展示“最佳数量”或预计涨幅；只展示玩家选择的实际数量和消耗。
- 只有实际收下的喜好物品消耗。一般与厌恶物品不会收下，原样留在背包；即使激怒开战或触发保护也不扣物。仍须校验确实持有足量未绑定物品，禁止用不存在的库存试探。文案必须表现观察、回避、拒绝或示警，不能写吞下、碾碎、溶解、丢失等与库存相反的事实。
- 物品消耗不会加入怪物掉落表；之后击败该怪物不能把全部礼物再领回来。

### 7.2 一般与厌恶物品的激怒概率

先应用本次物品的心情变化，再以实际 `m_after` 动态计算风险。**8% 和 25% 仅为动作后心情恰好 0% 时的曲线取值，不是一般/厌恶物品的固定开战概率。** 本节曲线已按此实现。

```text
r_neutral(m_after) = clamp(0.08 × (1-m_after)², 0, 0.90)
r_dislike(m_after) = clamp(0.25 × (1-m_after)^1.5, 0, 0.95)
r_like = 0
```

一般/厌恶物品完成对应判定后，无论开战与否，对应次数增加 1。喜好物品本身不激怒；所有实际提升心情的动作也统一跳过开战判定，具体见第 7.3 节。赠送喜好物品不会清除累计交谈失败和冒犯记录。

一般/厌恶赠物计数保留作记忆与行为记录，本版不再额外乘入赠物开战概率，避免次数项使一般物品反而比厌恶物品更危险。反复交谈失败的递增风险仍按第 6 节执行，不受此次赠物曲线调整影响。

激怒公式使用真实的 `m_after ∈ [-1,1]`，不将负心情截为 0；因此负心情比 0% 更危险。交谈激怒公式同样如此，各自保留最后的概率上限。负心情本身不等于失败开战名单，未被记录的玩家仍能靠喜好物品修复心情。

每次赠送都按下列曲线计算，表中为若干取样点，实际数值连续变化，不按档位固定开战概率。表格比较的是**相同的动作后心情**，且尚未应用开战保护：

| 心情 | 一般物品 | 厌恶物品 |
| ---: | ---: | ---: |
| -100% | 32% | 约 70.71% |
| -50% | 18% | 约 45.93% |
| 0% | 8% | 25% |
| 50% | 2% | 约 8.84% |
| 90% | 0.08% | 约 0.79% |
| 100% | 0% | 0%（只作为公式端点；有效厌恶物品通常已使心情下降） |

例如同样从 50% 心情开始：一般物品不改心情，按 50% 计算为 2%；若一次厌恶物品使心情下降至 35%，则按 35% 计算，约为 13.10%，不是继续套用 50% 的 8.84%。心情越差，两条曲线的激怒概率越高；同一非满值心情下，一般物品概率均不超过厌恶物品的一半。满心情两者公式均为 0，而厌恶动作通常已使心情离开满值。

激怒随机命中后，先经过第 7.4 节的保护拦截；只有确实开战时，文本才说明敌人发起攻击，并为本次全体实际参与玩家写入失败开战名单。未开战或被保护拦住的厌恶反应不能写成已经造成伤害，也不写必败标记。

### 7.3 提升心情的动作不触发开战

这是已明确的统一规则，不能只在“喜好物品”分支单独实现。

```text
先完成目标、队伍、失败开战名单等资格检查
再同步怪物共享心情与队内最低心情
m_before = 同步完成后、本次动作执行前的心情
计算并应用本次动作效果，得到 m_after

若 m_after > m_before：
    本次动作的开战概率 = 0
    不抽取激怒随机数，不转入/恢复战斗
    不新增交谈失败次数、冒犯次数或失败开战标记
    保护累计次数 +1，每满 3 次按第 7.4 节发放 1 次开战保护
    保存心情、动作结果及已成功发生的物品消耗，继续交涉
否则：
    按具体动作原有规则处理；没有提升不等于必定开战
```

- 负心情改善也算提升：例如 -80%→-70%、-2%→0%，即使仍处于暴怒或敌意状态，也不能因本次动作触发开战。
- 不要求跨档位；例如 10%→11% 同样受保护。判断使用服务端精确心情，不比较显示文字或取整后的百分比。
- 喜好赠物即使因满值保护被拒收、或微小收益暂存精度余数，也维持既有 `r_like=0`，不能因为显示心情没变改走一般物品激怒分支。
- 普通交谈失败会降低心情，一般物品不提升、厌恶物品降低，因此仍按既有对应风险规则处理。将来新增其他改善心情的行为，也必须复用这个统一判断。
- 原有累计失败和冒犯记录保留，但不能在心情提升后追加一次“历史耐心不足”的开战判定；正向动作也不能选择激怒、扑击或造成伤害的结果文案。
- 失败开战名单仍在动作执行之前检查：命中的队伍无法执行提升心情的动作，不扣礼物、不允许用本条洗白。此时直接失败属于资格拒绝，不是成功提升心情后又被激怒。
- 本条保护该动作本身，不撤销玩家之后主动开战、结束战前谈判或独立世界事件等事件。有效正向动作需更新会话活动时间与 revision，超时处理必须复验，不能用旧版本超时结果紧接着把同一动作转成开战。

### 7.4 累计三次改善心情的开战保护

按用户例子，“累计 3 次”指三次有效提升心情的动作，不是连续三个按钮、跨越三个心情档位或提高 3 个百分点。期间允许穿插心情不变的一般物品；发生心情下降才打断尚未满三次的累计。

```text
goodwill_progress：当前未兑换的提升次数，初始 0，范围 0～2
combat_protection_charges：已经获得的保护次数，初始 0

每次被接受的动作，以同步后的 m_before 与实际 m_after 比较：
  m_after > m_before：
    goodwill_progress += 1
    若 goodwill_progress == 3：
      combat_protection_charges += 1
      goodwill_progress = 0
  m_after == m_before：
    goodwill_progress 不变
  m_after < m_before：
    goodwill_progress = 0

动作原规则判定 would_start_combat 后：
  若 would_start_combat 且 combat_protection_charges > 0：
    combat_protection_charges -= 1
    拦截本次开战，结果返回 ongoing，继续交涉
    不创建/恢复战斗，不让敌人行动，不写失败开战标记
  否则按原结果处理
```

规则细节：

- 正向动作本身已经不会开战，因此只积累保护，不消耗已有保护。一次交付无论多少件、提升多少百分点都只算一次；只有本次真实心情提升才计数，满心情拒收、无效请求、重复回调和仅刷新不能累计。
- 微小收益只有实际增加持久化精确心情时才计一次；仅保存不足精度的余数不计次，但仍不激怒。当前不另加最小赠礼金额，拆成多次有效赠礼可分别累计，这是次数制的结果，需纳入经济模拟。
- 获得后，只在原规则本来会触发交涉开战时消耗。一般/厌恶物品自然未激怒，或交谈失败但未激怒，均保留保护；因此有保护时，下一次厌恶物品无论随机结果如何都不会直接开战。
- 保护覆盖交谈失败激怒、一般物品激怒、厌恶物品激怒；正式开战后不再提供交涉动作。
- 保护不取消心情下降及对应失败/冒犯计数；一般与厌恶物品保持拒收不扣物；心情实际下降后，未满三次的 `goodwill_progress` 归零。已经兑换的保护仍保留，只扣真正拦截的 1 次。
- 累计完成三次后开始下一轮，因此可以反复获得。**未指定的存储方式建议为次数可累积**：六次提升、期间没有下降，可存 2 次，依次拦截两次开战；不把后续获得静默覆盖为 1 次。
- 保护使用怪物生命实例级共享余额与进度，和共享心情一起保存、被下一支合法接手队伍继承；不能在换队时给每个成员各复制一份。此归属方式是与现有共享心情保持一致的建议默认值。
- 队内最低同步若使怪物共享心情下降，也重置尚未兑换的进度，但不算赠礼动作、不发放保护、不清空已获得保护。会话预览不写状态，不能触发这个重置。
- 失败开战名单仍是最先执行的资格拒绝；已有标记的队伍不能用保护抵消确定性必败，不消耗保护余额，也不能先执行赠礼。
- 主动开战、战前离开、真实超时结束，以及其他独立世界事件，不属于交涉激怒，不能用保护阻止；失效的旧超时任务仍须按版本校验拒绝。
- 怪物生命结束时余额和进度随之结束，新生命从 0 开始；逃跑、断线、换队、服务重启不清零或补发。

用户示例的完整过程：

| 动作 | 心情变化 | 未兑换累计 | 已获保护 | 结果 |
| --- | --- | ---: | ---: | --- |
| 第一次喜好 | 提升 | 1 | 0 | 不开战 |
| 第二次喜好 | 提升 | 2 | 0 | 不开战 |
| 一次一般 | 不变 | 2 | 0 | 不打断累计；仍按一般物品原有风险判定 |
| 再一次喜好 | 提升 | 0 | 1 | 满三次，获得保护，不开战 |
| 接着一次厌恶 | 下降 | 0 | 若激怒则变 0，否则仍为 1 | 必定不会因这次交付开战 |

本例以中间的一般物品没有提前激怒为前提：当时尚未攒满三次，所以不能倒用未来的保护。若此前已有保护，它也可拦截一般物品激怒。一般物品不打断累计，不等于在没有保护时免除原有风险。

面板可显示“善意积累：2/3”“开战保护：1 次”，这些是明确的操作进度，不涉及隐藏幸运、魅力或精确心情。获得时提示“它记住了你们接连的善意，下次动怒时会有所克制”；保护触发时显示“开战保护生效”，并保留可继续交涉按钮。

每个怪物新增至少两条保护触发文案，体现愤怒被克制，不写已造成伤害。例如幽狼：“它呲起牙，喉间却压住了那声咆哮；先前的善意让它没有扑上来。”森林史莱姆：“尖刺刚从胶面冒出，又缓缓缩了回去；它似乎仍记得你们送来的那些礼物。”

### 7.5 数值示例

`M=200`、默认初始心情 0%、喜好系数 1：

- 喜好物品总价值 20：提高 10 个百分点，到 10%。
- 再给价值 50：提高 25 个百分点，到 35%。
- 再给价值 50：到 60%。
- 再给价值 50：到 85%。
- 再给价值 30：到 100%，累计喜好价值 200，未命中失败开战名单时下一次交谈必成。
- 若配置初始 -30%，同样的价值 200 只能提升到 70%；达到满心情还需价值 60 的合意赠物，并遵守单次涨幅上限。
- 若在 80% 时误给价值 20 的厌恶物：下降 15 个百分点到 65%，再以 65% 计算厌恶风险。
- 一次给价值 500 的喜好物仍最多提高 25 个百分点；物品选择确认须提醒“大批赠物不保证同等收益”，避免玩家误以为所有投入都能按比例回收。

## 8. 会话、战斗面板与操作权限

### 8.1 遭遇面板

```text
幽狼 · 心情：戒备
它站在树影边缘，鼻尖微动，目光始终没有离开你们。

[战斗] [交涉] [躲避]
```

未命中失败开战名单时，打开交涉面板本身不扣体力、不判定、不改变心情；只有接受第一项实际动作时才创建并锁定可变会话。预览档位按怪物共享心情与队内历史记录取最低值计算，但读面板不写低其他人的记录。若玩家实际发起 `/交涉` 时名单命中，直接输出失败并开战，不显示可继续交谈或交付物品的面板。被动查看怪物详情只提示“它拒绝与你们交涉”，不自动开战。

```markdown
# 交涉

【三首雾沼蛇母】心情：戒备

> 善意积累：0/3｜开战保护：0 次

> **它游开半圈，对你仍托着的「微光草药」没有再看一眼，尾梢缓缓扫过身旁的沙土。**

对方未收下：
```

### 8.2 每页十条的交涉背包

每页固定最多十条，沿用 8.1 的引用排版；第十一条从下一页的 ① 开始。空背包显示“没有符合条件的未绑定材料”。分页状态与搜索词保留在上一页、下一页和刷新命令中，搜索重新从第一页开始。

示例名称仅用于说明布局，实际页面必须用真实物品定义的中文名称和可用数量，不凭样稿新增物品。页面顶部保留怪物行为文案，列表只包含按第 5 节规则允许给予且本人可用数量大于零的物品，不夹带任务物、地图、实例或没有权限的禁用行。

#### 8.2.1 行内蓝色链接

- 每页编号固定为 `①②③④⑤⑥⑦⑧⑨⑩`，翻到下一页从 ① 重新开始，最后一页不足 10 条则按实际数量显示。
- 每条物品独立成块：`> **圈号 物品名称 ×可用数量** [交涉]`，下一行 `> 客观分类`，块间空一行。`[交涉]` 是紧随物品信息的蓝色行内命令链接，不是底部独立大按钮，也不是外部网页链接。
- 沿用项目 `Format.createMarkdown().addText(...).addButton('[交涉]', { data: command, autoEnter: false })` 的行内链接方式；具体蓝色由平台命令链接样式呈现，须在目标聊天客户端验收。
- 不靠空格补齐做绝对右对齐；链接在同一条目的右侧/尾部，长名称换行时仍属于该条目，避免比例字体下错位。
- 每条链接绑定稳定 item ID、当前目标生命、发起者身份及操作上下文；圈号只是展示序号，不能作为扣物依据。
- 点击行内 `[交涉]` 进入该物品数量确认，默认 1 件，允许修改为正整数；确认页显示拟交付的物品及数量，并说明喜好收下才消耗、一般与厌恶拒收保留，按钮为 `[确认交付] [更改数量] [返回交涉]`。仅打开确认页不扣物。
- 其他队员点击同一条链接时，服务端校验操作者；不能扣原发起者库存。建议返回其本人同目标交涉页再选择，而非复用原数量上下文。

#### 8.2.2 分页、搜索与翻页

| 控件 | 行为 |
| --- | --- |
| 上一页 | 当前页减一，保留搜索条件；第一页不循环跳末页，也不产生交涉动作 |
| 搜索 | 打开关键字输入，按中文名、图鉴号或客观交涉分类检索本人可交涉库存，提交后回结果第一页 |
| 翻页 | 打开目标页码输入，跳到指定页，保留搜索条件；只接受合法正整数 |
| 下一页 | 当前页加一；末页不循环回第一页 |
| 交谈 | 位于分页按钮下方，直接发起一次交谈判定，不依赖是否选过物品或是否持有可交涉物品 |

- 首次打开默认显示全部可交涉物品第一页，无需先选材料分类。分类用于准入、搜索、展示和偏好匹配，不再强制增加一级选择菜单。
- 先过滤资格、数量和搜索条件，再计算总数与分页，不能先取 10 条原背包再过滤，造成每页不足或漏项。
- 建议按客观交涉分类固定次序、再按稳定 item code 排序；不能按怪物喜好、预计收益、最近随机反应排序。背包同物品合并数量，实例不混入列表。
- `pageSize=10`；搜索参数使用绑定查询并转义通配符，设合理长度上限，不拼 SQL。空关键字清除搜索并返回全部第一页。
- 页码越界或交付后总页数减少时，定位到最后一个有效页并展示当前页码；非法非整数输入给出中文提示，不偷偷发起交谈。
- 空背包展示“背包中暂无可用于交涉的物品”；搜索无结果展示“没有找到符合条件的物品”，两种情况下都保留交谈与离开入口，页面按 1/1 处理。
- 翻页、搜索、打开数量确认、返回列表均为只读导航，不扣体力、不改变心情、不计善意进度、不消耗保护，也不刷新有效交涉动作的超时时间。
- 玩家提交有效交付后，返回该目标交涉页，显示本次反应并刷新本人库存数量；保留原关键字与页码，必要时收敛到有效页。物品耗尽立即从列表消失，不能再显示旧可用数量。
- 导航页码不改共享动作 revision，避免一人搜索让全队动作失效；交付/交谈等实际动作仍校验最新状态及幂等标识。按钮不携带隐藏属性、偏好答案、估值或成功率。
- 分页控件四个一行，交谈单列下一行；主动开战、离开另列，避免十条物品各占实体按钮额度。若某平台无法渲染十条行内链接，需补平台兼容并明确验收结果，不能悄悄减少为每页五条。

### 8.3 队伍权限

- 沿用现有队长发起遭遇/战斗的权限；交涉内允许每位满足条件的真实队员交谈、赠送自己的物品。
- 贿赂不能从队友背包自动拿物品；队长也没有这种权限。
- 交谈者必须存活、可行动、同区域且 `x/y/z` 一致，并属于冻结名单。
- 一次只处理一个动作。多人同时点击，只有最新版本的一个动作生效，其他请求刷新面板。
- 主动开战、离开导致全队状态改变，沿用队伍控制权限；若现有行为无明确权限，新增队长限制。
- 会话期间禁止入队、退队、踢人、解散与移动直接穿透。允许队长先结束交涉，再执行这些操作；超时恢复后也不丢失个人记忆。

### 8.4 持续交涉仅限开战前

持续交涉只允许未进入战斗的遭遇。正式开战后，战斗面板不显示“交涉”或“继续交涉”，交谈、贿赂、翻页、搜索以及旧消息按钮也必须由服务端拒绝。回合开始、尚未提交行动也不例外。

服务端先检查实际战斗状态，再处理旧动作回放，防止曾经的赠物结果重新显示可操作交涉页。拒绝提示只提供战斗面板和操作面板。未开战时仍可连续赠礼与交谈，主动开战或激怒开战后会话立即结束。

启动升级时关闭旧版绑定战斗的预览与活动交涉会话，释放参与者占用；不抹去共享心情、玩家记忆、隐藏属性或结算账本。战前空闲超时只释放会话，不自动制造战斗。

逃离战斗后再次遭遇仍沿用原记忆规则：有失败开战记录的队伍必败；本规则不额外把主动开战登记成失败交涉。

### 8.5 命令建议

保留 `/交涉 <怪物编号>` 打开或恢复面板；增加交涉交谈、交涉物品、交涉交付、交涉结束等路由。具体路径遵循项目现有 Router/schema 风格，不让 handler 自行拆一整串任意文本。

关键动作结果使用结构化类型：

```typescript
type NegotiationResult =
  | { kind: 'ongoing'; sessionId: string; revision: number; view: NegotiationView }
  | { kind: 'success'; settlementId: string; view: SettlementView }
  | { kind: 'combat_started'; combatId: string; openingText: string }
  | { kind: 'combat_resumed'; combatId: string; text: string }
  | { kind: 'closed'; reason: 'left' | 'expired' | 'target_gone' };
```

### 8.6 自动战斗兼容

- 老的“默认选择交涉”配置保留，但改为自动进行一次交谈。
- 成功：展示结算；激怒：按原自动战斗配置接管战斗；仍可继续：展示交涉面板，停止本次自动推进，等待玩家选择。
- 不默认自动消耗任何背包物品，也不自动无限空谈；以后若做自动贿赂须独立设置物品和数量上限。
- 城镇追捕等特殊场景不能继续硬编码跳过交涉后，又在手动入口采用另一套允许规则。二者统一读取完成策略。

## 9. 怪物对玩家的记忆与换队同步

### 9.1 身份定义

```text
MonsterLifeKey = spawn_id + generation
MemoryKey = MonsterLifeKey + character_id
```

- 用怪物生命实例记录，不能用怪物名字、坐标、队伍 ID 或 QQ ID 作为唯一关系键。
- 同一怪物移动、玩家换平台绑定、怪物改名字不影响记忆。
- 逃跑后同一只怪物回血不等于新生命，记忆不能重置。
- 正常死亡后生成新怪物才开启新生命；若现有刷新机制复用 spawn 行，必须递增 `generation`。同一实例跨阶段或 Boss 转形态不递增。
- 同种怪物的另一个实体不继承仇恨；“全物种长期记忆”不属于本文默认范围。

### 9.2 同步算法

接受队伍第一项实际交涉动作时，在一个事务内执行：

```text
先读取同一生命实例的共享心情与计数：
    仅该生命从未初始化时读取档案初始心情（默认 0%，可配置负数），各累计次数 = 0

先检查队内是否有人命中该生命的失败开战名单：
    命中 → 直接失败开战，不执行交谈/赠物随机判定

对冻结名单中的每个真实玩家 i：
    缺少个人记忆时，m_i = 怪物当前共享心情
    各累计次数也继承怪物当前共享计数，不重新取出生值

m_team = min(monster.shared_mood, m_i...)
f_team = max(monster.shared_talk_failures, f_i...)
n_neutral_team = max(monster.shared_neutral_count, n_neutral_i...)
n_dislike_team = max(monster.shared_dislike_count, n_dislike_i...)

将以上聚合值写回怪物共享状态和所有参与者的记忆，再进行本次动作。
每次动作后的新心情、计数，同时写回怪物共享状态与所有参与者。
```

取最大累计次数而不是相加，避免同一次团队失败在下一次组队时被重复放大；不会因换发言者清零。

这是一种“共同经历”的记忆：玩家跟随低心情队员完成一次实际交涉后，也会承担该次低心情，不能再把该队员踢掉恢复高心情。

| 情况 | 结果 |
| --- | --- |
| A 对怪物 80%，B 对怪物 15%，一起开始 | 全队 15%，A、B 都写为 15% |
| A 与 B 交涉后 B 退队，A 重开 | A 仍保留最后共同心情，不恢复历史 80% |
| 怪物共享 80%，A 个人 80%，新队员 C 无记录 | C 继承 80%，全队仍为 80%，不降回出生值 |
| A、B 一起改善到 70%，离开后原队返回 | 两人均 70%，继续使用 70% |
| A 队离开时共享 65%，完全陌生的 C、D 接手 | C、D 从 65% 开始，不能重新随机或重置 0% |
| A 队离开时共享 -35%，完全陌生的 C、D 接手 | C、D 从 -35% 开始，负值也原样继承 |
| 怪物后来被他人改善到 90%，旧玩家 E 历史为 30% | E 实际交涉时按最低值降为 30%，写回共享值与本次队员 |
| 失败数 A=2、B=5 | 以 5 为基础继续，下一次失败记为 6 |
| 同种但不同生命实例 | 建立该实体的新关系，读取该档案配置初始值，默认 0% |

以上例子除另有说明，均以未命中失败开战名单为前提。读面板只预览这个最小值；实际写回发生在第一项动作接受时。会话中始终使用已冻结名单，防止中途加人不参与最小值计算却拿奖励。

### 9.3 躲避、逃跑、离开与恢复

- 交涉后点击离开、遭遇躲避、战斗逃跑、断线、会话超时，都保存怪物共享心情、个人心情、累计计数以及失败开战标记。
- 已有记录的玩家躲避或逃跑不会清零；从未交涉的玩家若需要创建互动记录，继承怪物当前共享心情，包括负值，不额外降低，也不重置为 0%。
- 逃跑本身不默认追加心情处罚；这是未被要求的规则，不隐藏加入。
- 不设自然恢复，不按日清零。记录保留至该生命结束；结束后可以归档审计，不能归档仍活着的怪物记忆。
- 没有实际与怪物互动的远程队友不进入名单，不参与心情、幸运、奖励或计数。

### 9.4 多队竞争

同一生命实例同一时刻只有一个活动交涉/战斗占用者。其他队伍得到“对方正在应付另一队人”的可读提示，不先扣礼物。

占用会话须有有效租约和持有者；超时清理必须核对会话版本，不能释放刚被续用的占用。对方已死亡、离场或结算后，所有旧按钮失效。怪物不能一边被 A 队谈判，一边被 B 队击杀后分别发奖。

释放占用不清除共享心情。上一队离开保存与下一队接手读取必须在同一生命记录锁下串行化，下一队不能读到上一动作提交前的旧心情。新队伍没有被记录玩家时，仍可尝试交涉，即使上一队已经因失败开战被永久拒绝。

### 9.5 失败开战名单：确定性拒绝规则

这是追加需求的硬规则，优先级高于心情、魅力、物品、职业、队长身份及自动战斗配置。

```text
blocked = 当前实际参与队伍中，存在任一玩家
          在该 MonsterLifeKey 下的 negotiation_combat_failed = true

blocked 为真：
    交涉直接失败，不生成成功随机数，不接受礼物
    心情仍按共享值与个人记录取最低，并保存；不因被拒绝额外扣心情
    进入/恢复战斗，并记录本次失败开战的全体实际参与玩家
```

标记触发条件：交谈未成后激怒开战、一般礼物激怒开战、厌恶礼物激怒开战，以及包含旧记录玩家而直接交涉失败开战。不是每一次交谈未成就写标记，也不是随机命中就立刻写标记；开战被保护拦截时没有实际失败开战，不能记录为后续必败。

- 被记录的是冻结名单中的全体在场真实玩家，包括没有奖励资格但实际参与者，不只记录发言者或赠物者。
- 普通主动攻击、偷袭、单纯躲避/逃跑、未激怒的交谈失败、主动结束谈判，不自动写入“交涉失败开战”标记；这些事件不是同一个触发条件。
- 标记随该怪物生命永久保留，没有日重置、时间冷却、礼物赎回或改名清除；失败次数和心情改善也不清标记。
- 同队新玩家不会仅因组队或看面板被标记；但实际参与了一次被名单拦截、继而失败开战的交涉，也属于本次失败开战玩家，会被记录。
- 被记录玩家退出后，剩余成员若也曾一起失败开战，仍然必败；必须由没有该怪物失败标记的队伍接手，才重新具有概率交涉资格。
- 全新队伍继承怪物上次共享心情，但不继承陌生人的个人失败标记。若自身旧心情更低，仍按最低值规则同步。
- 将怪物喂至满心情再邀请被记录玩家不能绕过检查；变更队伍需结束会话，新交涉会重新检查名单，旧会话按钮不能继续使用。
- 名单必须早于物品扣除及首项交涉体力消费检查。被拒绝的交涉动作不额外扣物/体力，但实际开战照常收取一次战斗体力，已经开战则直接拒绝交涉，不推进回合。
- 默认前端只说明“它认出了你们中的旧面孔，拒绝再听任何解释”，不列出玩家姓名或隐藏属性；服务端按角色身份准确命中。

优先级举例：怪物共享心情 100%，队伍含已失败开战的 A，仍直接失败；没有失败标记且最低同步后仍为 100% 的陌生队伍才必定交谈成功。两条规则分别控制交涉资格和有资格后的概率，不相互抵消。

## 10. 心情掉落加成与幸运结算

### 10.1 心情倍率

交涉成功使用成功判定之前的心情。**50% 心情才达到基础掉落，过早成功需承担投入不足的减产；不是任意正心情都获得加成。** 建议采用通过 0%→0 倍、50%→1 倍、100%→2 倍的线性公式：

```text
F_mood = 2 × clamp(m_success, 0, 1)       // [0,2]
相对基础的增减比例 = F_mood - 1
```

| 成功心情 | 相对基础产出 | 心情倍率 |
| ---: | ---: | ---: |
| ≤0% | 无普通物品产出 | 0（公式防御值；当前曲线不会在此区间自然交涉成功） |
| 10% | -80% | 0.2 |
| 20% | -60% | 0.4 |
| 30% | -40% | 0.6 |
| 40% | -20% | 0.8 |
| **50%** | **基础产出，不增不减** | **1.0** |
| 60% | +20% | 1.2 |
| 70% | +40% | 1.4 |
| 80% | +60% | 1.6 |
| 90% | +80% | 1.8 |
| 100% | +100% | 2.0 |

例如某物品的交涉基础概率为 20%，幸运中性时，20% 心情成功后为 8%，50% 心情成功后仍为 20%，满心情成功后为 40%。这里是已经交涉成功后的掉落判定，不再额外乘一次交谈成功率。

只有交涉成功使用该倍率，普通物品减少的是期望产出，不从背包扣回已有战利品。负心情不生成负倍率。交涉失败后改为击杀，使用普通战斗奖励，不把交涉心情的加成或减产带进击杀奖励。成功概率曲线保持原规则：中性魅力、50% 心情时仍为 20% 成功率，不能把“基础掉落”误解为交谈必成。

### 10.2 每人幸运对全队产出的贡献

对有奖励资格的真实玩家集合 `R`：

```text
b_i = 0.20 × luck_i / 100
F_luck_team = Π (1 + b_i)
```

| 队伍组成 | 全队幸运倍率 |
| --- | ---: |
| 单人幸运 -100 / 0 / +100 | 0.8 / 1.0 / 1.2 |
| 四人全为 -100 | 0.8⁴ = 0.4096 |
| 四人全为 0 | 1.0 |
| 四人全为 +100 | 1.2⁴ = 2.0736 |
| +100、+50、0、-100 | 1.2×1.1×1×0.8 = 1.056 |

全队贡献按乘算，不把四个 -20% 相加为 -80%。四人最低仍保留 40.96% 的原掉落期望，最高为 207.36%；系数始终为正。以后扩大队伍上限时需重新评估乘算的经济边界。个人分配权重仍为 0.8～1.2 后归一化，不与全队倍率混成同一次抽取。

体力不足、NPC、远程、旁观者不贡献幸运，也不分配奖励；不能让没有消耗和资格的小号免费提供 +20%。冻结时具有资格的玩家，结算时不会因临时换人替换其幸运值。战斗中阵亡者是否领奖沿用现有奖励资格规则，不额外设“活着才能贡献”。

### 10.3 幸运对个人分配权重

```text
w_i = 1 + 0.20 × luck_i / 100      // [0.8,1.2]
P(owner=i) = w_i / Σ w_k
```

“权重 +20%”不等于“最终分配概率增加 20 个百分点”。两人幸运为 +100、-100 时，分配概率为 60%、40%；四人全为 +100 时仍每人 25%。单人最终分配概率始终 100%。

四人 `+100,+50,0,-100` 的权重为 `1.2,1.1,1.0,0.8`，概率约为 `29.27%,26.83%,24.39%,19.51%`。每件可分割战利品独立抽取一次归属，随后在结算页合并数量。

### 10.4 避免掉率 100% 封顶吞掉额外收益

现有掉落先把概率截为 100%。若仅在该概率上乘心情，原本必掉物品永远无法多掉，不符合“额外 100% 掉落提升”。新倍率作用于基础掉落的**期望批次数**。

先按对应结算渠道计算原有基础概率 `p_legacy ∈ [0,1]`，保留原有条件和概率封顶，然后：

```text
交涉成功：F = F_mood × F_luck_team
战斗胜利：F = F_luck_team

λ = p_legacy × F
batch_count = floor(λ) + Bernoulli(λ - floor(λ))

每个成功批次：按原有数量分布抽取 q，再逐份按幸运权重分配。
```

例如基础概率 0.8、满心情、全队幸运中性：`λ=1.6`，至少掉一批，另有 60% 再掉一批。基础概率 1、满心情：两批，期望产出恰好翻倍。不会把概率字段写成 160%，也不会把每个物品分别向上取整。

若全队负幸运令 `λ<1`，原来的必掉普通物品可能落空，这是“-20% 全队产出贡献”的直接效果；任务保底、剧情必给物不进入此倍率，不能丢失任务推进道具。

低于 50% 心情也会使普通掉落减产。例如交涉基础必掉一份、20% 心情、幸运中性，`λ=1×0.4=0.4`，本次仅有 40% 掉一份，不能先保底给一份再计算心情，否则低投入惩罚会被吞掉。

同一掉落条目内的稀有装备每多一批都必须独立生成实例；互斥掉落组以组为单位生成批次，不能把原互斥项展开后全部独立抽取。

### 10.5 与当前奖励的兼容

- 现有交涉经验约 20% 的口径保留，不被幸运、心情放大。
- 现有交涉掉落基础 20% 系数保留为本文原有建议；**50% 心情恢复这一交涉基准**，低心情按比例减产，满心情相对基准增加 100%。这次修改调整心情倍率，不自动将交涉基准替换为完整战斗掉落；是否取消旧 20% 系数仍属于单独的奖励基准审核项。
- 各渠道当前适用的队伍、词条、副职业、全服活动、丹药等照旧计算进入 `p_legacy`。不能借统一函数把目前仅战斗生效的丹药偷偷扩展至交涉。
- 当前会随机选一名队员提供个人 `dropBonus`；建议仍用**均匀抽样**选计算参考成员，保留该项语义；最终归属另用幸运权重。不得先按幸运权重抽这个参考人，否则高幸运高掉率队员会额外改变全队基础概率。
- 铜币直接账本奖励、经验、技能领悟、图鉴解锁、任务进度不参加幸运分配。掉落表中的普通货币物品按其既有发放路径兑换，是否属于可倍率普通掉落由奖励条目显式标记。
- 固定剧情、首杀、悬赏/任务保底和试炼奖励不复制；普通可重复掉落才参加倍率。
- 物品图鉴、装备实例、绑定字段、铜币转换统一走现有正确发放能力，不继续复制旧交涉分支中的简化 `INSERT`。

四人全 +100、满心情时，相对相同队伍和旧交涉基准的倍率为 `2×1.2⁴=4.1472`。心情自身仍只提供 +100%；总倍率超过 2 来自独立的幸运因素，面板不显示具体拆解。

### 10.6 体力与重复结算

- 打开面板不扣体力；第一项被接受的实际动作按遭遇规则预扣 1 点并冻结奖励资格。
- 多次交谈、赠物不重复扣体力。
- 交涉转战斗沿用此次已付体力与奖励资格，不能在开战函数中再扣一次；实际战斗中不开放交涉。
- 多敌人战斗的补扣继续按现有“初始敌人数”规则，先扣费用必须有共享消费凭证。
- 部分敌人被交涉解决后再战胜剩余敌人，同一敌人的物品、经验只结算一次；体力以该场共享账本核对，不靠剩余目标数重新估算。
- 同一生命实例最多一份终结奖励。结算表建立生命键唯一约束，邮件重发、消息重试不能触发再次抽奖。

## 11. 多怪、Boss 与特殊场景

### 11.1 普通同格多怪

一次交涉选定一个独立目标，心情、偏好、记录各自保存。成功后该目标和平离场，剩余敌人仍需处理；不把一只怪物的满心情同步给整个格子。

战前交涉成功的目标结束遭遇，后续战斗不能再对该生命发奖；其他仍在场的怪物可以另行选择战斗。实际战斗中不允许安抚目标。

### 11.2 多部位、双体与召唤物

- 多部位 Boss 采用整体交涉主体，部位按钮指向本体会话，不给爪、尾、护甲各开独立奖励。
- 容量基于整体真正可结算的掉落合计，只计一次；身体各部位按展示需要使用同一心情档位。
- 双体 Boss 若本来是一个共同战斗实体，配置明确代表者与完成策略：双方达成整体协议后退出；不能默认和其中一个谈成就重复发双份 Boss 奖励。
- 若双体确为两个独立可结算单位，则保持各自心情，分别成功；两种情况必须由 Boss 配置决定。
- 战斗临时召唤物继承召唤者心情、偏好和行为变体，不创建独立可刷掉落的成功结算；主体现有召唤清理逻辑继续复用。

### 11.3 “所有怪物”与现有强制战斗的衔接

现有代码对城镇执法者直接拒绝交涉，战斗奖励也对召唤物、执法者、测试 Boss、二转试炼等作过滤。这与“所有怪物都加入系统”的范围存在必须显式处理的差异。

本文建议所有怪物均具备心情、偏好、文案和记忆，且允许完成交涉；**完成交涉的世界结果由场景策略决定**：

| 场景 | 交涉成功的建议结果 | 不应自动发生 |
| --- | --- | --- |
| 普通野怪、迷宫怪 | 和平退出，结算其交涉奖励 | 伪装成击杀重复发奖 |
| 世界/区域 Boss | 按该 Boss 完成策略和平退场，可领取允许的交涉掉落 | 未批准就完成要求击杀的悬赏、首杀、解剖部位任务 |
| 城镇执法者 | 本次追捕停止攻击并给予脱离机会，保留犯罪和执法状态；冷却复用现有追捕规则 | 通过贿赂清除犯罪、获得执法者普通战利品 |
| 二转/剧情试炼 | 本轮和平结束，试炼记为未通过，可按原规则重试 | 以说服替代要求实际战斗验证的任务 |
| 测试 Boss | 返回交涉测试结果，仍遵守测试服奖励限制 | 流入正式经济的可交易奖励 |
| 临时召唤物 | 表达态度并交由主体处理整体结束 | 独立发奖 |

未命中失败开战名单且队内最低同步后仍为满心情 100%，保证交谈成功；场景策略仅决定成功意味着什么，不能再把它伪装成概率失败。名单命中时直接失败的资格规则在所有场景保持一致。特殊场景进入前明确写出“和平结束不计为试炼通过”等结果，避免玩家赠礼后才知道。

此节涉及现有世界规则，需作为审核项；如果最终保留强制战斗禁交涉，应在版本说明中明确列出范围例外，不得声称“所有怪物交涉均已完成”。

## 12. 文案系统与内容生产标准

### 12.1 组织粒度

文案按以下维度选择：

```text
怪物身份 × 行为发生前心情档位 × 偏好类型 × 物品反应类别 × 变体
```

一次贿赂反应以动作前档位决定基础语气，物品效果和动作后档位决定收束句；面板展示动作后档位。这样“原本敌意很重，但收下喜爱物后稍微松动”的描述能与档位变化一致。

每个怪物需要：

- 8 档 × 3 偏好类型 × 每格至少 2 条 = 至少 **48 条基础赠物反应**，包括负心情的暴怒、愤懑、敌意三档；默认初始 0% 使用戒备档文案。
- 每个实际可给予的物品反应类别，匹配后仍至少有 2 种完整有效表达；只写 48 条、不区分物品种类不算达标。
- 8 档各至少 2 条交谈未成反应；能自然成功的档位各至少 2 条交谈成功反应。负心情三档不生成不可达的随机成功文案，戒备档中只有心情大于 0% 的部分可用成功文案。
- 至少 2 条一般物品激怒、2 条厌恶物品激怒、2 条反复交谈激怒、2 条玩家离开反应。
- 至少 2 条认出失败开战旧人的直接拒绝反应，以及 2 条陌生队伍接手时与当前共享心情相符的反应；不能给每个接手队伍都写“初次见面，恢复戒备”。
- 对重大物种特征有专属动作：胶质震动、魂火收缩、蛇信停顿、枝叶舒展、齿轮转动等。

可以组合“怪物专属动作句＋物品类别细节＋结果句”，但展开后的文本必须通顺且保持物种差异。基础句不能只是替换怪物名字的全局模板。

### 12.2 选择与防重复

- 同一怪物、同一类别优先不重复最近两条；候选只有两条时至少不连续重复上一条。
- 文案选择独立于成功/激怒随机结果；刷新旧结果不能重新掷玩法随机数。
- 一次动作持久化选中的文案 key 和必要安全参数，重试回放相同结果。
- 文案没有覆盖时在发布检查中失败；运行时紧急故障可显示“对方的反应难以辨认”，同时记录配置错误。该回退不是内容验收通过。
- 不声称非人形怪物一定能讲话；交谈可以表现为语调、姿态和对行动意图的理解。
- 不在实际没扣物、没攻击、没成功时描写相反事实。成功文案不无条件写玩家赠送了不存在的物品。

### 12.3 八档反应与已落地语料

正式语料以 `src/config/monster-negotiation.ts` 和 `src/config/monster-negotiation-dialogues.ts` 为准。当前 30 种形态分别手写两条喜好、两条一般、两条厌恶行为，结合八档心情的各两条态度句，以及物品类别的各两条感官细节。每个模板的每档三种偏好均可选两条，连续同类动作交替变体；刷新复用已经保存的结果。

完整模板偏好和形态样例见[怪物交涉喜恶与文案覆盖审计](怪物交涉喜恶与文案覆盖审计.md)。覆盖数字是组合覆盖，形态相同的怪物会共享行为主体，不冒称全部句子逐怪物独立手写。

以森林史莱姆的戒备档为例：

| 反应 | 变体一 | 变体二 |
| --- | --- | --- |
| 喜好 | 细胶将{物品}卷进清澈的内层，尖锐的胶棱悄悄圆了下来。它仍留着戒心，等着看你们接下来如何表示。 | {物品}被护在亮核周围，柔软的波纹一圈圈散开。双方保持着距离，它没有急着作出决定。 |
| 厌恶 | {物品}还未碰到胶面，细胶便猛地缩回，尖锐的胶棱齐齐朝向递礼的手。它仍留着戒心，等着看你们接下来如何表示。 | 亮核远远避开{物品}，外层翻起浑浊的泡沫，将接纳礼物的缝隙紧紧封住。双方保持着距离，它没有急着作出决定。 |
| 一般 | 细胶停在{物品}前晃了晃，随后垂回体侧，没有把礼物卷走。它仍留着戒心，等着看你们接下来如何表示。 | 你手中的{物品}映在透亮的胶面上，里面的气泡缓慢浮起，又照旧沉下。双方保持着距离，它没有急着作出决定。 |

满心情喜好礼物在事务前置校验时拒收，不扣物、不增加善意次数，提示点击交谈。一般和厌恶物品在所有档位都拒收；即使有保护或真的开战也保留库存。

### 12.4 同一怪物对不同物品类别的差异

| 类别 | 感官细节一 | 感官细节二 |
| --- | --- | --- |
| 草药 | 柔软叶片散出清淡的草香。 | 草木的汁液留下细小的绿痕。 |
| 骨质 | 骨质在接触间碰出清脆的轻响。 | 苍白骨面映出一点暗光。 |
| 水性粒子 | 细小的水纹在礼物旁漾开。 | 湿润清凉的气息浮了起来。 |
| 火性粒子 | 几粒火星跃起，带出暖热的气流。 | 一线赤光裹着热意闪过。 |
| 雷性粒子 | 微小电弧发出短促的噼啪声。 | 亮紫色的电光跳了一下。 |
| 魔力粒子 | 细小的魔力弧线交织一瞬。 | 微弧在空气里闪出淡淡涟漪。 |

类别细节只描述物品自身的特征，不预先声称怪物已吃下或毁掉它。偏好由明确的类别、粒子属性与单品例外决定，随后组合对应反应；不能只替换物品名字。

### 12.5 跨物种风格

| 形态 | 喜好动作 | 厌恶或一般动作 |
| --- | --- | --- |
| 蛇 | 颈侧轻触，盘曲身体护住礼物，吐信放缓 | 扬颈收信、尾梢拦路；一般物品只嗅探或游开，不碾碎 |
| 蟹 | 螯钳轻夹，护到腹甲下，细泡放缓 | 高举双螯空夹示警；一般物品探螯后空手收回 |
| 树精 | 细根卷入湿土，树皮裂隙探出新芽 | 根须缩回、粗根拱墙；一般物品绕根而过 |
| 哥布林 | 掂重藏进腰包，嘴上故作勉强 | 缩手按紧腰包、握刀反问；一般物品摆手嫌弃 |
| 骷髅 | 指骨摩挲，把礼物安置在肋骨间 | 魂火收缩、断刃横拦；一般物品只端详后垂回指骨 |
| 构装体 | 开启接缝纳入材料，核心与关节趋于稳定 | 接纳口紧闭、重臂拦住、核心急闪；一般物品扫视后照常运行 |

其余形态同样遵循各自的骨架、器官和运动方式，不让非人形生物套用统一的“伸手收下”或人类对白。

### 12.6 旧人拒绝与新队接手样稿

- 幽狼认出旧人①：它从你们身上嗅到了熟悉的气味，原本收敛的唇角再次翻起。这一次，它没有留给你们开口的余地。
- 幽狼认出旧人②：它的目光掠过队伍，忽然停在一道旧影上；短促的低吼响起，交谈的机会已经结束。

## 13. 数据结构与事务设计

### 13.1 建议新增表

以下为字段设计，不是可直接执行的迁移 SQL。使用现有 MySQL/事务工具，不新增第二套数据库或 Redis 作为关系记忆真源。

| 表 | 关键字段与约束 | 用途 |
| --- | --- | --- |
| `character_hidden_attributes` | `character_id` 主键；`luck`、`charm` 为有符号 SMALLINT；`created_at` | 隐藏基础值，应用与数据库双重范围校验 |
| `monster_negotiation_lives` | `(spawn_id,generation)` 主键；`capacity`、`shared_mood_ppm`、共享正向余数和失败/一般/厌恶计数、`goodwill_progress`、`combat_protection_charges`、价值/档案/掉落快照版本、`resolution`、占用会话、`revision` | 生命级共享心情、善意累计、保护余额、耐心、交涉快照、占用和终结状态 |
| `monster_negotiation_memories` | `(spawn_id,generation,character_id)` 主键；`mood_ppm`、正向余数、失败/一般/厌恶计数、`negotiation_combat_failed`、`first_failed_combat_at`、首次失败会话 ID、最近文案 key、时间戳 | 持久个人心情与不可清除的本生命交涉必败标记 |
| `negotiation_sessions` | `id` 主键；生命键、来源遭遇/战斗、战斗 ID、`state`、`revision`、`expires_at`、心情与计数、共享体力凭证 | 活动会话 |
| `negotiation_session_members` | `(session_id,character_id)` 主键；奖励资格、角色职责 | 冻结名单；不要保存用于前端展示的幸运和魅力快照 |
| `negotiation_actions` | `(session_id,request_id)` 唯一；预期 revision、操作者、动作、物品及绑定来源、结果种类、文案 key、时间 | 幂等、回放和物品审计 |
| `monster_reward_settlements` | 生命键唯一；结算渠道、状态、结果安全快照、幂等发放编号 | 战斗与交涉共享终结发奖防重 |

若现有表已可完整表达某项能力，优先扩展复用；尤其结算表需与现有战斗事务对齐，不能只给交涉加唯一键而普通击杀绕过。

所有参与主键的 BIGINT 按项目安全 ID 处理方式传递，不能未经范围校验强制转为可能丢精度的 JavaScript number。JSON 只放配置或不可变快照，不把并发可变的所有玩家关系塞入一个巨大 JSON 字段。

### 13.2 动作事务

统一参与交涉的写入路径，建议锁顺序为：

1. 队伍控制记录与角色占用记录，按稳定 ID 顺序锁定。
2. 关联战斗会话（如有）、怪物生命记录，按稳定顺序锁定。
3. 交涉会话及成员记录。
4. 按 `character_id` 锁定怪物记忆。
5. 按物品 ID 锁定操作者库存/实例。
6. 奖励结算与发放记录。

首次创建尚不存在的记忆行要在生命/会话锁内以唯一键 upsert 后重读；不能指望对不存在行的普通查询自然串行化。所有入队、开战、逃跑相关路径必须遵守一致的占用和锁序，否则仅交涉函数内部加锁无效。

事务内执行：身份/位置/状态校验 → request 去重 → revision 校验 → 失败开战名单检查 → 怪物共享状态与个人记忆同步 → 首次体力消费 → 物品验证、仅喜好扣除（一般/厌恶只校验持有量） → 计算动作效果，更新善意进度/发放保护，提升心情时跳过开战判定，否则按动作规则处理 → 对本来要发生的交涉激怒先扣保护拦截 → 写新共享状态/个人记忆 → 无保护且确实开战时才写入全队失败开战标记并战斗转移，或成功奖励结算 → 保存动作结果 → 提交。名单命中走确定性失败分支，跳过交涉消费与随机，不消耗保护，但仍保存最低同步心情，并在同事务内登记本次失败参与者、交接战斗。

保护获得、消耗、心情变更及动作结果必须同事务提交；余额不得为负，累计第三次的重复请求只发放一次。会话表如保存保护展示快照，只是缓存，不是第二套余额，始终以生命记录锁下的当前余额为准。

消息渲染和发送放在提交后。网络发送失败不退款、不重新判定；玩家再次点击或查询可以读回同一结果。数据库整体回滚时物品、体力、心情、结算全部回滚。

### 13.3 开战交接

不能沿用“交涉事务先返回失败，再在外面无条件 startCombat”的窗口；这会让两条请求同时失败并开两场战斗。

建议让战斗创建核心接受已有事务连接和共享体力凭证，在同一事务内由 `negotiating → combat` 转移并创建/恢复战斗。若确需两阶段处理，必须持久化唯一的 `combat_start_pending` 事件、保留目标占用并由可重试处理器完成，失败期间不允许再收礼。

共享心情保存、全队失败开战标记、怪物占用与战斗创建必须作为同一次状态转移提交；不能出现“战斗开始但未记录玩家”或“写了永久失败而事务实际没开战”的半完成结果。主动开战分支不写失败开战标记。

### 13.4 状态机

```text
未开战遭遇 → preview → negotiating
                         ├─ 喜好/未激怒/保护拦截 → negotiating
                         ├─ 交谈成功 → settling → 结束遭遇
                         ├─ 激怒或主动开战 → combat（关闭交涉入口）
                         └─ 离开/空闲超时 → 释放占用，保留记忆
已开战 → 拒绝交涉（不进入预览、不回放旧交涉页）
```

同一事务完成结算时 `settling` 可以是内部过渡状态，不必为可瞬时完成的步骤另起异步任务。崩溃恢复只能推进未完成事务状态，不能重新抽奖。

## 14. 经济约束与参数复核

### 14.1 保留 20% 交涉基准的含义

若单人、无其他增益，普通战斗基础掉落期望价值为 `V=200`：

- 旧交涉期望约 `0.2V=40`。
- 新方案中性幸运、20% 心情成功时，条件掉落期望约 `40×0.4=16`；50% 心情成功时为 `40`，恰好回到基础产出。
- 满心情、中性幸运，新交涉期望约 `80`。
- 从默认初始 0% 喂到满心情，喜好系数 1 时投入参考价值至少 `V=200`；初始 -30% 则至少 `1.3V=260`，不含中途失败造成的额外损失。

因此满心情保证成功主要购买的是安全脱战和确定结束机会，并不保证材料盈利。玩家也可以在 50% 心情、较少投入时尝试交谈，承担失败和激怒风险。

四人队既有基础掉率加成最高为 +150%；在没有概率饱和、其他增益或特殊条件时，满心情、四人幸运全 +100 的交涉期望可达到 `0.2×2.5×2×1.2⁴V=2.0736V`。这个值大于默认初始 0% 的喂满成本 `V`，可能出现持续刷取利润，不能把单人亏损当成整个系统没有产出风险。正态分布令极值队伍更稀少，但极值仍是需要验证的边界。

### 14.2 上线前必须模拟的组合

- 单人、双人、三人、四人；幸运取 -100、0、+100 和混合值。
- 低价普通怪、材料种类多的精英、高价值 Boss、迷宫怪。
- 默认 0% 与配置 -30%/-100% 的初始心情、直接交谈、喂到 50%/80%/100% 后交谈；陌生队伍接手负心情。
- 各物品可得成本与参考价偏差，特别是大量产出的低价喜好物。
- 高基础概率条目与低概率稀有装备；互斥组、随机数量、货币兑换。
- 既有全服活动、副职业、丹药、词条等真实适用组合。

建议输出每 100 次遭遇的平均赠物价值、成功率、开战率、耗时、体力、掉落价值和净收益分位数。模拟用合成隐藏值，不从生产导出真实玩家属性。

若产出过高，优先调整怪物参考价值、喜好系数、交涉基础奖励系数与可赠送清单。必须保持需求锚点：具备资格且同步后满心情必成、失败开战名单命中必败、单人幸运贡献极值、心情最多额外 100%；不能为平衡在后台偷偷打破这些规则。

### 18.1 本次明确采用的实现口径

1. 幸运、魅力独立按 μ=0、σ=30 的有界离散正态形状抽取；新角色创建及老角色补齐均幂等，普通人物与管理 DTO 不携带这两个字段。
2. 心情以百万分之一单位保存，范围为 -100%～100%。默认 0%，单模板可在配置中覆盖初始值。价值尾数累计，防止低价值材料被逐次取整成大量免费心情。
3. 心情倍率为 `2×max(0,m)`。50% 对应本项目既有的交涉基准；保留旧 20% 基础掉落系数和个人掉率加成的位置：`p_legacy=clamp(p_drop×0.2×(1+词条+旧队伍加成)+个人dropBonus,0,1)`。没有将原来仅战斗生效的丹药等附加到交涉。
4. 全队幸运倍率为 `Π(1+0.2×luck/100)`，个人分配仍按对应 0.8～1.2 权重归一化。互斥组每批只给一种，额外批次独立选择品种。
5. 只有喜好物品被收下并消耗；一般与厌恶物品拒收保留库存，但仍按偏好影响心情和动态激怒。送礼改变心情，只有交谈直接判定成功；善意满 3 次获得一层可累积保护。普通物品不增心情，也不打断未完成的善意累计。
6. 生命身份使用现有系统重新生成时产生的新 `monster_spawns.id`；无需额外迁移一个不会被现有重生代码更新的 generation 字段。原怪物记录不会因队伍变化清空。
7. 持续交涉仅限未开战遭遇，开战后所有交涉入口和旧按钮失效。打开、搜索、翻页是预览；第一项有效行动才占用会话，120 秒超时仅释放占用。交涉转开战仍按原失败先手规则处理。
8. 主动开战不记交涉失败名单；真实激怒才记当次全体参与者。黑名单优先于满心情与保护；旧按钮重放返回原结果。
9. 单品例外在全局准入后生效，如哥布林厌恶哥布林耳朵、树精拒收活木。地图、任务重要物与实例不能靠例外配置放行。
10. 普通零价怪材复用已有炼金固定成本估值；普通肉块估值为 4，星尘只作为掉落容量估值时取 100，仍禁止交付。家园木材、石料、金属因缺少统一交涉估值暂不接收；完整清单逐项注明。
11. 原有已开始的战斗保留旧幸运结算口径；新战斗保存奖励版本。更新前的战斗结束后，下一场才开放新交涉。
