# 家园系统实施方案

> 目标：在现有 AlemonJS + MySQL 文字 RPG 中加入“百纳居、私人小屋、家园升级、建材兑换、家具制作与家具效果”。
>
> 本文是可执行的开发规格，默认按当前项目结构增量实现，不要求一次性重构现有地图、移动或 PvP 系统。

## 1. 当前结构与设计结论

当前项目已经具备本功能所需的基础能力：

| 现有能力 | 当前实现 | 家园系统复用方式 |
| --- | --- | --- |
| 玩家坐标 | characters.current_region_id / pos_x / pos_y / pos_z | 小屋地块仍属于 baina_town，不改世界坐标模型 |
| 百纳镇建筑 | map_npcs，interaction_kind='building' | 新增 baina_residence 建筑 |
| 地图显示 | src/response/map.ts 查询 map_npcs 与 map_special_objects | 额外查询玩家自己的 player_homes |
| 移动与抵达 | src/game/adventure.service.ts | 回家、出门由家园服务处理，普通移动在家中禁止 |
| 货币 | characters.copper_coins | 购买、升级、兑换全部在事务内扣除 |
| 物品 | item_definitions、player_inventory | 建材和配方材料复用现有背包体系 |
| 通缉 / 执法者 | player_warrants、createCityPursuitEncounter | 家中隐藏普通玩家；百纳镇有效通缉犯对周围玩家公开且可被合法缉捕 |

### 1.1 必须遵守的决定

1. 不为每个小屋创建重叠的 map_regions。当前移动按坐标查区域，重叠区域会破坏区域选择和远距离移动。
2. 小屋地块仍在百纳镇公共区域内，但回家后新增私人访问状态，以 player_home_visits 作为可见性边界。
3. 不把私人小屋写入 map_npcs。map_npcs 是公共地图内容；玩家自己的小屋由地图服务单独追加。
4. 家中不允许组队、移动、玩家 PvP、抢劫或被普通玩家发现；家主通过 /家园 出门 回到小屋门前。
5. 通缉规则优先于家园隐身规则。普通家中玩家不进入普通感知列表；处于百纳镇有效通缉状态的家中玩家对周围玩家公开、在玩家感知列表中优先显示，并可被合法发起 PvP；三星及以上进入家园时仍创建执法者遭遇。
6. 家园坐标是公共地块坐标，不是房屋唯一坐标；多个玩家可以随机到同一地块。房屋实例通过 player_homes.id 和 player_home_visits.home_id 隔离。

## 2. 百纳镇建筑布局

百纳镇区域范围为 x=-25..24、y=-135..-86、z=0。冒险者公会作为中心锚点，其余店铺以不同距离、不规则方式分布在周围。

### 2.1 建议最终坐标

| 建筑代码 | 建筑名称 | 坐标 | 与公会曼哈顿距离 | 说明 |
| --- | --- | ---: | ---: | --- |
| guild_counter | 冒险者公会 | (-2,-111,0) | 0 | 百纳镇中心、任务与公共服务 |
| blacksmith | 铁匠铺 | (-17,-123,0) | 27 | 西南侧，保留炉火区氛围 |
| alchemy_sweetshop | 糖水屋 | (-12,-128,0) | 27 | 西南偏南，靠近生活区 |
| oddworkshop | 异工坊 | (6,-121,0) | 16 | 东南侧，靠近工坊街 |
| bookshop | 百味书屋 | (14,-108,0) | 19 | 东侧，靠近北侧街区 |

pear_guide 建议仍保留在 (-22,-128,0)。幽暗密林入口、深处入口和非建筑地标不纳入本次重新排版。百纳居坐标必须避开 map_npcs、map_special_objects、地下入口及资源刷新坐标。

### 2.2 坐标改动的同步清单

必须同步修改：

- src/database/bootstrap.ts 中百纳镇 map_npcs 的 upsert 数据；
- src/game/adventure.service.ts 初次抵达公会时的固定坐标，改为读取 guild_counter 坐标，禁止继续硬编码旧坐标；
- src/response/bounty.ts 中副职业任务的店铺坐标文案和按钮目标；
- src/response/map.ts 的建筑排序，加入 baina_residence；
- 用 rg 检查所有旧坐标文案，例如旧的 -8 -116、-12 -127、4 -121、12 -116。

建议新增 src/game/home.constants.ts，集中导出建筑坐标。数据库种子仍写入具体值；常量只用于剧情、按钮和服务层，不能替代数据库位置校验。

## 3. 数据库设计

当前项目真正的启动初始化入口是 src/database/bootstrap.ts 的 schemaStatements 和 initializeSchema；src/database/migration/*.sql 主要是历史资料，不能只新增一个 SQL 文件而不接入 bootstrap。

### 3.1 player_homes

每个角色最多一间小屋，购买时分配百纳镇中圈至外圈的公共地块。同一地块可以存在多个玩家的小屋，因此地块坐标不能设置 UNIQUE 约束。

~~~sql
CREATE TABLE IF NOT EXISTS player_homes (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  character_id BIGINT UNSIGNED NOT NULL,
  town_region_id BIGINT UNSIGNED NOT NULL,
  plot_x INT NOT NULL,
  plot_y INT NOT NULL,
  plot_z INT NOT NULL DEFAULT 0,
  house_level TINYINT UNSIGNED NOT NULL DEFAULT 1,
  floor_count TINYINT UNSIGNED NOT NULL DEFAULT 1,
  status ENUM('active','demolished') NOT NULL DEFAULT 'active',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_home_character (character_id),
  KEY idx_home_plot (town_region_id,plot_x,plot_y,plot_z),
  KEY idx_home_town_status (town_region_id,status),
  CONSTRAINT fk_home_character FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE,
  CONSTRAINT fk_home_town FOREIGN KEY (town_region_id) REFERENCES map_regions(id) ON DELETE CASCADE
) ENGINE=InnoDB;
~~~

### 3.2 player_home_visits

该表是“当前是否在家”的唯一状态来源，不修改 characters，也不创建重叠区域。

~~~sql
CREATE TABLE IF NOT EXISTS player_home_visits (
  character_id BIGINT UNSIGNED NOT NULL,
  home_id BIGINT UNSIGNED NOT NULL,
  entered_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (character_id),
  UNIQUE KEY uk_home_visit_home (home_id),
  CONSTRAINT fk_home_visit_character FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE,
  CONSTRAINT fk_home_visit_home FOREIGN KEY (home_id) REFERENCES player_homes(id) ON DELETE CASCADE
) ENGINE=InnoDB;
~~~

查询公共玩家时统一使用：

~~~sql
LEFT JOIN player_home_visits hv ON hv.character_id = c.id
WHERE hv.character_id IS NULL
~~~

查询家主自身状态时必须校验当前角色和 home_id 的归属，不能相信客户端传入的房屋编号。

### 3.3 家具定义、配方和实例

~~~sql
CREATE TABLE IF NOT EXISTS home_furniture_definitions (
  code VARCHAR(64) NOT NULL,
  name VARCHAR(64) NOT NULL,
  description TEXT NOT NULL,
  effect_json JSON NOT NULL,
  required_house_level TINYINT UNSIGNED NOT NULL DEFAULT 1,
  max_per_floor TINYINT UNSIGNED NOT NULL DEFAULT 1,
  floor_slot_cost TINYINT UNSIGNED NOT NULL DEFAULT 1,
  is_active TINYINT(1) NOT NULL DEFAULT 1,
  PRIMARY KEY (code)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS home_furniture_recipes (
  furniture_code VARCHAR(64) NOT NULL,
  item_id BIGINT UNSIGNED NOT NULL,
  quantity INT UNSIGNED NOT NULL,
  PRIMARY KEY (furniture_code,item_id),
  CONSTRAINT fk_home_recipe_furniture FOREIGN KEY (furniture_code) REFERENCES home_furniture_definitions(code) ON DELETE CASCADE,
  CONSTRAINT fk_home_recipe_item FOREIGN KEY (item_id) REFERENCES item_definitions(id)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS player_home_furniture (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  home_id BIGINT UNSIGNED NOT NULL,
  furniture_code VARCHAR(64) NOT NULL,
  floor_no TINYINT UNSIGNED NOT NULL DEFAULT 1,
  slot_key VARCHAR(32) NOT NULL,
  placed_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_home_furniture_slot (home_id,floor_no,slot_key),
  KEY idx_home_furniture_floor (home_id,floor_no,furniture_code),
  CONSTRAINT fk_home_furniture_home FOREIGN KEY (home_id) REFERENCES player_homes(id) ON DELETE CASCADE,
  CONSTRAINT fk_home_furniture_definition FOREIGN KEY (furniture_code) REFERENCES home_furniture_definitions(code)
) ENGINE=InnoDB;
~~~

max_per_floor、floor_slot_cost 和 effect_json 必须由服务端读取并校验，不能让用户提交 JSON 效果或自行指定无限家具数量。

### 3.4 百纳居商店与兑换

~~~sql
CREATE TABLE IF NOT EXISTS home_shop_offers (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  offer_code VARCHAR(64) NOT NULL,
  output_item_id BIGINT UNSIGNED NOT NULL,
  output_quantity INT UNSIGNED NOT NULL,
  input_item_id BIGINT UNSIGNED NULL,
  input_quantity INT UNSIGNED NOT NULL DEFAULT 0,
  copper_price BIGINT UNSIGNED NOT NULL DEFAULT 0,
  is_active TINYINT(1) NOT NULL DEFAULT 1,
  sort_order SMALLINT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_home_offer_code (offer_code),
  KEY idx_home_offer_active (is_active,sort_order),
  CONSTRAINT fk_home_offer_output FOREIGN KEY (output_item_id) REFERENCES item_definitions(id),
  CONSTRAINT fk_home_offer_input FOREIGN KEY (input_item_id) REFERENCES item_definitions(id)
) ENGINE=InnoDB;
~~~

规则：

- 铜币报价：input_item_id IS NULL 且 copper_price > 0；
- 物品报价：input_item_id IS NOT NULL、input_quantity > 0 且 copper_price = 0；
- 结算前锁定角色、输入物品行和报价配置；不足时整个事务回滚；
- 不直接把“锻材”当货币扣除，必须按具体 item_id 扣除。

### 3.5 材料分类和种子

材料分类统一为以下规则：

- 建材只有三种：木材、石料、金属，统一使用 item_category='建材'；
- 所有怪物材料统一使用 item_category='怪材'，将旧的“兽材”和“精兽材”都归并为“怪材”，用户界面不再显示这两个旧分类；
- 家具可以使用建材和普通怪材，不新增“家园材料”分类；
- 现有 player_inventory 只保存 item_id 和数量，背包类型来自 item_definitions.item_category，因此要迁移的是物品定义和背包查询/显示，不要再为背包单独增加一套材料分类字段。

新增三种建材，避免改变现有 living_wood、meteor_iron 等锻材在锻造系统中的含义：

| code | 名称 | item_type | item_category |
| --- | --- | --- | --- |
| home_wood | 木材 | material | 建材 |
| home_stone | 石料 | material | 建材 |
| home_metal | 金属 | material | 建材 |
| slime_gel | 史莱姆凝胶 | material | 怪材 |

史莱姆凝胶由各种史莱姆怪物掉落，用于制造史莱姆床；它是普通怪材，不是家园专属材料。其余三种建材主要由百纳居商店获得。现有 item_definitions、player_inventory、inventoryView 可以直接承载这些物品。

数据迁移必须包含：

~~~sql
UPDATE item_definitions
SET item_category='怪材'
WHERE item_category IN ('兽材','精兽材');
~~~

同时将 bootstrap.ts 中所有“兽材”和“精兽材”种子改为“怪材”，并修改以下现有背包/图鉴入口：

- src/response/inventory.ts：材料子分类删除“兽材”“精兽材”，加入“怪材”“建材”；
- src/game/codex.service.ts：材料筛选项删除“兽材”“精兽材”，加入“怪材”“建材”；
- src/response/item-codex.ts：物品图鉴直接显示迁移后的 item_category，不保留旧分类兼容文案；
- 背包查询、材料丢弃、商店展示继续按 item_category 读取，不能再写死旧分类。

史莱姆凝胶需要加入所有史莱姆模板的 drops_json，包括 slime_red、slime_orange、slime_yellow、slime_green、slime_cyan、slime_blue、slime_purple 和 black_slime 等现有史莱姆。

## 4. 家园规则与 v1 数值

以下数值作为 v1 种子值，必须写入 home.constants.ts 或配置表，不能散落在 handler 中。

### 4.1 房屋成长

| 操作 | 铜币 | 木材 | 石料 | 金属 | 前置 |
| --- | ---: | ---: | ---: | ---: | --- |
| 购买简陋木屋 | 500 | 0 | 0 | 0 | 未拥有小屋、位于百纳居 |
| 房屋升级 Lv.2 | 800 | 30 | 20 | 0 | Lv.1 |
| 扩建二层 | 1,000 | 50 | 30 | 0 | Lv.2 |
| 房屋升级 Lv.3 | 2,000 | 80 | 50 | 20 | Lv.2 |
| 扩建三层 | 3,000 | 120 | 80 | 30 | Lv.3、已有二层 |

房屋初始为 1 层，每层 6 个家具槽位；Lv.2/Lv.3 时每层槽位分别为 8/10。扩建只增加楼层，不自动赠送家具。

### 4.2 小屋随机坐标

- 以公会 (-2,-111) 为中心；
- 候选坐标属于百纳镇 z=0，且满足曼哈顿距离 12..22；
- 排除 map_npcs、map_special_objects、未开采 resource_spawns、未击败 monster_spawns 和地下入口；
- 不排除已有 player_homes：同一个公共地块允许多个玩家的小屋，player_homes 只记录房屋实例，不代表地块占用；
- 不以 characters 是否正在该坐标作为房屋唯一性条件。购买时只需保证该坐标不是公共建筑、资源、怪物或入口坐标；
- 应用层最多随机尝试 64 个候选点，失败后使用固定候选列表兜底；
- 选点、扣钱和创建房屋必须在同一 withTransaction 中完成；
- 房屋实例不因坐标重复而冲突；只有角色唯一键冲突或其他事务失败时才回滚，不得让用户损失铜币。

### 4.3 家具 v1 示例

| code | 家具 | 效果 | 材料示例 | 每层限制 |
| --- | --- | --- | --- | ---: |
| wooden_bed | 木床 | 在家休息时体力恢复速度 +10% | 木材 20、石料 4 | 1 |
| slime_bed | 史莱姆床 | 在家休息时体力与魔力恢复速度 +20% | 木材 25、史莱姆凝胶 15 | 1 |

家具配方可以混用三种建材与普通怪材。例如史莱姆床使用建材木材和怪材史莱姆凝胶；其他家具可以使用魔力绒毛、魔力獠牙、魔力鳞片等普通怪材，不得为这些材料新增“家园材料”或“家具材料”类别。

铜币报价作为基础价格，锻材兑换必须明显优于直接出售再购买：

| 输出 | 铜币购买 | 物品兑换示例 |
| --- | ---: | --- |
| 木材 | 5 铜币 / 个 | living_wood 1 个兑换木材 10 个 |
| 石料 | 8 铜币 / 个 | refined_beast_bone 1 个兑换石料 12 个 |
| 金属 | 15 铜币 / 个 | meteor_iron 1 个兑换金属 8 个；star_copper 1 个兑换金属 18 个 |

实际报价全部落库到 home_shop_offers；表格只是 v1 默认种子值。

## 5. 服务层实现

### 5.1 新增文件

~~~text
src/game/home.constants.ts       # 坐标、价格、楼层、家具效果的类型化常量
src/game/home.service.ts         # 查询、购买、进出、升级、扩建、家具与兑换
src/response/home.ts             # /家园 面板与家园操作
src/response/home-shop.ts        # 百纳居商店、购买与兑换
~~~

### 5.2 home.service.ts 必须提供的能力

~~~text
homePanel(qqUserId)
purchaseHome(qqUserId)
enterHome(qqUserId)
leaveHome(qqUserId)
upgradeHome(qqUserId)
expandHome(qqUserId, floor: 2 | 3)
listFurniture(qqUserId, floor?)
craftFurniture(qqUserId, furnitureCode, floor, slotKey)
removeFurniture(qqUserId, furnitureId)
listHomeShop(qqUserId)
buyHomeMaterial(qqUserId, offerId, quantity)
exchangeHomeMaterial(qqUserId, offerId, quantity)
homeEffectProfile(qqUserId)
~~~

所有写操作使用 withTransaction，至少锁定当前角色、player_homes 行、player_home_visits 行、需要扣除的 player_inventory 行、家具定义/报价定义和目标楼层计数。

### 5.3 购买流程

1. 验证角色已注册、处于百纳镇、当前位置正是 baina_residence 坐标、没有进行中的移动/战斗/开采。
2. 锁定角色并确认没有 player_homes。
3. 在百纳镇候选环带随机选取公共地块，排除公共对象、资源、怪物和入口，但允许命中已有 player_homes 坐标。
4. 使用条件更新扣除 500 铜币：UPDATE characters SET copper_coins=copper_coins-? WHERE id=? AND copper_coins>=?。
5. 创建 player_homes，写入 player_events：home.purchased。
6. 返回家园面板和小屋公共坐标，不自动进入家中。

### 5.4 进出家流程

enterHome：

- 只能由房主执行；必须拥有有效小屋、已在百纳镇、在自己的 plot_x/y/z；
- 禁止有队伍成员、主动战斗、移动、开采、昏迷或被关押；
- 插入 player_home_visits，唯一键冲突时按“已在家”处理；
- 调用通缉行踪更新；三星或更高时调用现有执法者生成逻辑；
- 执法者只对该通缉者的遭遇查询可见，不展示给其他玩家；
- 进入家中后显示红名状态和执法者提示，不能通过家园按钮绕过执法战斗。

leaveHome：

- 只删除本人 player_home_visits；
- 角色仍位于 characters 中保存的百纳镇地块坐标；
- 删除后立即恢复普通地图感知和 PvP 规则；
- 写入 player_events：home.left。

## 6. 可见性、移动与通缉改造

这是本功能最重要的兼容部分，不能只新增家园面板而遗漏旧查询。

### 6.1 普通玩家隐藏与通缉例外

普通家中玩家必须从公共玩家列表中排除；但处于百纳镇有效通缉状态的家中玩家必须作为例外公开。统一可见条件为：

~~~sql
LEFT JOIN player_home_visits hv ON hv.character_id = c.id
WHERE hv.character_id IS NULL
   OR EXISTS (
     SELECT 1 FROM player_warrants w
     WHERE w.wanted_character_id = c.id
       AND w.city_region_id = <当前百纳镇区域ID>
       AND w.status = 'active'
   )
~~~

以下查询必须采用上述规则：

- src/game/dungeon.service.ts 的 dungeonPlayersInRange；可改名为 playersInRange，并保留兼容调用；
- src/game/adventure.service.ts 的 coordinateInteractionTargetsFor 玩家查询；
- 任何 /目标、感知列表、坐标互动、伏击候选的玩家查询；
- src/game/pvp.service.ts 的 cityPvp、fieldPvp、startPvpBattle 目标读取与目标有效性检查。

家主在家中调用 /面板 时，不能通过当前坐标看到公共玩家；家园面板只显示房屋和家具。通缉犯例外只作用于周围玩家的公开感知和 PvP 目标查询，不会让其他玩家看到其房屋内部家具或普通家园面板。

### 6.1.1 通缉玩家在感知列表中的排序

`dungeonPlayersInRange` 返回玩家时必须带上 `wanted` 和 `inHome` 字段。`nearbyPoints` 构建玩家目标后，玩家目标之间按以下顺序排序：

1. `wanted=true` 的玩家优先；
2. 曼哈顿距离更近者优先；
3. 名称或 game_id 作为稳定的最终排序键。

排序只调整玩家目标之间的顺序，不改变怪物、建筑、资源和地标的既有排序规则。通缉玩家的显示名称使用“红名”标识，并继续显示可攻击按钮。

### 6.2 家中禁止攻击与通缉例外

在 PvP 入口统一增加 isInHome(characterId) 检查，但不能把“目标在家”直接视为无条件免战：

- 攻击者在家：仍拒绝从家中主动发起普通 PvP；
- 普通目标在家：提示“目标正在自己的家园中，无法攻击或打劫”；
- 处于百纳镇有效通缉状态的目标在家：允许周围玩家按现有合法缉捕规则发起 PvP，不因目标在家而拦截；
- 对通缉家中目标的攻击不应给攻击者新增红名，是否产生战斗掉落、失物返还和悬赏结算沿用现有 resolvePvpVictory 规则；
- 城镇 PvP、回合制 PvP 和任何抢劫入口都必须使用同一个“目标是否为公开通缉家中玩家”的判断，不能只有感知列表能看到而攻击接口仍拒绝；
- 已在战斗中的角色不能进入家园；购买和制作也不能中断战斗。

### 6.3 红名、通缉和执法者保留

- cityWantedAlert：通缉者本人在家时仍返回 wanted=true，并显示“家园内”；
- townPassiveWantedAlert：百纳镇居民仍能收到家中通缉犯的红名公告；
- /通缉：仍列出 active warrant，状态显示“已回到家园（行踪仍暴露）”；周围感知到该通缉犯的玩家可以直接发起合法缉捕 PvP；
- 家中通缉犯的公共目标坐标使用其 player_homes.plot_x/plot_y/plot_z，作为可感知和 PvP 距离判断的位置；玩家仍看不到房屋内部家具和其他家园内容；
- recordWarrantSighting：进入家园时用家园地块坐标记录最近行踪；
- createCityPursuitEncounter：家园入口视为仍在百纳镇，三星及以上进入时照常触发执法者；
- 击退执法者后的冷却、通缉升级和战败关押保持现有逻辑。

现有执法者生成函数位于 adventure.service.ts 内部。实现时应抽成可由“公共城镇抵达”和“进入家园”共同调用的服务函数，避免复制三星判断。

### 6.4 移动和地图

- 家中调用 /移动、/前往、/前往地图、/探索、/寻怪时统一提示先 /家园 出门；
- /地图只给房主追加“我的小屋（x,y）”，其他角色查不到；
- /地图的目标排序加入百纳居，但不把玩家家园写入 map_npcs；
- 房主在公共地块调用 /家园 回家进入家中，不需要地图道具；
- 定时抵达和热重载补偿不应自动把角色送进家中，只有显式 enterHome 才写访问状态。

## 9. 验收标准

### 9.1 基础购买

- 未注册角色不能查看或操作家园；
- 不在百纳居坐标发送 /家园 购买会被拒绝；
- 铜币不足时余额不变，没有半成品 player_homes；
- 并发两次购买只创建一间小屋并只扣一次钱；
- 重启机器人后房屋、坐标和材料仍存在。

### 9.2 坐标与地图

- 百纳镇六座建筑坐标与本文一致且无重复；
- 公会在中心附近，其余商铺距离不完全相同并分布在周边；
- 两个或多个玩家可以拥有相同 plot_x/plot_y/plot_z，但各自只能进入自己的房屋实例；
- 房主 /地图 能看到“我的小屋”，其他角色看不到；
- 家园地块不被资源、怪物或公共建筑覆盖。

### 9.3 隔离与 PvP

- 玩家 A 在家时，玩家 B 的感知、坐标互动、目标列表中没有 A；
- 若 A 是百纳镇有效通缉犯，B 能在感知范围内看到 A，A 在玩家列表中优先显示并带有攻击按钮；
- B 对普通家中玩家不能通过城镇 PvP、野外 PvP、回合制 PvP 或抢劫攻击；对通缉家中玩家则按现有合法缉捕规则允许发起 PvP；
- A /家园 出门后，下一次感知刷新即可正常出现；
- 家中不能移动、探索、开采、加入或创建队伍、开始战斗。

### 9.4 通缉与执法者

- 普通玩家在家不红名暴露；通缉者在家仍出现在本人状态、/通缉和被动提示；
- 通缉犯在家时会出现在周围玩家的感知列表，并排在其他玩家之前；
- 周围玩家可以对家中通缉犯发起合法缉捕 PvP；
- 三星通缉犯 /家园 回家时仍触发执法者，执法者只对该通缉犯产生遭遇；
- 击退、战败、关押、冷却和星级升级与原城镇逻辑一致；
- 通缉犯出门后恢复公共感知，位置仍按现有行踪规则处理。

### 9.5 房屋与家具

- 初始房屋为 1 层简陋木屋；
- 二层、三层扩建有正确前置条件，重复扩建不会重复扣费；
- 每层最多一张床；
- 材料不足、楼层不存在、槽位占用、等级不足时不会创建家具；
- 家具效果只在家中生效，离开后不继续叠加。
