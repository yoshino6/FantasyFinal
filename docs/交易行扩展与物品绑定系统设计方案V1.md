# 交易行扩展与物品绑定系统设计方案 V1

日期：2026-09-06。状态：设计方案，尚未修改游戏逻辑或执行数据库迁移。

本方案是[机巧人偶制造与养成方案](机巧人偶制造与养成系统设计方案V1.md)的配套基础规则，也适用于当前游戏的现存物品。

## 1. 已确定的规则

以下采用用户最后更正的口径：绑定不是仅针对材料，而是覆盖所有物品。

1. **几乎所有非绑定成品均可上架交易行。** 同时保留正常材料、粒子的交易；个别任务、剧情、货币、账号专属物等明确例外单独列出。
2. **所有物品都有绑定状态。** 同名堆叠物允许同时持有绑定和未绑定数量；独立装备、异械、人偶实例分别标记。
3. **所有物品完成一次交易后，在接收方处绑定，不能原样再次交易。** 挂单、托管、浏览、撤单不是成交，不提前绑定。
4. **装备、异械等首次穿戴、启用或实际使用成功后绑定。** 卸下、维修、洗练、充能、重命名不能解除绑定。
5. **所有材料消耗先扣绑定，再扣未绑定。** 使用药剂、食物、维修包等消耗品也采用相同的保留可交易库存原则。
6. **已确认的制造例外：不可逆制造的新成品可以交易；拆解、互转等产物继承绑定。** 这是新产物的发行规则，不代表原物品被解除绑定。

本次延续“完整 MD 设计方案”的任务范围，不将这一套涉及全局库存与历史资产的改动直接上线。

## 2. 当前实现与目标之间的实际差距

源码核对结果如下，并非已经具备这些能力：

| 范围 | 当前情况 | 需要补充 |
| --- | --- | --- |
| 交易资格 | `is_tradeable=1`、可堆叠、回收价大于 0、仅材料/消耗品，且整类排除特殊/家具等 | 按具体物品政策开放，解除不合理整类排除；零回收价不代表不可交易 |
| 普通背包 | 每角色＋物品 ID 只有一行数量，没有绑定数量 | 同一物品的绑定与未绑定分账 |
| 装备实例 | 保存品质、耐久、效果与打造信息 | 每实例绑定、托管占用与成交历史 |
| 交易订单 | 按物品定义 ID 和数量撮合买卖 | 继续支持标准品撮合；新增独立实例逐件寄售与购买 |
| 成交入库 | 直接合并普通库存 | 在成交事务中给接收物品加绑定 |
| 撤单返还 | 按物品 ID 返还数量 | 保留原绑定状态、实例 ID、品质与属性，不重新生成默认物品 |
| 库存操作 | 初步文本检索至少 33 个游戏 TS 文件直接增减或删除普通库存 | 统一库存写入入口，不能只修炼金和交易行 |
| 物品定价 | 市场初始参考价主要从回收价 ×2 产生，并限制 70%～150% 区间 | 新成品需独立生产成本锚；独立装备不能共用同定义硬价格区间 |
| 进入条件 | 游戏服务检查 Lv.10、已登记、注册满 72 小时；响应层还检查位置与梨子喵任务 | 沿用条件并统一服务端校验，新增实例购买不能绕过 |

现有 `is_tradeable` 是“物品定义是否允许交易”，不是“这一份物品有没有交易过”。不能把买家买了一瓶药后直接将全服该药的 `is_tradeable` 改为 0。

## 3. 上架范围与例外清单

### 3.1 默认应当开放

| 物品 | 可交易条件与交付形式 |
| --- | --- |
| 怪材、锻材、炼材、粒子、基材、构件 | 未绑定数量可上架，成交数量在买家处绑定 |
| 药剂、秘药、符咒、投掷物、食物、洗练露、维修包 | 非绑定的未使用份数可交易；不因“特殊”分类误禁 |
| 武器、防具、首饰 | 独立实例、未绑定、未穿戴、不在其他托管/操作中 |
| 被动/主动异械 | 独立实例、未绑定、未启用；保留真实品质、耐久与充能信息 |
| 普通装饰品、可携带家具 | 未绑定、未摆放，且属于可转移物品；摆放后按使用绑定 |
| 非专属书籍、地图、图纸 | 逐物品审核，实际阅读/学习/使用后绑定或消费 |
| 天空粉尘 | 可交易的普通来源份数；为主线实际使用的那份按使用绑定 |
| 灵枢素体、纯粹的灵魂痕迹、育成原液 | 按本方案的新生产绑定规则生成，未绑定可交易 |
| 机巧人偶·未认主 | 未绑定实例可卖；购买即交易绑定，买家可认主但不能转卖 |

“几乎所有”采用默认开放、明确禁用原因的方式做盘点，最终提交物品代码级清单。不能简单把 `is_tradeable=0` 全部改为 1，也不能继续用“特殊”“图纸”等大分类拦截所有物品。

### 3.2 明确保留的不可上架项

- 货币本身、玩家技能点、经验、角色、称号、已学技能、已解锁图鉴、任务进度等非普通物品资产。
- 角色绑定的恩赐、NPC 赠予的专属信物、剧情证明、任务专用钥匙、必须保留的剧情媒介。
- 当前已经明确为绑定的异械图纸、绑定技能相关物，不因同类其他图纸开放而解禁。
- 管理员/测试生成且标明专属的装备，临时战斗道具、限时体验物及不应进入正式经济的奖励。
- 已认主人偶、已开启并形成私人进度的物品、已有剩余次数/内容但尚不支持完整实例交付的容器。
- 已穿戴、已启用、已摆放、正在制作消耗预占或处于任何托管中的实例。

“暂不支持完整交付”必须在清单中显示为待适配项，不能宣称这些物品已经开放；支持后可以移出该例外。

## 4. 绑定时点与行为矩阵

| 行为 | 是否触发绑定 | 处理 |
| --- | --- | --- |
| 查看背包、详情、图鉴、预览穿戴 | 否 | 不改变资产状态 |
| 加入普通物品快捷栏 | 否 | 只是选择操作入口，不视作使用 |
| 装备成功穿戴 | 是 | 对所选实例绑定；失败/取消不绑定 |
| 异械成功启用/装配到生效栏 | 是 | 被动一经生效也算；不能拖到首次主动出手才绑 |
| 家具摆放、非消耗书籍实际阅读等 | 是 | 对实际使用份数/实例绑定，不绑定同名整堆 |
| 药剂/食物一次消耗 | 消耗份数记使用事件 | 优先吃绑定；本次用掉的未绑定份数已销毁，其他未使用份数仍未绑定 |
| 物品只是放进制作面板 | 否 | 不消耗、不绑定；确认时再按实际投料处理 |
| 制作实际消耗 | 原料销毁 | 根据配方规则决定新产物，见第 5 节 |
| 市场挂单、撤单、自然过期 | 否 | 未成交原件退回，保持未绑定 |
| 市场部分成交 | 是，仅成交部分 | 接收数量绑定；卖家剩余托管数量继续未绑定 |
| NPC 商店购买 | 推荐纳入交易绑定 | 买家收到即绑定，避免从基础商店搬同件商品到交易行倒卖 |
| NPC 回收物品 | 物品退出经济 | 按回收规则销毁，不产生给其他玩家买回的无绑定副本 |
| 玩家直接交易、赠送、玩家物品邮件 | 是 | 转给另一角色时绑定，不能通过免费赠送绕过“一次交易” |
| 正常掉落初次分配 | 否，除非奖励本来绑定 | 是生成资产后的首次归属，不是队内玩家之间转卖 |
| 同一角色仓库与背包移动 | 否 | 原状态与来源不变；不同角色不视为同一个主人 |
| 系统奖励邮件领取 | 按附件自身政策 | 邮件只是配送方式，不能一律当交易或一律解除绑定 |
| 维修、充能、洗练、升级原有实例 | 不能解除 | 仍是同一资产；绑定状态至少维持原状态 |

前五项及市场交易符合已确定规则；NPC 购买、赠送和仓库边界是补齐后的推荐默认，实装说明必须面向玩家明确展示。

天空粉尘的特别情况：主线窥探成功但保留媒介时，**只将实际作为媒介的 1 份绑定**。优先沿用已有绑定媒介，不因每次打开剧情页面多绑 1 份，更不能把用于出售的全部 20 份一起绑定。

绑定默认到**角色**，不是 QQ 账号或全账号仓库。绑定期间只能由该角色持有与合法消耗，不能寄到自己的另一个角色。

## 5. 已确认的制造例外及其完整边界

### 5.1 不可逆制造可以产生新的可交易成品

用户已经选择：不可逆制造的新成品可交易；拆解、互转等产物继承绑定。

因此同一份素材不能原样转售，但玩家购买它以后完成新的生产，可以出售新的产品。支持的机巧生产链为：

```text
解构师自产灵枢素体（未绑定）
  → 炼金师购买（该素体已绑定）
  → 素体被不可逆消耗，生产新的未认主人偶（新物品可未绑定）
  → 主人购买（未认主人偶已绑定）
  → 主人认主（绑定伙伴，不能再卖）
```

同理，购买材料制作新的药剂、食物、原液可获得可交易新产品。查看成品详情时显示“新品未绑定，交易后绑定”，同时保留制造者及来源记录。

### 5.2 不允许靠改名或变换容器伪造“新成品”

| 操作 | 产物绑定规则 |
| --- | --- |
| 经过审核的不可逆新成品配方 | 可以重新发行未绑定新品，但专属来源限制仍保留 |
| 拆解、分解、提取、粒子互转、压缩/解压 | 按输入绑定来源继承，不能重置 |
| 改名、洗词条、维修、充能、强化、熔炼附加属性 | 同实例维持绑定，不允许用新 ID 掩盖旧物 |
| 开箱、拆包、合包 | 包装不重置绑定；交易绑定礼包的内容至少继承交易绑定 |
| 制作失败返料 | 返还原绑定构成，不能全部返成未绑定 |
| 取消尚未执行的生产 | 原件原状态，没有新物品 |
| 绑定装备拆出零件后重新组回同类装备 | 作为再制造/翻新继承限制，不计入可解绑定的新品配方 |

仅写“配方不可逆”还不够：要检查完整配方图，防止 A→B→C→A 的循环把同一份绑定资产恢复为可交易物。不能只因本步骤没有直接逆配方就自动放行。

建议为每条配方标记 `new_product`、`transform`、`modify_instance` 或 `package`，未知配方默认继承绑定，待明确盘点后开放。这个分类需要结合产物身份和整体转换链审核，不由物品名是否变化决定。

灵枢素体、纯粹的灵魂痕迹、育成原液、未认主人偶可以列入新生产配方；V1 不提供它们回收为同价值原料的逆路线。普通药剂和食物同样属于新产品。既有可以解构的构件/异械须结合回收闭环单独标记，不能一次性将整个解构目录都标为可重置绑定。

### 5.3 专属来源与已穿戴物的防洗白建议

为避免“绑定神器→拆解→生产普通装备→出售”绕过专属资产限制，建议玩家界面统一显示 `[绑定]`，内部保留原因：

- **交易绑定**：正常买来的原料，可用于经审核的新成品生产。
- **专属绑定**：任务、恩赐、管理员专属奖励、已经穿戴/启用/使用过的永久物品，以及它们拆解出来的材料。

专属绑定在拆解与再制造中持续继承；新成品配方仅对“普通来源或交易绑定原料”重新发行未绑定新品。交易购买的装备穿戴后，原因升级为专属绑定；购买普通材料直接消耗制造不触发这个升级。

这是对已确认规则的防绕过细化建议，实装时需作为公开规则说明，不能只在数据库里暗设。若希望连专属材料也能在新生产中变成可交易物，应明确调整这一条并重新核算专属奖励价值。

绑定来源不能仅靠备注判断，必须进入库存账本；不得让玩家手动修改原因。“解绑定道具”“买回洗绑定”“跨服洗绑定”均不在 V1 范围。

### 5.4 混合投料、批量与失败返料

所有投料仍严格先绑定后未绑定，不能为了生成可交易新品偷偷改为先耗未绑定。预览展示每批将产生的绑定/未绑定成果数量。

- 普通转换配方：本批有绑定输入，则本批产物绑定；全部输入未绑定才产生未绑定结果。
- 获准的新产品配方：普通和交易绑定输入可生成未绑定新品；本批有专属绑定输入，则本批所有产物专属绑定。
- 批量逐批分配原料状态，不把“100 批中一批用了绑定材料”错误扩大为整张订单全部绑定，也不按平均比例分摊一件不可分割装备。
- 随机多产/大成功的额外产物采用同批状态。失败副产物按转换继承处理，不当作新品出口。
- 失败返料从**本次实际扣除账单**恢复；若只返一部分，固定先保留原扣料序列前端的份额，即专属绑定→交易绑定→未绑定，避免通过失败选择性返出更容易交易的材料。
- 每笔账单保留输入分桶、返还分桶、净损失、产物分桶。重试不重新抽一次绑定分配或概率。

例：某转换每批消耗 4 份，库存绑定 3、未绑定 5，做 2 批。第一批用绑定 3＋未绑定 1，其结果绑定；第二批用未绑定 4，其结果未绑定。按批次记录，而不是将两个结果一律绑定或一律未绑定。

点灵失败只损耗 2 份天空粉尘，应直接按这 2 份的绑定优先顺序扣除，素体、痕迹和其他 18 份从未离开库存。成功时才按三组完整耗材计算新品绑定。

## 6. 库存数据模型：保留兼容性但统一所有写入

### 6.1 普通堆叠物

建议保留当前 `player_inventory` 的“角色＋物品”一行结构，避免让已有大量查询突然因为两行绑定/未绑定而重复 JOIN；新增：

```text
quantity                 总库存
trade_bound_quantity     交易绑定数量
personal_bound_quantity  专属绑定数量
unbound_quantity         派生值：quantity - 前两项
```

`[绑定]` 显示前两项之和。专属原因与批次来源在追加式库存流水记录，不能依赖总数表恢复完整历史。

约束：所有数量均为非负整数，`trade_bound_quantity + personal_bound_quantity <= quantity`。清空删除时三项都必须为 0；不能总量删了但另表绑定余额还在。

该结构保留只读总量查询的含义，但**不保证旧写入 SQL 兼容**。所有新增/减少/移动/退款操作必须经过统一服务；旧的 `quantity=quantity-1` 会破坏绑定分账，必须逐入口迁移。

### 6.2 独立实例

在 `player_item_instances` 或统一实例元数据中增加绑定类型、绑定角色、首次交易事件、首次使用事件、原始制造者、所在位置/托管订单与版本。

状态例如 `bag / equipped / device_active / home_placed / market_escrow / consumed`。实际表结构可复用现有装备和异械引用，但必须有统一的“当前能否操作”检查，不能出现既上架又穿戴。

装备成交应转移原实例，不按 `item_id` 新生成默认品质。必须保留品质、耐久、耐久上限、效果 JSON、打造主材信息、附加词条及已经存在的其他实例字段。未认主人偶也同样交付原实例和制造信息。

未认主人偶现在具有出生人格与 1～2 个出生技能，订单应展示核心性格、兼容词条和具体已学技能，交付时原样保留。购买、撤单和认主均不重新随机；其实际报价可能因初始组合不同而有差异。不得把技能不同的两个实例当作同质堆叠物撮合。

### 6.3 统一库存服务

建议提供以下职责，名称可随项目风格调整：

- 发放：明确来源与绑定类型；未知来源不能悄悄当作未绑定。
- 消耗计划：聚合同物品 ID、多槽位需求，校验总量和锁定量，返回绑定优先的分桶方案。
- 消耗提交：事务内按实际计划扣除，写唯一请求流水，返回可用于失败返料的凭据。
- 返还：按原流水恢复绑定/未绑定和实例，不重新判断成品默认状态。
- 移动/托管：保留状态与原始所有权；只有实际跨主人交付才触发交易绑定。
- 绑定：幂等将某份/某实例绑定或提升原因，不能绑定同名所有物品。
- 制作产出：按配方绑定策略和当批输入来源写入，不由各职业自行拼判断。

主线保留、玩家锁定、装备使用、交易托管等限制先过滤不可用库存，再在可用部分执行绑定优先。绑定不是可以绕过锁定或强制吃任务物品的理由。

## 7. 消耗优先级需要覆盖的入口

这是全局行为，不能只覆盖新的人偶培养。

| 入口 | 必须执行的处理 |
| --- | --- |
| 炼金、提纯、萃取、构造、解构 | 绑定优先扣料，产出/返料使用正确继承规则 |
| 锻造、精炼、熔炼、融合、装备修复 | 材料绑定优先；加工现有装备不能解除绑定 |
| 背包直接使用、快捷物品、战斗投掷 | 同一消耗服务，不能战外正确而战斗仍扣错 |
| 自动战斗、旧副本战斗分支 | 与手动战斗同样处理，不能保留旧 SQL 漏洞 |
| 任务提交、转职、进阶、突破、被动研究 | 所有材料支付先绑定，任务保留媒介与数量正确 |
| 家园建造、家具制作、烹饪及活动兑换（存在时） | 库存支付和产出规则一起覆盖，不只搜“炼金” |
| NPC 出售/回收 | 默认先出售绑定份数；明确回收价，物品离开经济，不返入公共货架 |
| 主动丢弃 | 默认先销毁绑定；玩家锁定的仍需解锁，不生成可被别人捡走的无绑定副本 |
| 邮件领取、奖励、补偿、回购/撤单 | 明确来源状态，不能绕过绑定入库 |
| 管理员编辑/清理、旧物品迁移脚本 | 写入总量与绑定分账的守恒，避免修复脚本成为漏口 |

**例外是市场出售**：它不是使用消耗，必须只取未绑定库存。若持有 10（绑定 7、未绑定 3），制作消耗 4 时扣绑定 4；上架 4 时拒绝并显示“可交易仅 3”，不能拿绑定 1 凑单。

## 8. 交易行如何支持标准品与装备实例

### 8.1 标准品继续按数量撮合

材料、固定规格药剂等使用现有买卖订单。卖家上架时只将未绑定数量移入托管；买家下收购单只冻结铜币。

匹配成功时，在同一事务中完成：扣减托管数量、买家绑定入库、卖家收款、税费、买单差额退款、剩余量、成交流水和市场参考价更新。任何一步失败整体回滚。

卖 10、成交 3、撤单 7：买家拥有绑定 3；卖家拿回未绑定 7。撤单不能将已成交 3 复制回来。过期返还采用同一套逻辑。

### 8.2 独立装备和异械逐件寄售

- 卖家选择实例，预览真实词条与价格后托管。每单数量固定 1。
- 买家购买具体订单和具体实例，不对“同一物品定义”盲目撮合一把可能品质完全不同的武器。
- V1 不提供按物品 ID 自动接收任意实例的装备求购单；标准品求购不受影响。后续若做条件求购，必须支持品质/等级/词条/耐久条件。
- 订单保留真实实例 ID 与不可变展示快照，托管期间禁止维修、强化、洗练、穿戴、启用、销毁、邮寄或重复上架。
- 买家确认前再次校验状态与快照版本。成交后原实例归买家且已绑定，不能马上用旧卖家链接修改。
- 撤单和过期返回同一实例；品质、耐久、词条、绑定状态和制造者完全不变。
- 交易列表/详情展示等级、品质、核心属性、剩余耐久/充能、制造者可公开信息、购买后绑定提示；外观相同也不能把不同实例合并成同一报价。
- 目录查看可以解锁基础物品图鉴，实例交易信息仍单独展示；不把买家私有构筑或绑定原因账单公开。

新页面分类建议为 `[全部] [材料] [药剂] [食物] [武器] [防具] [首饰] [异械] [造物] [其他]`，二级分类按原有背包对应类别展开。筛选、关键词、上一页、搜索、下一页保留；内联链接使用蓝色且不自动发送。

### 8.3 价格与费用不能遗漏

现有标准品参考价/限价机制不应继续把新成品直接钉在半价回收锚上。普通量产品采用明确获取成本、前置失败净损耗、稳定产量及制造空间来初始化；已有真实成交形成的参考价不能每次重启被初始化覆盖。

装备/异械实例参考价仅提示，不按同 `item_id` 的统一 70%～150% 区间强制锁死，避免优秀词条或品质无处定价。仍保留正整数价格、资金上限、订单总额安全检查与既有市场风控，不对未知物品随手给 1 铜币硬锚。

现有市场按卖方周成交额收取分段 3%～16% 手续费。本方案生产报价默认是**税前标价**，卖家实际到手要再扣税；想要“到手成本加 20%”，同一固定税率 f 下报价应约为 `ceil(生产成本×1.2/(1-f))`，跨税档需分段精算，不能直接把 20% 当净利润。

例：标价 11159、整笔处于 3% 档时，手续费 `ceil(11159×3%)=335`，到手 10824。相对自产中性成本 9299.05，实际空间约 1524.95，不是 20%。

当前已有 Lv.10/72 小时、订单数量、每日同物品发布次数、周成交额等限制，本方案不顺手删除。需复核挂单额度是否包括未成交卖单占用，及成交时是否再次校验，防止同时挂多张单绕过限额。高价人偶会受到真实额度影响，页面必须提前显示，而不是确认最后才失败。

重复成交、拆单取整、手续费跨档、冻结买款、差价退款、撤单手续费、过期买款返还均纳入守恒测试。人偶“不能转卖”不能替代交易系统自己的反重复结算措施。

## 9. 其他转移渠道必须一致

- **面对面交易、赠送、玩家寄信**：若存在或后续实现，使用同一个跨角色转移服务；收件后绑定。当前管理员发物邮件不是玩家交易入口，不能将其现状误写为已支持玩家互寄。
- **公会仓库**：绑定物不能交给共享仓库再由别人领走；非绑定物交公库时记录捐赠来源，实际交付另一个玩家时绑定。若不能追溯，V1 暂不开放该类共享流转。
- **地面丢弃/拾取**：绑定物丢弃应销毁或只能本人取回；非绑定物被另一玩家拾取按转移绑定，不能用丢地上绕过市场。
- **系统邮件**：撤单返还保留未绑定；市场成交配送如果借邮件完成，附件在创建时已经标记买家绑定，不能等领取以后才决定。奖励邮件按奖励定义决定。
- **NPC 买回**：如果将来做回购，必须认领原实例、保留绑定状态；不能按定义重新生成无绑定副本。当前 NPC 回收并不要求建立回购系统。
- **礼包、随机箱子**：买到的箱子已绑定，开出的物品继承；箱子内容不是制造新品。不能把一件绑定装备装进未绑定礼盒后卖出。
- **交易失败**：未提交事务的转移不绑定；已提交但通知失败的转移已经绑定，补发通知不能回滚一次交易历史。
- **退款/人工纠错**：区分错误成交恢复和普通撤单。只有有完整原交易账、物品未被消费或改造的异常修复才能恢复原状态；不得给玩家通用“退货解绑定”按钮。

## 10. 旧库存、旧订单与迁移

当前普通库存混在同一数量中，虽然市场有成交记录，但物品可能已经被消耗、混堆、拆解或再次流转。不能把历史买入总量直接当成现在的绑定数量，也不能宣称可以精确还原所有旧物品来源。

推荐首次迁移采用明确切换时间：

1. 先生成只读报告：现存物品政策、总库存、实例数量、穿戴/启用实例、旧卖单托管、买单冻结款、邮件附件、未知来源和现有不可交易物。
2. 短暂关闭新挂单、成交及其他库存写入，清算或原状撤销所有未结束旧订单；卖家拿回原资产，买家拿回剩余冻结款。迁移引起的撤单不收罚费。
3. 当前穿戴、已启用、明确恩赐/任务绑定、测试实例标为专属绑定。可靠日志能定位到具体实例的既往穿戴/使用也回填绑定。
4. 无法定位历史来源的普通剩余材料/道具与未穿戴实例，作为“历史库存”维持未绑定，并从切换时起严格执行；这是一次性兼容口径，要公开说明，不是忘了处理历史交易。
5. 原本不可交易的物品逐代码判断：真正专属的回填绑定；只是被旧分类/市场能力挡住的正常成品重新开放。不要将旧 `is_tradeable=0` 一律等同于已绑定，也不要一律清零。
6. 新增字段和所有读写适配部署完成后，核对各角色总量、绑定分账、实例所有权、钱包＋冻结款＋卖家到账＋税费。确认守恒后再开放市场。
7. 保存迁移批次和逐项变化账。中断可重入；程序回滚不得丢掉新绑定字段或把已交易一次的物品恢复可出售。

如希望更严格冻结全部无法证明来源的历史物品，必须另行确认影响范围，不能用“防漏洞”理由擅自把所有老玩家库存全绑。本方案推荐上面的兼容迁移。

## 11. 前端提示与玩家可理解的规则

背包按总量聚合显示，例如：

```text
天空粉尘 ×23
[绑定] 8  [未绑定] 15
可制作使用：22（主线保留 1）
可上架：15
[详情] [上架]
```

上架确认：“本次托管未绑定 10 份。成交部分将绑定买家；未成交撤回仍可交易。”购买确认：“购买后绑定，不能再次转卖，可正常使用/制造。”

穿戴确认：“首次穿戴后绑定，卸下仍绑定。”当前已经绑定的装备不重复弹出无意义二次确认；实际穿戴仍由同一事务执行。

配料确认：“本次消耗绑定 7＋未绑定 3；生成未绑定育成原液，失败时材料全损。”若来源导致成品专属绑定，明确显示原因。

不要让全部页面只显示灰色 `[绑定]` 却没有数量。交易行只展示可交易库存，但详情可以查看总拥有、绑定、可交易与托管数量；搜索结果不能因为还有绑定 10 份就显示可卖 10 份。

空列表说明应区分“没有符合筛选的成品”“只有绑定物品”“物品正在托管”“该类尚不支持完整交付”，不能统一误报背包没有物品。

## 12. 验收场景与关键遗漏清单

| 场景 | 必须得到的结果 |
| --- | --- |
| 买 3 瓶药，自己原有未绑定 7 | 总数 10，绑定 3，可交易 7；不会整堆绑定 |
| 绑定 3＋未绑定 7，使用 4 | 剩未绑定 6；总量和分账守恒 |
| 绑定 7＋未绑定 3，上架 4 | 拒绝，可交易数量明确为 3 |
| 卖 10，成交 3，撤回 7 | 买家绑定 3；卖家未绑定 7；无额外份数 |
| 装备预览后取消/穿戴失败 | 不绑定 |
| 装备穿戴成功再卸下 | 仍绑定、不能上架 |
| 异械启用后未曾出手 | 已绑定；停用不解除 |
| 两人同时购买同一装备实例 | 仅一人成交，另一人不扣钱；原实例只属于一人 |
| 上架和穿戴并发 | 一项成功、另一项校验失败，不能同时成立 |
| 装备交易/撤回 | 词条、品质、耐久、附加信息与实例 ID 不变 |
| 交易绑定材料生产获准新品 | 新品可未绑定，原材料已消耗，不能另返一份 |
| 绑定材料互转/拆解 | 产物继承绑定 |
| 专属装备拆解再加工 | 不能通过生产流程洗成可交易新品 |
| 配方批量混合绑定来源 | 逐批分配，不全单污染、不随机洗白 |
| 失败返料/服务器重试 | 按原扣料分桶返还一次，不丢绑定、不重复产物 |
| 任务粉尘反复查看/窥探 | 不消费整堆、不反复新增绑定份数 |
| 箱子、邮件、礼物、共享仓库 | 转移与开包不能绕过绑定 |
| 强化、洗练、维修原实例 | 不生成新的未绑定同物副本 |
| NPC 购买再市场出售 | 推荐规则下买入即绑定，不能直接倒卖 |
| 只读详情/图鉴/快捷栏 | 不绑定、不扣料 |
| 钱包/税费/买单退款/过期 | 资金守恒，不因物品新品种导致溢出或少退 |
| 旧库存迁移与重启 | 无资产数量变化、无绑定原因重置、迁移可重入 |

实施前用源码检索加数据库定义导出建立“全部资产写入点”和“全部物品代码交易政策”两张清单。本文已经核到市场、库存、装备与邮件主干，33 个文件是初步检索命中数，**不是完整运行路径数量，也不代表每个入口已经验证**。

未来代码验收包括项目类型检查、纯函数绑定分配测试、隔离数据库的成交/返还/并发测试和 QQ 客户端页面点击。未覆盖的脚本、旧战斗分支、活动或管理员入口必须逐项列出，不以“主要功能正常”代替全局消耗规则完成。

## 13. 对机巧方案的同步修订

- “未认主人偶可交易”精确为：**新生产且未绑定的未认主人偶可出售一次**；玩家购买后虽未认主，也已绑定，不能转送或再卖。
- 炼金师购买的素体/灵魂痕迹/粉尘会绑定，但可以通过批准的不可逆点灵生产新的未绑定人偶，维持跨副职业供应链。
- 买到的育成原液立即绑定；开瓶仍先用绑定瓶数，再使用未绑定瓶数。
- 人偶绑定伙伴身份从认主开始；物品交易绑定可能早于认主，两个状态不能合成一个布尔值。
- 任何人偶材料退款都保留原分账；培养和认主错误不能通过“先返一个无绑定成品”来处理。
- 制造成本表仍采用材料获取价值，绑定不让自己持有的材料变成免费；实际市场交易税费另计。
- 新系统正式开放获取前，应完成全局绑定和交易的基础适配，避免首批人偶已经多次倒卖后再追溯补绑。
