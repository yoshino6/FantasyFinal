# 动态世界系统实装结果报告

> 实装日期：2026-09-03
>
> 本报告如实区分「已可运行」与「仅预留数据结构/待继续制作」，避免将首批内容误认为完整内容库。

## 本次已完成

### 可运行闭环

- 区域独立天气：14 个现有地图区域各自拥有天气档案、当前状态、演变修订号与演变日志。
- 渐变天气前沿：天气仅在预报序列的相邻状态间自然演变；每次间隔 70–120 分钟。`rare_abrupt_front` 的固定概率为 1.2%，并会写入账本。
- 区域异象：首批纳入叶脉流光雨、荧孢雾潮、根辉迷雾、琥珀花雨、丝雨回澜、玻潮盐雾、鸣岩回风、铁花灰雨、坠星泥雨、镜雪极光、雷丝垂云、蚀光微雨等区域生态异象。
- 后台推进：每 10 分钟结算到期天气与巡游 NPC；每一次巡游路线推进、天气转变均写入 `game_event_ledger`。
- 战斗快照：创建怪物战斗时冻结区域天气，保存到 `combat_environment_snapshots`；本场后续回合不受外界天气刷新影响。当前已实际接入双方先攻修正，并在战斗面板和回合日志显示。
- 反刷取：探索资格来自跨越 8×8 世界网格产生的「有效暴露」，原地重复移动/重复探索不会增加；十分钟窗口上限 12，奇遇成功后有 5 分钟角色冷却，且同一角色只能持有一条活跃奇遇。
- 奇遇实例化：奇遇模板、实例、选择、命运印记、世界线阶段均分别存表。选择采用实例 ID 校验与数据库唯一约束，无法重复领取同一结算。
- 首批内容：7 条区域天气关联奇遇、21 个选择结果，覆盖密林、河岸、赤铁隘口、沼泽、雷崖、霜冠/蚀界、世界树草甸。每项选择会给出铜币、命运印记及世界线阶段影响。
- 巡游与地点：5 名巡游 NPC 具备独立路线与行动修订记录；5 个常驻地点具备状态表，可作为后续支线/建筑入口的数据源。
- 管理能力：管理员可从 `/管理` 进入“世界生态管理”，查看区域天气、世界线、巡游实体、活跃奇遇与当日账本；`/世界事件账本 [数量]` 可追溯具体事件载荷。

## 本次未完成的范围

以下不是故障，而是完整设计中需要持续内容生产和跨模块联动的后续范围：

1. 设计文档设想的数百条奇遇与数十名 NPC 尚未全部写成模板；本次只提供可扩容的表结构、调度和 7 条端到端样例。
2. 世界线阶段已经记录，但尚未直接调用现有 Boss 刷新服务来生成/关闭具体 Boss；现有 `bossGate` 仅作为配置元数据保存。
3. 巡游 NPC 已独立行动和记录，但尚未渲染为地图上的可交互实体，也未实现多人同场景的发现者/见证者/协助者分配。
4. 天气的元素预报已经快照和展示；目前战斗中实际生效的是双方先攻修正。水/火/雷/风等伤害倍率尚未接入所有技能、DOT、召唤物、反击与 Boss 特殊伤害链，贸然局部接入会导致职业不公平。
5. 隐藏掉落目前只以命运印记和铜币实现；专属物品、掉落池、邮件补偿、重复保护尚未制作。

## 后续合理化建议

1. 先把天气伤害调整抽象成战斗统一的「元素最终倍率」钩子，再覆盖普通攻击、主动技能、DOT、召唤物与 Boss 脚本，配套自动化数值测试。
2. 为 `dynamic_encounter_templates` 增加编辑器/导入校验：节点可达性、选择唯一性、奖励上限、前置旗标和世界线改变量必须在发布前验证。
3. 实装公共场景实例表，明确发现者、见证者、协助者与旁观者，设置奖励归属、人数上限、跨群到场窗口和同 IP/同队伍软限制，才能完整处理“喊人刷 NPC”。
4. 将世界线阶段映射到既有 Boss/建筑/巡游 NPC 的显隐或刷新规则，并以账本关联 ID 追踪每次激活与回收。
5. 管理面板下一步应提供世界线回溯、天气人工覆盖、异常事件检索、角色暴露预算查询及导出；所有人工操作都应同时写入管理员操作日志与世界事件账本。
6. 先修复全项目现有 TypeScript 错误，再增加天气演变、并发重复结算、奇遇幂等结算、玩家串通模拟等自动化测试。
