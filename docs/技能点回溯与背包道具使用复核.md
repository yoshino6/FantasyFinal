# 技能点回溯与背包道具使用复核

日期：2026-09-06。状态：代码已实装，静态检查、格式器测试和隔离数据库事务测试通过，QQ 真机发送未验证。

## 1. 玩家行为记录的现状

目前不能认为所有玩家行为都有完整、可回放的日志。现有 `player_events`、战斗日志、制作手记和管理操作日志分别覆盖部分业务；没有统一覆盖每次点击与所有数据变化的玩家操作账本。管理网页的 `operation-journal` 也不能代表全部聊天端玩家行为。

技能点有独立的 `player_skill_point_ledger`。源码中的角色初始 1 点、升级增加、进化伴随升级增加、技能学习、技能升级、专精、鉴识分支、匠心学习以及洗点退款均有专门写入位置。正常总来源为初始等级的 1 点加后续升级点数；管理员测试重置等例外不能作为正常额外来源。

旧存档可能没有流水，或只有管理员补录的 `legacy_opening_balance`。该记录只是当时的可用余额，不能还原此前花在每个技能上的点数。本轮没有追加一个声称能恢复全部旧行为的虚假历史，也没有新增全玩家操作日志系统。

## 2. 洗练露最新规则

| 情况 | 执行规则 |
| --- | --- |
| 完全无记录 | 回溯后可用点数直接等于当前角色等级。 |
| 只有旧余额记录 | 仍视为无明细，执行等级回溯。 |
| 有真实收支或此前重置记录 | 按可核实、未退款的实际投入处理；部分流水不自动补满等级。 |
| 记录计算结果超过等级 | 最终可用点数限制为角色等级，超出额度不发放，预览明确提示。 |
| 原余额已经超过等级 | 预览后校正到等级，修正额记账。 |
| 预览后升级或改变加点/配置 | 原确认失效，重新预览。 |
| 没有需重置的内容 | 不消耗药；重复确认已完成请求返回原结果。 |

例如 Lv.30、当前剩余 4 点的无记录角色，回溯后为 **30 点**，净增加 26 点，不会变成 34 点。有记录角色当前 20 点，可退 7 点，结果为 27 点；若记录可退 20 点，最终最多为 30 点。

无明细的等级回溯同时撤销普通付费技能学习和旧强化，付费技能保留发现记录，需重新学习；免费、绑定、当前职业配置赠送的技能保留基础能力。技能等级、专精及鉴识分支回到基础值，受影响的快捷技能、被动关联和自动配置同步整理。不能既保留旧强化，又领回一整套技能点。

付费学习技能在洗练后遗忘，保留发现记录并进入「可领悟（未学习）」列表，可重新花费技能点学习。即使只有部分流水、缺少旧学习或升级明细，也不会因记录不完整而留下这些付费技能的旧学习状态与专精；有流水时仅退其中已记录且未退款的投入，不按今天的价格猜测昨天的花费。免费、绑定和当前职业赠送的基础能力保留，它们无法核实的旧升级进度不凭空退款。追加 `allocation_refund`、`legacy_level_reset` 和必要的 `allocation_reconcile` 记录，使新余额与账本一致；修正/退款不算额外升级来源。无明细回溯后已有结清记录，下一次改走流水，不能重复补满等级。转职使用相同服务。

## 3. 背包与道具复核

只读审计了当前 **778 项 consumable 定义**，逐项分类保存到[现存道具使用审计.json](现存道具使用审计.json)。审计脚本为 `scripts/item-use-audit.ts`，不调用正式初始化，不包含玩家身份或数据库密码。

| 分类 | 数量 | 当前入口与行为 |
| --- | ---: | --- |
| 直接战斗外使用 | 126 | 回复药、回蓝药、混合回复、幸运/经验秘药、背包食物、图纸盲盒，显示 `[使用]`。 |
| 专用流程 | 46 | 洗练、修理、技能书、改名/改性、进化预览、地图和卡片，显示 `[使用]` 并进入对应流程。地图/卡片为查看，不消耗。 |
| 战斗用途 | 541 | 投掷、控制、净化、回合增益和战术药等标注“战斗中使用”；国王讨伐专用装置保留专属战斗用途。 |
| 持有或其他交互用途 | 65 | 构造图纸、赠礼、任务凭证等，不伪造一个会扣物品但没有效果的直接使用按钮。 |

审计所见定义均归入以上类别，没有遗留到“未知使用方式”。分类覆盖不等于逐项完成线上实测；其中大量道具是同规则的等级/品质变体。

背包首页“最近获得”、道具分类列表及物品图鉴均接入相同使用规则；补齐“秘药、投掷物、符咒、技能书”子分类。`/使用道具 <物品编号>` 可手动使用普通战斗外道具，按钮附带独立请求编号。

### 已处理的边界

- 回复按实际固定值或最大生命/魔力比例结算，混合回复只要一项有收益即可使用；满血满蓝且没有回复收益不扣药，不超过上限。
- 普通药不代替复活；死亡状态不使用。战斗外入口检查 PVE/PVP 活动战斗，不能绕过战斗回合。
- 检查物品归属、数量、角色等级；效果更新使用当前已知炼金定义，品质不会再次重复乘算。
- 同一条使用按钮重复点击，只执行一次；即便一瓶药不足以回满，也不会因双击重复扣两瓶。要再次使用时从背包生成新操作，手动重新发送命令视为新的使用意图。
- 幸运/经验秘药保存完整剩余战斗场次；战斗内外使用同一同族取强规则，兼容旧秘药代码。同强度且剩余场次充足时不浪费新药，较弱药不覆盖较强效果。
- 背包食物直接消耗现有成品，不重复收餐厅制作材料和加工费；写入餐食增益并重算属性。有餐食正在生效时暂不覆盖、不扣食物。
- 旧图纸盲盒按配置随机给尚未持有的图纸，全部已持有时不消耗；缺少必要效果配置时整笔回滚。
- 战斗快捷栏不再接受洗练露、食物、技能书等非战斗物品；旧快捷配置的实际使用也先拦截。PVP 不消耗只对怪物收益有效的经验/幸运秘药。普通回复药在战斗里无回复收益时也不消耗。

没有新增“把所有回合增益提前保存到下一场战斗”的备战系统。持续再生、护盾、净化及 24 类战术药仍按各自既有战斗状态和回合规则使用；背包明确标注，避免误以为场外点击就能永久获得增益。

## 5. QQ 行内链接发送错误修复（2026-09-06）

用户日志中的糖水屋成品货架返回 `40034108：qqbot-cmd-enter不支持show`。已安装 QQ 适配器会把带显示文字的自动发送行内按钮转换为 `qqbot-cmd-enter` 并附带 `show`，触发平台拒绝。

背包与图鉴 `[使用]`、成品货架 `[详情]`、炼金手记详情与再次投料、炼金说明与提纯、导师入口、图纸研习及维修包链接统一设置 `autoEnter: false`，生成蓝色 `qqbot-cmd-input` 链接。点击只填入命令，玩家手动发送后才执行；使用命令的请求编号与防重复消耗机制保留。底部独立键盘按钮沿用原交互。

补充使用实际 QQ 适配器渲染的回归，覆盖背包首页与道具分类、直接使用与专用流程、成品货架和炼金手记；检查输出无 `qqbot-cmd-enter`。本次类型检查及相关回归通过，未主动向 QQ 发送实测消息。

## 6. 付费技能遗忘补正（2026-09-06）

洗练的技能遗忘与退款金额分开判断。有学习扣点记录，或属于普通付费且非职业赠送、非绑定的已学技能，洗练时删除学习状态与专精，保留发现记录供重新学习；不再要求每次旧升级都存在完整流水才能遗忘。鉴识被遗忘时，其旧分支同步重置。缺失的旧费用不估算，仍沿用无明细按等级、有明细按记录且余额不超过等级的规则。

类型检查通过；隔离数据库回归 20 项通过，无失败或跳过。新增验证涵盖旧鉴识分支、部分流水、免费/绑定/职业赠送技能保护、清理战斗引用，并执行实际技能列表与学习函数，确认遗忘后可以重新学习、再次洗练只退新学习投入。未操作真实玩家存档，QQ 实际点击未验证。
