# 天赋 V2 与地图开局衔接复核

复核时间：2026-09-08 23:23 前后。对象为正在修改的工作区，不是已部署正式服。基准：[初始天赋重设计方案 V2](./初始天赋重设计方案V2.md)及[路线奖励 V4](./地图初始路线奖励与信物修订V4.md)。本轮只改文档、读取代码与运行检查，未接管正在进行的天赋代码开发，未运行数据库初始化、迁移或部署。

## 1. 结论

**两份设计可以兼容，当前代码尚处于新旧迁移中，不能只更新目录就按完整天赋 V2 开放。**地图剧情仍是 14 图、42 路线、113 基础分支，结构检查通过；天赋运行目录已经独立为 9 类、90 项，旧 G01～G18 都保留且 code 不重复，“？？？”的 U01～U10 尚未加入。

当前最大的衔接风险是：缺可用性门槛的目录选择、身份与技能写入不核验结果、仍走普通经验的教学、无援天赋与默认出战伙伴，以及新旧奖励来源不分。旧“113 分支已通过”的报告只代表当时的旧天赋流程，不覆盖新 90／100 项天赋组合。

《初始天赋重设计方案 V2》开头的源码快照仍写 18 项，本次实时检查已是 90 项。本轮不改动正在作为另一项工作基准的天赋 V2 数值与正文，只在这里记录当前差异。新出现的 `talent-rewards.ts` 也说明收益接入仍在进行，不能仅凭旧文件搜索就断言某项永远未实现。

## 3. 代码中的主要冲突与缺口

### 3.1 需要在开放新版选择前处理

| 项目 | 现场证据 | 影响与处理方向 |
| --- | --- | --- |
| 目录没有 availability 门槛 | `talent.config.ts` 的定义没有 availability；`divine-message.ts` 显示全部目录，`character.service.ts:321` 附近按目录 code 接受选择 | 部分效果或入口尚未接通时也可选择。应在配置、目录与选择事务共用可用性判定；不能只隐藏按钮，旧命令仍可直达 |
| 绑定技能写入可能为空 | `character.service.ts` 写祝福后用 `INSERT ... SELECT ... WHERE code=? AND category='bound'` 写技能，但未检查 affectedRows 或重查 | 新目录先部署、技能定义未同步时可能建成有祝福、无技能入口的角色。应在同一事务预检定义并确认落库；缺失则友好回滚，不能先建角色再等以后补技能 |
| 目录数值和实际旧结算不同 | 本次快照 G12 目录 1.75，`awardRealmExperience` 仍 1.25；G02 目录耗时 0.50，移动仍 0.80；G10 目录半价／每日 5000，`divine-effects.ts` 仍 0.92／200；G01 目录休息 3 倍、败战满 HP，旧休息／醒来入口仍 1.3／50% | 不是文案可以解决的差异，需把新函数接到真实发奖、移动、报价／扣款与恢复入口。若接入新收益函数，还须移除旧 G12 乘数，避免 1.25×1.75 重复放大。这里是修改中快照，不宣称它们已部署成正式问题 |
| 特殊成长缺少分流 | `opening-progress.service.ts:14` 的教学和后续安全委托仍调用普通 `awardRealmExperience`；该函数先 `repairEvolutionProgress` 再按境界／进化上限处理 | 当前 U 类尚未上架，暂不会让玩家选入这条断路。将来加入 U 类前必须实现独立成长状态、教学节点、投影与 SP 账本；仅增加目录条目会造成按普通经验升级或被旧进化修复截断 |
| 黄金兔默认出战 | `companion.service.ts:39` 的 `grantGoldenRabbit` 插入 `is_out=1`；现有目录已有 J08 断契狂徒 | 喂兔后自动得到战斗参与者，会破坏无援资格。领取时按天赋默认待命；已拥有和实际参与要分开，不能为追求天赋收益强迫玩家放弃善意分支 |
| 身份仍多源读取 | `talent-data.ts` 的 `ownedTalent` 从 `player_blessings` 按 code 排序取第一个；`opening-combat.ts` 读取所有匹配的旧／新前缀 | 单角色多条历史祝福时，面板／收益与战斗可能认出不同数量的天赋。需先按创建证据完成迁移清单，建立唯一权威身份；不能用字典序默选，或把全部旧祝福都套新版倍率 |
| 奖励 V4 尚未接入 | `opening.service.ts`、`opening-pack.service.ts` 仍发旧礼包或 keepsake；`openingFollowupQuest` 仍优先寻找未登记 keepsake | 若只删旧信物而不改主线，会要求玩家递交已经不再发放的物品。新分支奖励、档案记录、交接门槛与恢复机制必须同版本切换；V4 的新增宝箱与恢复奇物也尚未实现 |

注册单事务、防重复创建、鉴识独立绑定与安全护送仍可复用；不需要因为改叫天赋重新设计整个角色注册。选择校验与新定义预检应补在已有事务内。

### 3.2 固定奖励与新收益函数的边界

已确认开局教学向 `awardRealmExperience` 传 `{ fixed: true }`，当前旧经验函数据此绕过 G12 和全局倍率。这个已有保护应保留。

新出现的 `talent-rewards.ts` 已有 `talentExperience` 等函数，其上下文目前是 kind、key、derived 等，不能假定它自动认识固定初行。接入时必须先识别固定来源，再决定是否调用普通成长倍率／延迟经验／天赋次数；“没有传 kind”不等于固定奖励豁免，例如 G12、C02 的分支并不都依赖 kind。

特殊成长还需单独识别教学事件，不能因为 `fixed=true` 就绕过特殊成长分流而发普通经验。反过来，不能把普通教学先发经验后再转专属资源，使同一次事件产生两份进度。

神秘宝箱、少女金币、关系 +1、女神事故返还都应持有稳定来源事件键；开箱和归档恢复不产生第二次可成长事件。当前源代码没有完成本稿完整来源模型，本轮也未做全 90 项收益入口的运行验收。

### 3.3 目录、版本与生成器

- `opening-content.ts` 已改为从 `talent.config.ts` 导出当前目录，**路线生成器目前不会覆盖这个独立配置**。旧脚本仍从 V1 解析 18 项并写到 `opening-content.generated.ts`，成为一份不再被该入口使用的旧输出，需清理来源混淆，但不应误报为当前直接覆盖 90 项。
- 路线生成器仍读 V2／V3 旧奖励字段，没有读本次奖励 V4。因此不能仅修正文档标题后运行它并宣称 V4 已进入游戏；先调整结构化奖励配置与生成方式。
- 当前 `divine-message.ts` 目录仍为分页行加两行分类，没有 V2 要求的独立分类页；详情返回固定第 1 页／全部，丢失分类与页码。未知分类会变成空列表，旧“交涉／生存”分类缺映射。蓝色链接 `autoEnter:false` 已保留。
- 路由已有 `/天赋目录`、`/天赋详情` 和旧神技别名；V2 建议的 `/天赋搜索`、`/觉醒天赋` 尚未在本次快照找到。旧搜索仍有自己的入口，不应写成“完全不能搜索”。
- A01 厄里斯返还分支仍有“原有的神技印记没有改变”文字。要随新剧情版本改为“已经觉醒的天赋印记”，不全库替换历史消息。
- 地图 C01／T03 与天赋 C01／T03 短编号重名是合法的；实际完整 code 当前区分 `opening_...` 与 `talent_...`。后续主线、奖励日志和工具不能只存短编号。
