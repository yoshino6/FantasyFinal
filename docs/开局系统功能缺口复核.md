复核日期：2026-09-08。依据当前工作区源码及 V1 系统方案、V2 路线脚本、V3 六地图重设计。本文记录功能差距与验收要求，不代表下列缺口已修复。

## 一、结论

当前已有 **14 张初始地图、42 条路线、113 个互斥选择分支**。还缺的主要是玩法结算、路线后续任务和城镇服务，并非单纯补几张地图的故事。

运行时已有技能限定注册、路线存档与分页、部分分支奖励、交涉后随从邀请、批量宝箱、公会基础服务、女神与航路的世界记录。但尚不能按“设计细节全部实装”交付。

**奖励版本澄清（2026-09-08）：**R医／R食／R匠等是早期 V1／V2 的通用补给分类，不能套用于全部当前剧情。V3 已明确废止重写六图十八条路线的 R 礼包，改为每个分支独立的特殊物品或资格；这些路线只共享一次基础落脚补给。下文 R 礼包差距只适用于仍采用 V2 的七图二十一条路线、V1 三人冒险团 F03，以及主方案宝箱中明确引用的两个奖励档。此前表格未写清适用范围，不能据此给 V3 路线增加旧礼包。

### 2. 不同身世还没有形成不同的可执行主线

除黄金兔照料、黄金宝箱开启等少数特殊检查外，入门阶段主要用一次“完成交接”统一结束。文案里写出的鉴识练习、治疗、工艺、勘路、飞行登记等任务，没有逐项转成独立进度与服务条件。

设计要求的 `E(1)+E(2)` 固定经验，以及抵达／登记／教学的 40%／20%／40% 发放，没有接入。选职也没有发放一次普通职业适配武器。

开局结束后，`openingMainQuest` 不再提供任务，旧主线仍要求升至 Lv.5；职业与后续地图指引仍带百纳镇背景。世界树出生玩家尚未获得完整的本地 Lv.1～5 成长路线。2026-09-08 补充：已按最新要求移除学习鉴识门槛，改为女神在降临时赠送绑定 Lv.1，后续专精由玩家自行消耗技能点升级。

证据：[统一入门结算](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:134)、[旧主线等级分支](E:/猫拉瑞亚/FantasyFinal/src/game/main-quest.service.ts:109)、[百纳镇职业引导](E:/猫拉瑞亚/FantasyFinal/src/game/career-quest.service.ts:24)、[职业选择结算](E:/猫拉瑞亚/FantasyFinal/src/game/character.service.ts:450)。

验收要求：逐分支走通“选择 → 真实教学动作 → 奖励 → 下一条主线”；基础链到 Lv.3，再由安全区附近的低级生活或战斗委托衔接到 Lv.5。

### 3. 仍沿用 V1／V2 的路线：旧 R 礼包发放不完整

适用范围：砾风石滩、幽暗密林深处、岩脊山麓、赤铁山道、雾藻湿地、百纳镇、世界树的 V2 路线，以及三人冒险团 F03。当前运行时也只有这些路线引用 `choice.pack`。

**不适用于 V3 的世界树草原环带、晨露河岸、沉星沼泽、霜冠高原、雷鸣断崖、月蚀遗迹。**V3 第 10 节明确规定十八条新路线不再叠加 R 礼包；应按各分支专属奖励与实际用途验收，详见本文第 10 项。

仍引用旧礼包的路线中，当前 `choice.pack` 的通用处理基本是发草药；R契额外发 3 份饲料。若这些路线继续采用现有 V2 设计，其礼包存在下表差距；若后续重写，应该同步替换奖励定义，而非先机械补发旧礼包。

| 礼包 | 与设计的差距 |
| --- | --- |
| R医 | 已有 3 份草药，缺 2 份基础回魔药 |
| R食 | 缺路线额外的 3 张热食票 |
| R匠 | 缺普通木／石／金属各 3 份及对应维修额度 |

### 4. 随从尚未真正参与冒险和战斗

名册和交涉邀请可以形成数据，但缺少以下接入：

- 每三次主人行动触发一次支援，手动与自动战斗共享节奏。
- 随从伤害、有限治疗、受伤和安定度损失的实际结算。
- 击败结算调用随从经验函数；该函数目前只有定义，没有调用方。
- 按物种限制专长，并将寻物、采集、警戒、交涉、工坊专长接入对应玩法。
- 黄金兔的低血量保护、每日寻药、每日面包能力。
- 后续可持续获得饲料的正常渠道；当前只有开局礼包和一次契约教学奖励。

随从面板已经写着“每三次主人行动触发一次”，目前会误导玩家以为支援已经生效。

心情规则没有必要改回固定几万：当前邀请依据现有心情占上限的比例判定；Boss 满比例时基础概率为 0.05%，不吃 G09 入队倍率。后续须继续沿用按掉落总价值形成的现有心情上限，不能把随从安定度当作野怪心情。

证据：[随从服务](E:/猫拉瑞亚/FantasyFinal/src/game/companion.service.ts:9)、[未接入的经验函数](E:/猫拉瑞亚/FantasyFinal/src/game/companion.service.ts:84)、[提前承诺支援的面板](E:/猫拉瑞亚/FantasyFinal/src/response/companion.ts:25)。

### 5. 初晓武器与猩红王冠仍缺专属效果

六种初晓史诗武器和五个猩红王冠部位已有物品定义与基础属性，但初晓效果只有数据标记，没有对应战斗处理；猩红王冠也没有进入现有套装识别列表。

需要补齐六武器各自效果、王冠单件余烬护盾、两件提升、五件休息恢复，并接入装备摘要及效果去重。魔族少女出手路线的结算展示也应明确实际得到的随机部位。

证据：[装备初始化](E:/猫拉瑞亚/FantasyFinal/src/database/opening-chests.ts:12)、[套装识别白名单](E:/猫拉瑞亚/FantasyFinal/src/game/epic-equipment.service.ts:40)。

### 6. 公会服务尚未全部适配到世界树和新城镇

世界树已经有独立接待人物和基础服务，但旧入口仍有以下问题：

- 职业选择的返回按钮仍指向百纳镇 `guild_counter`。
- 悬赏板的地点检查仍要求百纳镇柜台，世界树不能直接复用完整悬赏办理链。
- 商店购买页已使用当地商人，商店首页、闲聊、切磋仍可能出现赫伯特及其百纳镇经历。
- “委托与教学”目前主要是一次性教学奖励，不能替代持续的本地低级委托。
- 浮叶镇、雪灯坳、霜龙客舍、眠鲸旅市已有基础落脚点，尚缺与其剧情相符的完整人物服务及日常活动。

证据：[职业返回按钮](E:/猫拉瑞亚/FantasyFinal/src/response/adventure.ts:764)、[悬赏位置限制](E:/猫拉瑞亚/FantasyFinal/src/response/bounty.ts:35)、[商店闲聊](E:/猫拉瑞亚/FantasyFinal/src/response/guild-shop.ts:65)、[基础教学](E:/猫拉瑞亚/FantasyFinal/src/game/opening-guild.service.ts:61)。

### 7. 安全护送缺目的地关闭后的恢复路径

路线存档之后，如果目标安全地图关闭或入口不存在，当前到达结算会一直提示“目的地正在维护”，不会重新选择开放的安全点。玩家仍受剧情锁约束，需要补上可恢复的改道逻辑。

F02 救援分支的到达文案固定写百纳镇、梨子喵和归来的三人组。若改送世界树，必须换成当地接引；只有送到百纳镇时才播放这组场景。

证据：[目的地检查](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:89)、[固定百纳镇场景](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:47)。

## 三、故事细节和后期伏笔还缺的兑现

### 8. 厄里斯版 A01 存在已经确认的场景断裂

当前按整页是否含“阿库娅／蓝发女神／补救单”过滤原故事。A01 的事故与女神见面位于同页，因此事故场景也被删除。

本次只读运行时内容检查：A01 原正文 2 页，应用当前厄里斯过滤规则后剩 **0 页**。结果是玩家从沼泽衔接直接跳到厄里斯面前，缺少如何遇见守门兽、如何意外死亡的过程。

应将事故段与神界段拆成独立场景，厄里斯接任只替换神界段，不过滤完整剧情页。

证据：[整页过滤](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:36)、[事故与女神同页](E:/猫拉瑞亚/FantasyFinal/src/game/opening-content.generated.ts:437)。

### 9. 带走女神目前主要是世界状态变化

目前已记录阿库娅下界、唯一持有人和厄里斯接任，但还没有完整的阿库娅同行 NPC、唯一实际位置、跟随与离线行为、三段落地故事、女神办事桌、事故函换回执等玩法。`aqua_stage` 尚无剧情推进使用。

注册页面会实时读取当前女神，也需要补齐注册途中发生世界切换的衔接规则，避免上下页无解释地换人；首次死亡叙述的随机内容也应固定到同一轮注册存档。

证据：[世界表](E:/猫拉瑞亚/FantasyFinal/src/database/opening.ts:7)、[首次切换](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:107)、[注册页面](E:/猫拉瑞亚/FantasyFinal/src/game/divine-message.ts:25)。

### 10. 特殊凭物当前用途大多只是说明文字

V3 的 54 件分支奇物，以及魔界邀请函等，已有发放或见闻记录。当前没有对应的逐项办理链：见闻表只见插入和查询，`used`、`archived` 未随实际交接更新。

这些才是新版剧情奖励的主要验收对象。例如逃婚小姐 M02 的拒婚见证书／婚宴座次卡／银餐刀，霜龙 C02 的暖爪纹／半枚封鳞／零欠款租约，魔剑 E03 的无刃剑心／不熄余火／空白判决。每人仅获得所选分支对应的一项，不替换成 R 礼包，也不将三个分支全部发放。

需要逐件明确并实现：谁办理、在哪办理、是否消耗、是否归还、发什么回执、留下什么资格、重复点击如何处理。逃婚小姐、霜龙、冰雪女王、无头骑士、鲸背市场、临时魔王和魔剑路线都应检查当前承诺是否落地，不能只检查物品有名字。

魔界、王都、天穹等明确留到后期的大章节可以继续作为伏笔；本轮应兑现的是设计中写明“现在可以使用”的服务和持久资格，而非一次性把所有后期地图做完。

证据：[凭物记录](E:/猫拉瑞亚/FantasyFinal/src/game/opening.service.ts:77)、[见闻只读查询](E:/猫拉瑞亚/FantasyFinal/src/game/opening-guild.service.ts:79)。

## 四、尚需验证，不能直接判定已可发布

以下为验收缺口，与上面的已确认功能缺失分开记录：

1. 在隔离数据库初始化新表、新地图和物品；验证重复初始化、旧角色保留、旧技能与新神技并存。
2. 真实开放地图与出生锚点检查：水域、Boss、危险叠区、地图建筑占位；高空落脚点普通导航与接驳的高度一致性。
3. 所有移动／寻怪／战斗／交涉／背包／传送等入口的剧情锁检查，包括旧按钮、错误参数、直接调用服务；随从操作也应覆盖交涉及活动状态边界。
