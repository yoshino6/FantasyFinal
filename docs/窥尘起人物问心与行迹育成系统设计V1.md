# 窥尘起人物问心与行迹育成系统设计 V1

状态：**原始设计稿**。问心部分的代码状态与验证结果见[实装成果](窥尘问心实装成果20260914.md)；行迹育成尚未全量实装。“全部有效操作按业务结果记录”的实施口径以[人物问心与全量有效操作育成实现方案 V1](人物问心与全量有效操作育成实现方案V1.md)为准。

## 一、定位与既有系统边界

人物育成分为两条互相呼应的线：**问心**决定今后每份等级成长偏向哪里；**行迹**记录角色真正做过什么，并在积累后形成对应六维的永久质变。玩家在问心事件中是异世界片段的旁观窥探者，不扮演片段中的审判者，也没有唯一“正确”答案。选择反映观察方式与愿意放弃的能力，不直接评判善恶。

项目现有六维为体质、精神、力量、智力、敏捷、感知。`realm_stage=2` 是窥尘；角色出生六维成长总和随机为 8.0～12.0，精度 0.1。现行等级属性按 `当前成长 × playerGrowthShares(level)` 追溯计算；1～10 级每次升级 1 份、11～20 级 2 份、之后每十级递增 1 份。一转另向成长字段加职业成长，进化注射也会直接提升等级。因此新系统必须分别处理**出生可塑成长、职业等外源成长、已结算的等级属性**，不能只在一次普通战斗结算里修改六个 `_growth` 字段。

本稿的硬边界：问心普通结果只在倾向与排斥两维之间转移出生可塑成长；大成功不扣排斥维，可将出生可塑六维总和提高，但绝不超过 12.0。质变只增加独立的永久基础六维，不修改成长率；现有职业、二转、进化、天赋、装备、技能效果及六维到战斗属性的换算不随本系统改动。角色解锁时的出生总和保留为历史基线 `S₀≤12.0`；当前出生总和 `S=Σg` 可因大成功从 `S₀` 增加到至多 12.0。

## 二、问心：Lv.11～Lv.20 的逐级成长抉择

### 触发与流程

- 窥尘角色只在**实际升到 Lv.11～Lv.20** 时生成问心记录，每个目标等级一条。升到 Lv.10 及以前、Lv.21 及以后都不生成。进化注射等特殊路径若使角色升入该区间，同样必须出票。
- 一次奖励连升多级，就为跨越的 Lv.11～Lv.20 按等级顺序生成多条，不因一条战斗奖励只算一次。功能上线前已经超过 Lv.10 的窥尘角色，在打开人物面板、主动打开问心或触发普通操作检查时，幂等补齐该区间内缺失的记录；超过 Lv.20 也至多补 Lv.11～Lv.20。每条记录保存 `from_level/to_level`、当时境界、事件版本、选项、变更前后成长与计算明细。
- 待选记录可以留在人物面板中，继续获得经验不剥夺选择权；多条待选必须按等级先后作答。升级时先按升级前的成长结算该等级属性；该次问心改变**下一次及以后**的成长。封顶经验条填满但没有升级时不触发。
- 事件卡给出一个具体的异世界生活片段及六个可选回答，让玩家确实能从六维中选择更倾向的一维。选项明示倾向与排斥维，不预告会落入 80% 的普通结果还是 20% 的大成功，也不在选择页预报具体增减数值。确认时由服务端独立判定结果类别并结算；选项一经确认不能重复领取，按钮只填入命令、由玩家发送确认。

### 数值规则

记当前**出生可塑成长**为 `g=(g体,g精,g力,g智,g敏,g感)`，当前总和 `S=Σg≤12.0`；解锁时的初始总和另存为 `S₀`，只作历史基线，不限制大成功增加成长。职业等外源成长另记为 `p`，人物今后的实际单份成长为 `g+p`，职业成长不参与问心增减。问心选择确定倾向维 `a`、排斥维 `b`（两者不同）。确认时服务端独立判定普通结果 80%、大成功 20%，选项本身不带隐藏的强度数值。

```text
目标增量 T = max(1.0, 向上取整到 0.1〔g[a] × 10%〕)

普通结果：实际转移量 d = min(T, g[b])
          g'[a] = g[a] + d，g'[b] = g[b] - d，Σg' = S

大成功：实际增量 d = min(T, 12.0 - S)
        g'[a] = g[a] + d，g'[b] = g[b]，Σg' = S + d ≤ 12.0

两种结果均保持其他四维不变；所有 g'[i] ≥ 0，按 0.1 精度结算。
```

这里的 10% 以**所选倾向维当前的出生可塑成长值 `g[a]`**为基数，不包含职业或装备加成；当 `g[a]=0` 时目标仍为 1.0。“至少 1”是**目标增量**，不是不足时仍保证到账 1.0。数据库现为一位小数，服务端以整数“十分之一成长单位”计算，目标值向上取整到 0.1 后再执行转移或上限截断，不使用浮点误差直接写成长字段。

普通结果若 `g[b]<T`，排斥维直接减到 0，倾向维只增加 `g[b]`；若 `g[b]=0`，本次普通结果不改变成长，也不去扣其他四维。大成功完全不扣排斥维，若剩余总容量 `12.0-S<T`，只增加剩余容量；若 `S=12.0`，本次大成功也不改变成长。概率判定不因上限、排斥不足或具体选项而重新抽取，避免玩家通过重试改变已经提交的结果。

例如六维各 2.0、`S=12.0`，选“倾向智力／排斥力量”，目标为 `max(1.0, 2.0×10%)=1.0`：普通结果让智力成长从 2.0 到 3.0，力量成长从 2.0 到 1.0，总和仍为 12.0；同一状态若判为大成功，则因总和已满 12.0，本次不增不减。再如 `S=10.0`、智力 2.0、力量 0.4，普通结果只转移 0.4，力量降至 0、智力升至 2.4；若判为大成功，则智力升至 3.0、力量仍为 0.4，总和升至 11.0。

“12”是**当前出生可塑六维成长总和的硬上限**，不再用作一维的差值参照。普通结果不能抬高总和，大成功可以逐次填补 `S₀` 距离 12.0 的空位；一转职业成长及其他外源成长不占这 12.0 的问心上限，也不会因问心被扣除。

### 问心事件题库与答题口径

正式运行时内容见[窥尘问心深层事件题库 V3（500 题）](窥尘问心深层事件题库V3.md)。题库包含 500 个独立的异世界事件，覆盖城镇秩序、战斗抉择、人际边界、探索伦理、技艺责任、交易权力、委托忠诚、家园归属与生命哲思。每个题干只陈述已经发生的片段及其深层冲突，不用疑问句索要答案；六个选项分别写明旁观者看破的本质、愿意承担的代价和无愧于心的选择。倾向与排斥按该项实际倚重和放下的能力标注，不采用固定维度搭配。每题提供六维各一个倾向选项；所有题共用本稿的 10% 目标增量、80%／20% 结果判定与 12.0 总上限。

玩家始终是旁观者，只能提出判断，不能亲自进入片段。事件显示时应有“你只能看见这一幕，无法进入它”的叙事锚点；选择后从[问心选择结果文案](窥尘问心选择结果文案V1.md)抽取一段模糊结语，并只列实际改变的成长方向，不展示具体数值或结果类别。短期内避免重复同一道题，也尽量错开同类生活场景。

## 三、行迹：真实行为积累与质变

### 行为口径与六维映射

角色从创建起即可记录行迹；窥尘以前只积累和展示，达到窥尘后才开放质变结算。人物所有**已提交的有效业务结果**都记事实，包括物品买卖、委托接取／完成和每场战斗胜败／撤退的最终结算；记录的是结果，不是指令、战斗回合或每次出手。打开页面、点击失败、读对话、重复提交、管理员补发或生成的世界事件不能凭空产生人物行迹积分。每一笔包含 `character_id`、规范事件类型、来源业务 ID、实际结果、六维权重、计分、版本和时间；同一业务结果有唯一键，重试不重记。权重表达角色用了什么能力，**不表达道德优劣**。

| 类型及结算点 | 倾向权重示例 | 不计入或限制 |
| --- | --- | --- |
| 委托接取、完成交付、有效放弃：护送、采集、调查、修缮、救援等分开归类 | 护送：体质2、精神1；调查：智力2、感知1；采集：感知2、敏捷1；修缮：力量2、智力1 | 接取、放弃记事实但可为零积分；重复交付不记；同模板刷取递减 |
| 任务阶段完成：解谜、谈判、探索、战斗等按真实完成目标归类 | 解谜：智力2、感知1；谈判：精神2、感知1；探索：感知2、敏捷1 | 只读剧情、自动推进标记不计；与委托交付同一成果不双计 |
| NPC 有结果的互动：交涉成功、赠礼达成、关系事件等 | 交涉：精神2、智力1；照料：精神2、体质1 | 普通寒暄、刷同一句对白不计；每日与对象设次数上限 |
| 每场野外战斗最终结算：胜利、失败、撤退分别记 | 根据本场已结算的贡献摘要分配：防护偏体质，近战输出偏力量，施法偏智力，机动偏敏捷，侦察偏感知，支援偏精神 | 不记录每个回合／出手；等级差过大、召唤物与队友贡献须另判；失败不能伪记胜利 |
| 每场 NPC／玩家切磋最终结算 | 本场有效防护偏体质，命中与招架偏感知，机动偏敏捷，策略偏智力，压制偏力量，支援偏精神 | 败北仍记结果；同对手重复、约定刷局、未达贡献门槛可记事实但不给分 |
| 野外调查、地形勘察、发现线索、真实救助 | 勘察：感知2、智力1；救助：精神2、体质1 | 单纯移动、地图查询和可反复领取的同一坐标不计 |

默认每个合格的**高价值结算**给 **3 行迹点**，按表中 2:1 分到两个维度；战斗按本场贡献摘要归类，单场最多 3 点。买卖、接取、放弃等其他有效结果也记事实，积分可为零或较低，详见实现文档。此为待校准的 V1 建议值，不是已确认的游戏经济参数。每个业务来源维护去重键；同一模板或同一对手当天前两次 100%、其后 25%，每日同类累计上限 12 点，每周全类型上限 120 点。上限按上海自然日／周计算，溢出行为仍保留在“行迹记录”中但不发点，提示应说清原因。不同任务难度可在成功结果处加权，但不得因为低风险高频动作超过完整委托。

行迹面板展示六维累计、最近有效来源、去重或衰减说明、距离下次质变的进度。玩家可看见“为何得到这 2 点感知、1 点智力”，而不是只看到一个隐藏倾向标签。

### 质变结算

建议先采用**可验证的固定门槛**：某一维累计每满 100 个有效行迹点，可结算一次该维质变，获得该维 **永久基础属性 +1**；扣除该维 100 点，其他维不扣。每一维每个自然周最多结算一次，角色累计质变上限和高等级收益衰减需用真实游玩节奏与战斗测算再定，未定前不得无限开放。质变不提高 `g` 或职业成长，也不改变当前出生可塑成长总和 `S`；六维基础属性的 +1 应进入现有统一面板、战斗重算与来源明细。达标时由玩家在人物面板确认，允许留存待结算，不在重复回调里自动连领。

这样两个方向有明确差别：问心改**未来每份等级成长的构成**，行迹给**某一维当下永久基础值**。两者可以同向，但不会靠刷交互把六维成长总和冲过 12。若后续希望“行迹质变也改变成长率”，必须改为同一预算内的重分配，并重新评审问心价值，不能直接叠加。

## 四、落地时的数据与结算要求

1. 增设人物出生可塑成长档案：六维 `g`、解锁时初始总和 `S₀`、当前总和 `S=Σg≤12.0`、外源成长来源、当前成长版本。历史角色不能直接把现有 `_growth` 之和当 `S₀`；应从职业记录及其他来源逐项核对，无法可靠拆分的角色列入人工迁移清单，不能猜一个初始值写入。现有角色数值先生成只读对账表，确认后迁移。
2. 增设“已结算等级成长六维累计”或逐级快照。迁移时以角色现有面板口径固化当前等级已结算份数；以后每次实际升级按当时 `g+p` 增加该级份数。问心改变 `g` 后**当前面板保持不变**，下次升级才用新值。职业变更如何对既有等级追溯，必须保留当前职业规则的效果，不应被这次系统暗改；可以在外源成长层单独保留职业追溯项。
3. 给问心票建 `character_id + to_level` 唯一约束；事件生成、升级、成长累加、选项确认、成长改写、日志同属事务。角色行锁和幂等键处理并发按钮、重复命令、断线重试。服务层验证境界、票状态、选项版本、普通结果的等量转移、大成功的 12.0 总上限，并持久化内部结果类别和选中的模糊文案；所有 UI／命令入口调用同一服务。
4. 给行迹建立“事实账本”和“六维余额／质变账本”，来源业务 ID 唯一；所有有效业务结果在其自身成功提交的事务中写入，其中战斗按每场最终结果结算。若原业务不能共享事务，则用可靠结算事件与消费去重处理，不能先给行迹再回滚业务。管理员补录应单列来源，并默认不产生有效点。
5. 角色详情将出生可塑成长、外源成长、总实际成长、已结算等级属性、永久基础六维与质变次数分开展示。旧版缓存与重算路径要一起切换，避免面板显示对了但战斗仍用旧的 `g×总份数`。

## 五、实施顺序与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A：只读对账 | 梳理全部成长写入、升级路径、行为结算点和历史角色拆分结果 | 每个角色能解释出生、职业、既有额外来源；无法解释者不自动迁移 |
| B：成长账本 | 独立出生可塑成长与已结算等级属性，接入所有升级路径 | 迁移前后面板及战斗六维相等；一转与进化既有收益不丢失 |
| C：问心 | 事件池、六选项方向展示、待选队列、80%／20% 判定、模糊结果文案、事务确认与回放日志 | 连升多级多票；当前属性不跳变；普通结果总和不变，大成功总和至多 12.0；排斥不足只转移实扣值；不可重复领取 |
| D：行迹 | 从实际业务成功点接入类型映射、去重、限额和可查账本 | 失败／只读／重试／同源重复／管理员路径不产有效分；任务与委托不双算 |
| E：质变与平衡 | 基础六维奖励、面板展示、数值回放、滥刷观察 | 奖励只加一次，不修改出生可塑成长；不同玩法均能合理到达门槛 |

本轮只完成设计与 500 道事件题库、结果文案草稿。需要评审行迹点数与限额、质变累计上限，以及历史角色的具体迁移办法；上述建议值不应当作已实装承诺。
