# AOE 防御后倍率统一复核与实装

> 已被后续直接威力方案取代：以 [AOE直接威力回调与实装](AOE直接威力回调与实装.md) 为准。以下是历史实现，不代表当前伤害算法。

日期：2026-09-16。范围：玩家、域民/导师借用的玩家技能、普通怪物、Boss、灵兽、人偶与异械的群体直伤。

状态：代码及离线定向验证完成；未执行线上数据库初始化、重启或真实玩家战斗验收。旧 V3 文档“威力系数约60%”是历史方案，本篇取代其群伤算法。

## 1. 本次改了什么

- 新增统一群伤配置 `src/game/aoe-damage.config.ts`，共64项固定攻击配置：10项普通玩家技能、44项怪物/Boss技能（含兼容旧版技能）、6项人偶技能、4项异械技能。
- 群伤不再先把攻击系数压到单体的60%。先使用单体参照威力计算防御，再乘每目标直伤比例。
- 普通 PvE、PvP、敌方攻击、敌方借用玩家技能、混乱友伤、独立蛇母AI、人偶与灵契的相关直伤路径同步。原生群攻只有一个存活目标时仍保留折算，不退回完整单体伤害。
- 技能威力行改为“单体基准××；每目标伤害××%（防御结算后）”，效果说明同步最终基准及比例。
- 数据库初始化覆盖最终威力和描述，可重复执行；不重置SP、技能学习、专精、快捷栏或自动战斗设置。
- 本轮不改变MP、CD、吟唱、职业资源消耗、施法占用回合、控制持续时间、Boss破除机制。仍按现有资源、冷却与附效为技能分档，不按冷却一刀切。

## 2. 实际算法与边界

令 A 为计入威力、专精及原有攻击加成后的攻击量，D 为目标有效防御，R 为群伤比例：

```text
单体参照直伤 = A² / (A + D)
群体每目标直伤 = 单体参照直伤 × R
后续再进入原有抗性、减伤、护盾及生命扣除流程
```

暴击、随机波动与取整沿用各战斗引擎原有顺序。比例描述是“相同面板、防御、其他修正下的参照直伤比例”，不是扣除固定护盾之后实际掉血的严格比例。命中失败为0；普通正伤害仍受最小1点及取整规则影响。

例如A=1000、D=1000：单体500伤害；新65%群伤325。旧方法把攻击量改成650，只造成约256伤害，实际只有51.2%。新方案避免高防御额外惩罚群攻。

| 定位 | 本轮主要使用比例 |
| --- | --- |
| 常规群伤、轻量附效 | 65% |
| 群减防、减速、较强附效 | 60%～65% |
| 强控制或额外机制结算 | 55%～60% |
| 高资源二转、充能、自损、可打断预警爆发 | 70%～75% |

基准威力是同冷却与资源档的伤害预算，不表示每项都有一招完全同条件的现成单体技能。带职业资源、预备回合或额外代价的技能使用更高预算。具体值以表格为准，不能将所有技能机械改成同一比例。

旧版蛇母/乌兹条目保留兼容：仅当数据库存在相应技能时同步，不重新创建已撤出的怪物。蛇母当前独立AI直接读取同一配置，避免只改数据库但实际出招仍用旧常量。

额外动态机制：

- 万法同劫：被转换的单体技能保留原单体基准，新增群伤防御后乘65%；原生群攻使用自己的比例，不再额外乘一次65%。人偶目标选择路径也识别此全体化，避免把全体攻击当作单体转去攻击人偶。
- 裂空振翼：100%单体基准，追加群体横扫防御后乘65%，说明与日志同步。
- 艾森缠缚的双目标直伤按65%处理；单体追击仍是单体，不错误再折算。
- Boss百分比生命机制、持续伤害、附加控制、尾扫后的单体追击等保留各自独立预算，不因本次群攻直伤规则重复打折。

## 6. 验证与生效

- `npx tsc --noEmit`：通过。
- 核心定向集：`aoe-damage / automaton-combat / hidden-combat / threehead-mother / boss-component-damage`，118/118通过。
- 加入 `skill-balance / resident-combat` 扩展回归：637项，635通过，2项既有失败：
  - `goblin_royal_signal_flag`：下位标签与现有5回合冷却不符合旧测试等阶范围断言。本轮未改该非伤害技能。
  - 切磋结算SQL契约：角色行迹记录校验报“行迹角色不存在或不是玩家角色”；模拟数据尚未覆盖该业务路径。
- 测试使用 `npx tsx --test --test-force-exit --test-reporter=spec ...`，避免现有导入模块的常驻句柄拖住退出；不是跳过测试。
- 新增覆盖：64项配置在低/同/高防御下的最终比例、种子全体直伤登记完整性、专精基准、重复描述同步、双方规则引擎倍率、人偶实际施放仅一个目标时仍折算。
- 未实测：线上数据库初始化、QQ面板真实渲染、真人组队战斗和长期胜率。不能据离线测试宣称线上平衡已最终验收。

发布需加载新代码，并走项目原有数据库初始化流程，使技能表同步新基准及描述；本次没有操作线上数据库或重启服务。建议发布后观察1/2/4目标场景、低防/高防敌人，以及同回合资源支出下的单体/群体总收益。
