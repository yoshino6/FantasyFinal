# 全图动态奇遇与世界线系统设计方案

> 状态：设计方案（本轮不实施代码）
> 适用范围：现有百纳镇、幽暗密林、世界树地表十个野外区域，以及后续地下城与扩展地图
> 设计目标：让地图上的 NPC、势力、怪物与地点持续「生活」；让一次相遇留下可追溯的后果；让个人选择能够汇入世界事件，却不把关键内容锁死给后来者。

## 1. 设计结论

本系统由四层状态组成：**世界局势、区域态势、NPC 行动、玩家命运**。它们共用同一套事件语言，但拥有不同的可见性、生命周期与结算范围。

```text
世界局势（全服、长周期）
  -> 区域态势（区域、时段/周目）
    -> NPC 行动（实体、独立行动记录）
      -> 场景奇遇（可相遇的机会）
        -> 玩家选择（个人命运）
          -> 因果影响（标记、关系、资源、威胁、线索）
            -> 后续奇遇 / Boss / 世界事件 / 新世界线
```

核心原则如下：

1. **NPC 是行动者，不是固定按钮。** 每个重要 NPC 有目标、日程、资源、关系和行动日志；玩家没出现时，他们仍会推进自己的计划。
2. **奇遇是配置化因果图，不是一次性随机文案。** 每个节点有前置、选项、检定、效果、延迟后果和收束出口。
3. **全局与个人必须分层。** 全服共同推进「世界进程」；玩家保存自己的立场、债务、目击和结果。世界改变后，错过的人仍有替代入口，绝不永久丢失主线能力或 Boss 基础奖励。
4. **日志优先于快照。** 所有重要改变先写不可变事件，再更新查询用的状态快照；奖励、选择和 Boss 解锁必须可审计、可重放、可幂等。
5. **不按分钟暴力模拟全图。** 用「懒推进 + 定时分片」演算 NPC 与区域，既让世界真实，又能在 MySQL 与单机器人实例上稳定运行。
6. **故事可常遇，价值不可刷。** 频繁移动、原地折返、组队呼叫都可以让玩家看见世界的余波，却不能无限重置稀有抽取、首见奖励、世界贡献或隐藏掉落。

首发内容建议达到 **12 个区域主题、8 条世界线、48 名重要 NPC、180 条 NPC 行动模板、360 个场景节点、96 个稀有链节点、24 个区域事件、12 个 Boss 前置变体**。这不是一次把所有内容硬塞进随机池，而是一个可以按区域和世界线持续增量扩容的内容库。

## 2. 与现有项目的衔接边界

本方案在当前项目之上增量建设，不重做已有地图、战斗或角色体系：

| 现有能力 | 本系统如何复用 | 不应破坏的边界 |
| --- | --- | --- |
| `map_regions`、`map_npcs`、`map_special_objects` | 区域、固定地标和 NPC 作为内容锚点 | 不把动态状态塞进静态地图表 |
| `characters` 的坐标与移动 | 仅在玩家进入、移动、探索、抵达时检查可触发奇遇 | 不替换现有移动、旅行、地下城规则 |
| `adventure.service.ts` 的遭遇、战斗、交涉、躲避 | 奇遇可调用既有战斗/掉落/对话能力 | 不绕开战斗事务直接发装备或 Boss 材料 |
| `player_npc_affinity` 与 NPC 资料页 | 好感成为关系维度之一 | 不用好感取代阵营、秘密、债务等独立状态 |
| `player_events` | 保留为面向玩家的历史摘要与管理员审计入口 | 不能承担高频 NPC tick 的完整事件流 |
| `monster_spawns`、Boss 与悬赏 | 世界事件控制「可出现的变体」或「激活条件」 | 不重复生成核心 Boss，不修改已在战斗中的实例 |
| `Format`、命令路由与按钮 | 只展示当前情境的少量可行动选项 | 关键校验必须在服务层，不信任按钮参数 |

建议新增专用的 `world_event_log`、`npc_action_log` 与状态快照表；不要把它们混进 `player_events`。前者按「世界实体」查询并可能高频写入，后者按玩家读取、保留周期和隐私要求不同。

## 3. 名词与状态层级

| 名词 | 含义 | 范围 | 典型生命周期 |
| --- | --- | --- | --- |
| 世界线（worldline） | 一条可阶段化推进的宏观冲突，如矿脉污染、月蚀复燃 | 全服 | 数周至数月 |
| 世界阶段 | 世界线的当前稳定阶段 | 全服 | 直到阈值/事件推进 |
| 区域态势（region state） | 某区域的安全、繁荣、污染、警戒、天气等数值与标签 | 区域 | 数小时至一周 |
| 势力（faction） | 有目标、资源、盟友/敌人的集体 | 全服/区域 | 长期 |
| NPC 实体 | 可命名、可追踪的行动者；重要 NPC 必须有独立身份 | 全服/区域 | 长期或剧情期 |
| 行动计划 | NPC 在某段时间内尝试完成的行动 | 单 NPC | 分钟至天 |
| 行动记录 | 行动实际开始、成功、失败、中断及其输入输出 | 单 NPC | 永久摘要 + 可归档明细 |
| 奇遇模板 | 可复用的内容定义，不保存玩家运行状态 | 内容库 | 版本化长期存在 |
| 奇遇实例 | 某角色/队伍一次实际看到的节点 | 玩家或队伍 | 分钟至任务结束 |
| 命运标记 | 对玩家未来选择的结构化影响，如「欠下灯使人情」 | 角色 | 有明确过期或收束条件 |
| 回响（echo） | 玩家选择投射到区域/世界的量化贡献 | 玩家 -> 世界 | 本周期结算后归档 |

### 3.1 四层状态的权责

```text
世界：决定“这片大陆正在发生什么”。例如月蚀遗迹的封印松动。
区域：决定“此处现在是什么气氛”。例如雾藻湿地警戒+2、浓雾。
NPC：决定“谁正在做什么、带着什么信息”。例如灯使阿岚正在护送火种。
玩家：决定“我知道什么、欠谁什么、曾经站在哪一边”。例如玩家救过阿岚，却偷走过祭司信物。
```

任何效果均须标明其落点。举例：救下灯使可以给玩家 `lampkeeper_trust +20`，给区域 `safe_route +1`，给世界线 `dawn_relay.support +1`；但不会直接让全服 Boss 消失。

## 4. 核心游玩循环

```text
移动 / 探索 / 抵达地图标记
  -> 读取角色命运、区域态势、活跃行动与世界阶段
  -> 在预算内挑选一个最匹配的场景奇遇
  -> 玩家观察、选择、战斗、交涉或离开
  -> 原子结算个人结果与回响
  -> 立即或延迟改变 NPC 计划、区域标签、后续节点
  -> 在面板、地图、传闻和 NPC 资料中给出可理解的反馈
```

每次探索不保证触发剧情。建议权重为：常规风景/资源 45%、普通遭遇 30%、动态 NPC/环境奇遇 18%、稀有或世界线节点 7%。当玩家在短时间内连续未触发有意义内容时，动态奇遇权重逐步补偿；同一模板则有个人冷却，避免重复刷脸。

### 4.1 反刷取：移动不是无限抽卡

触发器不以“执行一次 `/移动`”作为一张独立抽卡券，而以**有效探索步**累积探索暴露度（exposure）。只有满足移动真实性、空间新鲜度和时间节奏的移动，才可参与奇遇候选抽取。

| 校验层 | 规则 | 结果 |
| --- | --- | --- |
| 移动合法性 | 复用现有位置、旅行、战斗和体力校验 | 非法/未完成旅行不进入抽取 |
| 空间新鲜度 | 记录角色近 20 个有效格簇；在同一小格簇往返只给极低暴露度 | 来回横跳不会重置稀有概率 |
| 路径质量 | 只有距离上次有效探索点达到阈值、抵达新地标邻域、跨区域边界或停留调查，才产生完整暴露度 | 鼓励探索，不强迫走固定路线 |
| 时间节奏 | 每角色按 60 秒/15 分钟/24 小时三档限制抽取与奖励 | 高频命令仍可移动，但不密集结算事件 |
| 内容冷却 | 模板、内容家族、NPC、稀有池各有独立冷却 | 换坐标不能绕开同一剧情链 |
| 世界窗口 | 世界线节点按事件窗口、个人贡献来源与日上限结算 | 不能靠连续换号推进全服 |

建议参数从保守值起步：每个角色每 60 秒最多进行 1 次完整候选抽取；每 15 分钟最多获得 3 次普通奇遇收益和 1 次动态 NPC/稀有池判定；连续 8 次无有效探索移动后，普通遭遇仍可出现，但稀有池权重归零，直到抵达新格簇、完成互动或自然冷却。参数必须配置化并通过数据观察调整，不能散落在 handler 中。

**暴露度不是体力，也不能囤积。** 建议每次有效探索增加 1～3 点、上限 6 点，抽取后消耗 1 点；超过上限直接丢弃。玩家下线后只自然回落到基础值，不会积攒一整天后连开多次稀有奇遇。未触发高价值事件时可获得“叙事保底”修正，但保底只提高未见过的普通/链式节点，不提高隐藏掉落和世界贡献。

所有抽取均先生成 `encounter_trigger_attempt`：它记录移动前后格簇、有效性、被拒原因、候选集合摘要、种子、最终模板或空结果。空结果同样记录，因此管理员可以区分“概率没有命中”和“玩家因折返被降权”，也能发现异常脚本行为。

### 4.2 看见同一 NPC，不等于复制同一奖励

动态 NPC 到达一处地点时，会形成持续 5～20 分钟的**场景在场实例**。其他赶来的玩家可以见到同一位 NPC、听到同一段传闻、参加公共战斗或看到其离开后的现场；但每人的选择、命运标记和私人对话都绑定自己的 `encounter_instance`。

- 首位发现者获得“发现/引介”资格，而非独占整个故事；
- 后到者进入 `witness`（目击）、`assist`（协助）或 `aftermath`（余波）入口，文本和可选项不同；
- NPC 独有的首次礼物、隐藏掉落、情报和世界贡献按**角色 + NPC + 场景周期 + 来源键**唯一结算；
- 可协作的护送、建设、讨伐会共享进度，但每个角色只有一次有效贡献，且必须满足不同的行动类型或最低参与度；
- 队伍正式组队时可创建一个共享战斗/护送实例；未组队而同时赶到的人只共享场景，不共享彼此的个人抉择。

这让“喊朋友来看看”成为社交乐趣，而不是让一个稀有 NPC 被十人轮流榨取十次奖励。

### 4.3 玩家可见的选择类型

| 类型 | 例子 | 结果设计 |
| --- | --- | --- |
| 观察 | 跟踪足迹、倾听争执、检查货箱 | 获得线索、风险或新的选项，不强迫消耗 |
| 介入 | 护送、劝架、出手相助 | 改变关系/区域态势，可能进入战斗 |
| 交易 | 交材料、交换情报、承担委托 | 有明确成本与可核验回报 |
| 立场 | 袒护一方、公开证词、保持沉默 | 改变阵营印象与世界线回响 |
| 冒险 | 潜行、偷取、伪装、赌注 | 有技能/属性检定、失败后果和安全下限 |
| 离开 | 暂不介入 | 不惩罚玩家；NPC 会按自身计划继续行动 |

### 4.4 区域天气：可预报的环境状态，不是随机惩罚

天气属于区域态势的一级状态，由气候、世界线、地盘事件与时间共同决定。它不是只换一段地图文案，而是同时影响**奇遇候选、NPC 行程、巡游路线、建筑服务、采集线索和战斗环境**。玩家进入或移动于同一片区域时，看到的是同一份区域天气；不能通过换坐标、换频道、重连或反复移动重新掷天气。

```text
区域气候基底 + 当前季候/时段 + 世界线异常 + 地盘事件
  -> 区域天气前线（2～4 小时）
    -> 地图可见性 / 移动叙事 / NPC 行动与建筑状态
    -> 奇遇条件与场景变体
    -> 开战时冻结为战场天气快照
```

天气设计遵循五条边界：

1. **可预报但不完全可控。** 玩家可看到当前天气、强度、预计结束时间和下一时段的模糊预报；世界线异常可打破预报，但会留下传闻与日志。
2. **有利有弊，不做纯减益。** 每种天气至少提供一个探索/剧情机会和一个可利用的战斗方向，避免玩家只想等待晴天。
3. **分区域共享，不逐格随机。** 一个天气前线覆盖一个区域或气候带；同一区域的局部地标可额外叠加“潮湿、背风、雷暴高点”等微环境标签。
4. **战斗开始即冻结。** 进入战斗时把天气、强度、微环境与版本写入战斗快照；战斗中天气变化不改变已开始的数值，防止跨回合争议与刷切换。
5. **不以罕见天气硬锁成长。** 委托和主线不能要求玩家无限等候低概率天气；所有关键步骤应有替代时间、消耗品、NPC 服务或累积进度入口。
6. **大多渐变，异象才骤变。** 常规天气按可观察的过渡阶段变化；无预兆骤变只属于高等级世界线、Boss 高潮或明确记录的区域灾害。

#### 4.4.1 天气状态、区域独立性与过渡

每个区域保存 `weather_code`、`intensity`（1～3）、`temperature_band`、`visibility_band`、`wind_band`、`started_at`、`ends_at`、`forecast_seed` 与 `cause`。展示给玩家的是可读组合，如“雾藻湿地：浓雾·微雨（预计还有 1 小时 20 分）”；业务判断使用稳定 code/tag，绝不用中文显示名。

##### 4.4.1.1 独立区域与渐变天气前线

每个区域各自抽取天气，依据自己的 `region_weather_profile`、季候、地貌、当前世界线和相邻区域的弱关联计算。相邻区域只允许影响“趋势”，不能复制结果：晨露河岸正下细雨时，砾风石滩可以是潮风；赤铁山道热浪时，岩脊山麓仍可能是山风；雷鸣断崖雷雨也不会让百纳镇同步落雷。

常规天气以状态机推进，推荐每 30 分钟为一个天气 tick、每个状态持续 2～4 个 tick：

```text
晴朗 -> 云起/起风 -> 细雨/薄雾 -> 暴雨/浓雾/强风 -> 减弱 -> 残雨/露重 -> 晴朗
飘雪 -> 风雪渐强 -> 冰晶风暴 -> 止雪 -> 冻雾/积雪 -> 飘雪或晴寒
```

普通气候转换中，至少 85% 必须走相邻状态；最多 13% 可跳过一个弱阶段（例如“云起”直接转“细雨”）；无前兆骤变的基准概率不高于 2%，且只用于地图公告、异常天象或已预告的高危地带。`weather_override` 可以打断状态机，但只接受世界线、Boss 高潮、地盘事故或 owner 确认操作；它必须写明“骤变原因”、影响区域、开始/结束时间和恢复目标天气。

这让玩家能从“风开始变重、远处云层压低、空气带着铁腥味”判断即将发生的事。预报服务显示当前阶段与下一阶段的方向，例如“风势正在增强，短时内可能转为雷雨”，而不是把每个天气都当作无缘无故的抽签。

| 区域 | 常规天气谱系 | 稀有异象（区域专属） | 与生态相连的玩法钩子 |
| --- | --- | --- | --- |
| 百纳镇 | 晴朗、微风、春雨、晨雾 | **琥珀花雨**：世界树冠洒下带微光的树脂花瓣，非真正黄金；会黏住货箱与足迹 | 商贩避雨、树脂收集、屋檐下的匿名委托、梨子喵线索 |
| 幽暗密林 | 阴翳、枝叶夜雨、地表雾、闷雷 | **萤枝夜潮**：枝端群萤在雨后同步亮起，照出被藤蔓遮住的旧路 | 迷路旅人、林间遗物、怪物迁徙、追踪/引灯支线 |
| 世界树草原环带 | 晴朗、花风、短阵雨、薄雾 | **根脉辉雾**：草根随晨雾泛光，短时显出地下根系的走向 | 草药采集、守根对话、根冠公羊的领地行为、隐藏地标 |

##### 4.4.1.2 异象天气的稀有度与叙事节奏

区域专属异象不是更高收益的全图彩票开奖。其正常出现频率建议为每区域每 5～12 个天气窗口一次，且每次都有三段式叙事：**征兆**（可在预报、NPC 行为、地标文案中察觉）-> **显现**（开启变体场景）-> **余韵**（保留现场、传闻或可收束支线）。例如“雷丝垂云”先有崖顶静电与驿站收伞，再出现云底电丝，最后只剩导雷石发热的痕迹。

真正的骤变仅用于“坠星泥雨突然压境”“Boss 改写天象”“矿脉爆裂引发铁花灰雨”等已经存在明确因果的事件。骤变发生后仍需至少保留余韵阶段，并向该区域玩家写入一条可查看的事件摘要；不能只因随机数命中就让玩家无准备地承受战斗劣势。

天气前线默认持续 2～4 小时，边界时刻由确定性种子预先生成；世界线、Boss 高潮或建筑事故只能以一条已记录的 `weather_override` 覆盖它，并明确 `cause`、范围和过期时间。地图关闭、服务器重启或定时任务遗漏后，使用最后快照与种子补算，不重新随机。

#### 4.4.2 奇遇、NPC、地盘与建筑联动

天气条件加入既有 Condition DSL：`weather_is`、`weather_intensity_gte`、`weather_tag_has`、`forecast_is`、`microclimate_is`；效果只允许创建有过期时间的天气前线或提交世界线天气覆盖请求。天气应当改变事件的入口、信息和策略，而非简单把同一事件概率翻倍。

| 天气 | 奇遇与巡游 NPC | 地盘/建筑变化 | 隐藏线索或回报 |
| --- | --- | --- | --- |
| 浓雾 | 灯使迷航、失散车队、无面者伪装、追踪难度提高 | 灯塔/驿站开放引路与避雾服务 | 雾中脚印、假灯油、隐蔽商路 |
| 细雨/暴雨 | 河岸救援、漏雨货车、雨中交易、潮位支线 | 渡口减班、屋檐商人、排水修缮 | 湿润药材、漂流货箱、潮汐证词 |
| 雷雨/强风 | 风筝匠求援、悬桥封锁、雷羽生物迁徙 | 风帆驿站暂停路线、避雷装置委托 | 导雷矿脉、断桥密道、风暴图鉴 |
| 干热/灰雨 | 矿工中暑、炉压异常、走私车队改道 | 灰炉工棚限供、临时诊所启用 | 炉渣线索、耐热材料、账册残页 |

| 月蚀暗潮/星尘雨 | 遗迹幻象、封印松动、巡游学者撤离 | 研究所封存或开启紧急研究 | 古文残片、镜像谜题、Boss 前置证据 |

重要 NPC 的行动计划必须声明天气容忍度与替代路线。例如阿岚在浓雾中优先巡灯、在雷雨中改为留守灯塔；黑市车队在强风中延误且可能转入断桥密道；研究所遭遇月蚀暗潮时会封存普通服务、开放短期调查。玩家错过巡游 NPC 后，仍可在其下一站、事故现场或建筑公告处获得合理余波。

#### 4.4.3 战斗天气快照与数值影响

天气只在室外/半开放战场生效；城镇室内、地下深层、密封建筑与已有独立环境的副本默认不继承区域天气，除非战斗模板明确声明。战斗创建时写入 `combat_environment_snapshot`，全队、敌方、Boss 和援军使用同一份快照。

| 天气环境 | 战斗标签与建议基础效果 | 策略意义 |
| --- | --- | --- |
| 晴朗/阴天 | 无通用数值修正 | 作为基准环境 |
| 微雨 | 水属性伤害 +5%；火属性伤害 -5% | 水系与火系互有取舍 |
| 暴雨 | 水属性伤害 +8%；火属性伤害 -8%；雷属性技能命中 +3% | 更强元素倾向，不能叠加多层导电伤害 |
| 浓雾 | 全体命中 -6%；首次鉴识额外显示“视野受阻” | 控制、范围技能和准备类技能更有价值 |
| 强风 | 远程/风属性技能命中 +4%；持续性地面效果持续时间 -1 回合 | 让风系有场景优势，但不改变回合顺序 |
| 雷雨 | 雷属性伤害 +8%；火属性伤害 -5%；双方首次命中率 -3% | 高风险雷系窗口，不增加随机落雷直接伤人 |
| 飘雪/冻雾 | 冰属性伤害 +6%；全体速度 -3%（最低不低于原值 85%） | 使速度与解控有意义，不能无限减速 |
| 干热/灰雨 | 火属性伤害 +6%；治疗量 -4% | 促使速战与资源安排，不削弱复活/关键保命 |
| 月蚀暗潮 | 光/暗属性伤害各 +5%；鉴识可见一条额外倾向 | 仅遗迹/世界事件模板启用，Boss 也受同规则约束 |

区域异象在战斗中使用独立的 `anomaly_tag`，并**替换**对应基础天气效果，不与其叠加；下表为首版方向，具体数值仍应在实战日志后校准。

| 区域异象 | 战斗标签与建议效果 | 设计意图 |
| --- | --- | --- |
| 琥珀花雨 | 木属性伤害 +5%；首次受到物理攻击后获得 1 回合“树脂迟滞”（速度 -2%，不可叠加） | 世界树树脂既提供生机，也会黏住行动 |
| 萤枝夜潮 | 首次鉴识额外显示一个敌方技能倾向；暗属性伤害 +4% | 提高观察价值，不凭空提高战力 |
| 根脉辉雾 | 木属性伤害 +5%；首次定身/缠绕效果持续时间 +1 回合（Boss 只显示抗性变化） | 映照地下根脉，而非直接加血量 |
| 逆鳞露雨 | 水属性伤害 +5%；闪避成功后下次水属性技能命中 +3% | 体现逆流与河兽的灵动 |
| 玻潮盐雾 | 首次受击的暴击伤害 -10%；火属性伤害 -4% | 盐膜提供轻微隔护，避免变成强防御天气 |
| 鸣岩回风 | 土属性伤害 +5%；双方范围技能命中 +3% | 断层回响使范围判断更清晰 |
| 铁花灰雨 | 火属性伤害 +6%；物理防御 -3% | 热灰灼蚀甲片，适合短促高压战 |
| 荧孢雾潮 | 木/暗属性伤害各 +4%；首次治疗量 -4% | 荧孢兼具药性与侵染性，效果克制且可对策 |
| 坠星泥雨 | 水/暗属性伤害各 +4%；全体命中 -3% | 冷泥遮蔽视野、带来星泥魔力 |
| 镜雪极光 | 冰/光属性伤害各 +4%；首次受击后显示攻击者元素 | 倒影提供信息而非额外随机伤害 |
| 雷丝垂云 | 雷属性伤害 +7%；首次雷属性技能命中 +3% | 雷云强势但有明确征兆与区域限制 |
| 蚀光微雨 | 光/暗属性伤害各 +5%；首次鉴识显示一项抗性倾向 | 服务于遗迹解谜与双属性对抗 |

同一战斗环境最多含**一个天气标签 + 一个微环境标签 + 一个世界事件标签**；同类修正不叠加，所有伤害/命中/速度修正在该层总和封顶 ±10%。Boss 不能靠天气获得额外生命倍率，也不能无视玩家承受的天气惩罚；若 Boss 有专属天气机制，必须在战斗开场和图鉴中明确说明，并仍受总封顶约束。

玩家的对策应偏向准备与选择，不要求装备随机毕业：雨披/灯油/热汤/避雷针等地图道具可抵消一次移动或感知负面；技能、职业被动和既有变异能力可提供有限环境适应；建筑提供避难、预报、路线改道和临时补给。道具只降低风险或开启替代入口，不能改写全区天气或把战斗修正变成无限增益。

#### 4.4.4 天气也受反刷取保护

- 天气前线和预报按区域实例锁定，移动不会重掷；
- 同一角色在同一天气窗口、同一地标、同一内容家族的“天气限定”掉落使用 `weather_window_source_key` 唯一结算；
- 天气只提高符合主题的未见节点权重，不增加探索暴露度、稀有池保底或世界贡献上限；
- 高价值天气事件采用场景在场实例：后到者可协助、目击或体验余波，但不能重复领发现/天气首见奖励；
- 天气覆盖、天气交替和异常的每一次发生、拒绝、结束都写入游戏事件账本，可按区域、窗口、原因和关联世界线查询。

选择文案应说明**可见代价和大致方向**，不暴露隐藏公式或全部后果。例如“将消耗一份灯油，可能获得灯使信任”“保持沉默会让这场争执自行发展”。

## 5. 宛如真人的 NPC：行动模型与独立记录

### 5.1 NPC 档案

每名重要 NPC 用以下字段定义，而非只用静态描述：

| 维度 | 示例 | 作用 |
| --- | --- | --- |
| 身份与归属 | `aran_lamplighter`、晨灯会 | 被谁认识、可参与哪些世界线 |
| 性格轴 | 谨慎 80、仁慈 65、野心 30、守密 90 | 决定同一局势下的行动倾向 |
| 目标队列 | 点燃中继灯 -> 找回弟子 -> 躲避审判 | 每次计划选择的候选动作 |
| 知识与秘密 | 知道封印裂缝位置；不知道祭司已倒戈 | 限制对话和误判，避免全知 NPC |
| 关系网 | 亲近/中立/敌对/债务/恐惧 | 影响合作、背叛、求助与传闻 |
| 资源 | 金钱、货物、伤势、护卫、证据 | 让行动有成本，避免无中生有 |
| 日程与位置 | 黎明巡灯、午后交易、暴雨时避难 | 使地图呈现合理的时间变化 |
| 行动记忆 | 最近成功、失败、玩家承诺、创伤 | 让 NPC 能记得玩家和自己的失误 |

一般路人只需共享原型和短周期生成记录；商人、任务人、势力首脑、Boss 关联者和能多次相遇的旅人必须使用独立实体。

### 5.2 行动不是每秒模拟

使用「**计划时钟**」推进：任何 NPC 的状态只在下列时机演算至 `now`：

- 玩家进入其感知区域、与其交谈或触发关联奇遇；
- 世界/区域计划任务每 5 分钟处理一小批到期行动；
- 世界事件结算、日切、天气或 Boss 状态发生改变；
- 管理员调试或回放。

每个 NPC 保存 `next_action_at` 与 `last_simulated_at`。推进时根据经过的离散时间片（最多补 24 小时，超出则压缩为摘要行动）选取行动并生成日志。这样离线 3 天不会插入数万行“走了一步”，却会得到“第三日夜间，阿岚因补给耗尽暂停巡灯”的可读结果。

### 5.3 行动决策

```text
可行动集合
  = 日程动作 ∩ 当前地点可执行 ∩ 资源足够 ∩ 世界线允许 ∩ 非冷却

行动分数
  = 目标优先级
  + 性格匹配
  + 关系/债务驱动
  + 区域危险与机会
  + 最近记忆修正
  + 有界随机（固定种子）
```

固定种子由 `npc_id + 行动时段 + 世界版本` 计算，并写入日志。它能让结果看似自然，同时保证错误回放、跨进程重试和管理员审计得到一致结论。随机只用于同分动作与受控检定；不可用于重复结算时反复掷骰。

### 5.4 行动日志例子

```json
{
  "occurredAt": "2026-09-03T20:00:00+08:00",
  "actor": "aran_lamplighter",
  "action": "escort_flame_to_relay",
  "from": "fallenstar_swamp:238,-353,0",
  "to": "fallenstar_swamp:282,-340,0",
  "intent": "dawn_relay.restore",
  "outcome": "interrupted",
  "reason": "mire_raiders_present",
  "effects": ["region.danger+1", "encounter.aran_ambush.enabled"],
  "seed": "...",
  "causedBy": ["player_echo:8421"]
}
```

玩家只能看到叙事化摘要，如“你听说灯使的火种在沉星沼泽附近熄灭”；管理员与开发工具可查看完整因果链。

### 5.5 巡游 NPC、地盘与建筑也是行动者

地图生态不只由单个 NPC 构成。新增三类可被奇遇引用的实体，使“谁住在哪里、什么地方正在发生什么”真正影响分支。

| 实体 | 定义与刷新方式 | 可产生的内容 | 示例 |
| --- | --- | --- | --- |
| 巡游 NPC（roamer） | 有路线、目的地、补给、同行者和停留窗口；可跨区域移动 | 邂逅、护送、交易、伏击、传闻、追踪 | 流动戏班、伤兵车队、迷路信使、黑市行商 |
| 常驻地盘（site） | 绑定区域/坐标的势力据点、营地、巢穴、渡口、农场或工坊 | 建设、失火、争夺、委托、商店、地盘支线 | 矿工营、退潮祭坛、沼泽避难棚、悬桥检查站 |
| 动态建筑（building） | 现有 `map_npcs`/`map_special_objects` 的可见地标投影，另有独立状态 | 升级、损坏、封锁、重建、开放新服务 | 灯塔、猎人驿站、临时诊所、遗迹研究所 |

每个 `site` 都有驻守势力、资源、治安、服务列表、建设等级、风险与关联 NPC。它可以被世界线和 NPC 行动改变，但不直接覆写 `map_special_objects` 静态种子：地图层读取 `site_state` 后叠加显示“开放、损坏、戒严、修缮中”等状态。

巡游 NPC 不能每次移动都重新生成。每个巡游团体拥有稳定的 `roamer_instance_id`、路线版本、当前路段、货物/伤势和生命周期；路线被玩家干预后，原计划中断并写出后果。未亲眼遇到车队的玩家，也可能在下一座驿站遇到其留下的货物、通缉令或目击者。

#### 首发地盘与建筑链示例

| 地点 | 正常状态 | 可变状态与关联 NPC | 支线与隐藏回报 |

| 雾藻湿地·苇影避难棚 | 伤员休整、湿地传闻 | 咕里、芦笛者、流亡者；可收容/失火/被占据 | 医疗支线、稀有药草位置、护送线路 |
| 雷鸣断崖·风帆驿站 | 商路、滑翔/风向情报 | 风筝匠、桥卫、走私客；可封桥/修桥/暗渡 | 风暴商队、桥下密道、外观与图鉴奖励 |
| 月蚀遗迹·临时研究所 | 古文解读与安全补给 | 破译员、执钥人、学者团；可开放/封存/失窃 | 禁书残页、镜像谜题、Boss 前置证据 |

建筑给出的服务必须同其状态绑定：失火的诊所不能照常卖药，戒严的检查站会新增盘查选项，重建后的驿站才出现新路线。即使建筑被破坏，基础地图移动和主线不锁死，玩家可通过替代营地、临时商人或邮件补偿继续推进。

## 6. 奇遇内容数据库：模板、实例与效果语言

### 6.1 不能把内容写死在服务层

业务服务只负责加载、校验、抽取、检定和结算；剧情、条件、选项、文本、权重、后果均存为版本化数据。每个模板以稳定英文 `snake_case` 编码，显示名和文本可单独本地化。

```text
奇遇模板 encounter_template
  -> 节点 encounter_node（开场/抉择/战斗/结算）
    -> 选项 encounter_choice
      -> 条件 condition_set
      -> 效果 effect_set
      -> 跳转 next_node / 延迟后果 consequence
```

### 6.2 条件语言（Condition DSL）

条件只允许白名单原子组合，禁止在数据库中执行任意 SQL/JS。

| 原子 | 示例 |
| --- | --- |
| 角色 | `level_gte`、`profession_is`、`has_item`、`skill_known`、`not_in_battle` |
| 位置与时间 | `region_is`、`near_position`、`weather_is`、`time_band_is` |
| 个人命运 | `flag_is`、`faction_reputation_gte`、`secret_known`、`choice_made` |
| 世界与区域 | `worldline_stage_is`、`region_tag_has`、`world_event_active` |
| NPC | `npc_state_is`、`npc_relation_gte`、`npc_action_active` |
| 频控 | `personal_cooldown_ready`、`daily_count_lt`、`first_seen` |

条件集支持 `all`、`any`、`not`；每个原子都有参数 schema 与静态校验。内容发布时应验证引用的 NPC、物品、怪物、区域、标记和下一节点都存在。

### 6.3 效果语言（Effect DSL）

| 类别 | 合法效果 | 约束 |
| --- | --- | --- |
| 玩家 | 增减命运标记、好感、阵营声望、线索、体力、普通物品 | 奖励表/每日上限/背包策略由服务层复核 |
| NPC | 改变关系、资源、伤势、知识、目标队列、下次行动 | 不能任意改静态 NPC 模板 |
| 区域 | 标签、风险/繁荣/污染等带上下限的指标 | 必须附过期时间或收束规则 |
| 世界线 | 写入有上限的回响，或提出阶段推进候选 | 不允许单个玩家直接跳过阶段 |
| 遭遇 | 开/关模板、设置个人冷却、安排延迟后果 | 延迟任务需幂等键 |
| 战斗 | 启动已配置的遭遇/援军/逃离路线 | 只能调用白名单战斗模板 |

所有 effect 先被编译为「计划」，再按固定顺序结算：**消耗与资格锁定 -> 状态修改 -> 物品/战斗 -> 日志 -> 通知**。若背包、库存或战斗启动失败，整个事务回滚或进入明确的补发队列，绝不出现扣了道具却没拿到结果。

### 6.4 节点类别

| 节点 | 用途 | 至少一个出口 |
| --- | --- | --- |
| `scene` | 描述环境、给予观察选项 | 离开/观察 |
| `choice` | 两个以上有差异的立场或资源决策 | 选择/放弃 |
| `check` | 技能、属性、物品、队伍条件检定 | 成功/失败 |
| `combat` | 接入现有战斗遭遇 | 胜利/失败/撤退 |
| `trade` | 限量交换或委托交付 | 成功/不足/取消 |
| `wait` | 延迟后果或等待 NPC 行动 | 到期/被中断 |
| `resolution` | 发放结果、记录回响、收束链条 | 返回地图/衔接后续 |

每个节点都必须有一个无资源消耗的退出或失败出口；重要剧情不能因为背包满、属性不足或遇敌失败而永久死锁。

## 7. 世界线、区域事件与 Boss 激活

### 7.1 世界线结构

世界线采用 0～4 阶段，而不是二元开关：

| 阶段 | 名称 | 作用 |
| --- | --- | --- |
| 0 | 潜流 | 仅传闻、零星异常、NPC 自主铺垫 |
| 1 | 显现 | 区域出现可调查的事件与普通支线 |
| 2 | 危机 | 区域态势变化、精英变体、势力公开对立 |
| 3 | 高潮 | 世界事件窗口、Boss 或大型协作目标激活 |
| 4 | 余波 | 按结果生成数日/数周的地图后果与替代任务 |

每次阶段变化写入 `world_event_log` 并创建不可变的 `world_event_instance`。阶段不可因重启、重复消息或单次重试倒退；策划若要修正，必须以新事件记录「补丁/回滚原因」。

### 7.2 个人与全局的交织

世界推进以「回响」而非直接投票决定。玩家完成有意义的奇遇、交付物资、救援、调查、击败变体精英，会向一个或多个立场写入有上限的贡献。系统按周期汇总贡献、在线人口和最低参与数来推进世界阶段。

```text
个人选择：救灯使 / 交出火种 / 带走火种
  -> 个人：信任、嫌疑、债务、后续 NPC 入口不同
  -> 区域：安全路线 / 掠夺者势力 / 浓雾之一得到修正
  -> 世界：黎明中继线的“守灯”或“夺火”回响 +1
  -> 世界阶段：达到阈值后，出现不同的 Boss 前置与余波
```

无论全服走向哪一条结果，玩家都可体验另一立场的残响、档案或追忆任务；首杀、图鉴、基础掉落与关键成长不依赖「恰好站对全服多数」。差异主要体现在 Boss 词条、援军、地图路径、商店、外观、称号和后续故事。

### 7.3 Boss 设计规则

1. 世界线只能**激活或改变 Boss 前置场景**，Boss 本体继续由现有刷新/战斗体系生成与结算。
2. Boss 有 `base` 与 2～3 个互斥的 `world_variant`。变体改变战斗机制、环境词条、援军和叙事，不把数值翻倍。
3. 同一窗口可用全服状态决定默认变体；玩家个人命运可提供一次性援助、额外对话或替代撤退路径，不能让两人看到互相矛盾的同一实体状态。
4. Boss 激活写入唯一世界实例键，例如 `dawn_relay:cycle_2026w36:climax`；重复触发只返回已激活状态。
5. Boss 失败、逃离、首通与冷却应进入世界事件日志；普通玩家奖励仍走既有个人战斗事务。

### 7.4 首发八条世界线

| 世界线 | 主区域 | 冲突与分歧 | 高潮 Boss/事件 |
| --- | --- | --- | --- |
| `dawn_relay` | 沉星沼泽、月蚀遗迹 | 守住中继灯 / 把火种交给无面者 / 寻求第三种修复 | 月蚀守望者的光暗变体 |
| `iron_debt` | 岩脊山麓、赤铁山道 | 矿工自救 / 监工镇压 / 揭露走私账本 | 熔炉监工·瓦尔克的过载或失控变体 |
| `marsh_brood` | 雾藻湿地 | 焚毁孢巢 / 引导迁徙 / 利用药性 | 三首雾沼蛇母的巢群变体 |
| `root_crown` | 世界树草原环带 | 守根、采伐、失控复苏 | 根冠公羊的守护或狂生变体 |
| `river_oath` | 晨露河岸、砾风石滩 | 河灯渔民、退潮祭徒、潮痕亡灵 | 晨潮鳄王/碎潮巨蟹的潮位变体 |
| `frost_exile` | 霜冠高原 | 收留流亡者 / 封锁疫源 / 追查伪证 | 白角霜王的护卫或孤王变体 |
| `storm_verdict` | 雷鸣断崖 | 悬桥裁决、商路通行、风筝匠密信 | 风暴巨隼·阿斯克的审判风暴 |
| `eclipse_archive` | 月蚀遗迹 | 保管禁书、焚毁证据、公开历史 | 遗迹执钥人与塞勒斯的终局关联 |

同一 NPC 可以串联两条世界线，但首发每条线只能有一个主问题，避免玩家无法理解因果。

## 8. 首发内容规模与内容生产规范

### 8.1 内容配额

| 内容类型 | 每区域 | 首发总量 | 说明 |
| --- | ---:| ---:| --- |
| 风景/传闻微事件 | 10 | 120 | 30～90 秒，强化区域气质，可无战斗 |
| 普通选择奇遇 | 12 | 144 | 2～4 个选项，至少一个后续标记 |
| NPC 动态相遇 | 6 | 72 | 由行动计划出现，带独立 NPC 行为 |
| 巡游 NPC 路线 | 2 | 24 | 每条至少有抵达、延误、遇袭、交易、余波五类节点 |
| 地盘/建筑事件 | 3 | 36 | 每处具备常态、危机、修复/变更三个以上状态 |
| 链式节点 | 8 | 96 | 2～5 节，包含延迟后果或跨区回访 |
| 稀有反转节点 | 3 | 36 | 需要命运/世界态势，低频高记忆点 |
| 区域事件 | 2 | 24 | 周期性、多人可贡献，非强制组队 |
| 世界线关键节点 | 5～7 | 48 | 8 条线分配到相关区域 |

模板可有多个文本变体，但不同变体不应只换名字；至少改变观察信息、检定路径、奖励资源或后续关系之一。

隐藏奖励遵循“三钥匙”原则：玩家至少满足**地点/时机**、**个人经历或技能**、**一次有代价的选择或行动**中的两项，才进入奖励候选；第三项决定品质或变体。隐藏奖励由 `reward_source_key` 唯一约束，首见奖励不可被换地图、换频道、组队解散或叫人重复获得。重复遇到同一故事时应转化为新情报、地区代币、NPC 态度、收藏文本或可协作进度，而非重复发高价值物品。

### 8.2 单条奇遇的制作卡

每个奇遇在入库前必须填完：

- `code`、版本、主题区域、建议等级、时段/天气；
- 开场的一句话钩子与可见风险；
- 触发条件、个人冷却、世界/区域条件；
- 所有节点、选项、检定、成功/失败/离开出口；
- 可见即时结果、隐藏延迟结果、收束/替代入口；
- 写入的命运标记、NPC 记忆、区域指标、世界回响；
- 奖励池、每日/周期上限、满背包处理；
- 所有内容引用、测试种子与验收断言。

### 8.3 避免伪分支

分支至少满足一个条件才算真实分支：后续可遇 NPC 不同、可见信息不同、解锁/关闭不同选项、区域态势不同、Boss 前置援军不同、获得的资源/代价不同。只把同一结局换一句对话不计入分支数量。

## 9. 代表性奇遇链：沉星沼泽「熄灯者的火种」

这条链展示同一个 NPC 能独立行动，玩家迟到也仍会看到合理后果。

### 9.1 起点：火光在雾中摇晃

触发：沉星沼泽夜晚，`dawn_relay` 阶段 0/1，阿岚的行动为 `escort_flame_to_relay` 或其结果在 30 分钟内可见。

| 选择 | 即时结果 | 写入后果 |
| --- | --- | --- |
| 挑灯同行 | 消耗灯油，进入护送/伏击 | 阿岚信任、区域安全、守灯回响增加 |
| 隐于芦苇观察 | 获得掠夺者口令或阿岚秘密 | 风险上升；可在后续伪装/揭发 |
| 以报酬为条件帮忙 | 交易成功则拿到地图线索；失败可能被误解 | 债务或嫌疑；不等于坏结局 |
| 带走火种 | 技能检定，成功获得危险物件 | 无面者关注、阿岚伤势/计划改变 |
| 离开 | 不结算奖励 | NPC 继续按行动模型推进 |

### 9.2 未介入时的独立行动

- 阿岚资源足够、区域风险低：成功点亮中继，玩家以后见到他时可拿到「迟来的谢意」支线；
- 被掠夺者拦截：生成 `aran_ambush`，之后玩家可能发现熄灭灯塔和遗落日志；
- 火种耗尽：阿岚返回村落，世界线的守灯回响减少，但出现“追查假灯油”的非战斗调查支线。

玩家并没有“错过内容”，而是进入一个与当前事实一致的节点。

### 9.3 延迟回响

两小时后或下一次进入月蚀遗迹时，根据个人标记和世界阶段触发：

| 个人经历 | 后续相遇 | 世界线意义 |
| --- | --- | --- |
| 曾护送阿岚 | 阿岚提供一条安全灯路、Boss 首回合可请求一次照明援助 | 守灯倾向 |
| 曾观察并取得口令 | 可潜入无面者营地，获得更完整证词 | 调查倾向 |
| 曾带走火种 | 被双方追问；可归还、利用或销毁 | 夺火/第三路倾向 |
| 从未相遇 | 可调查残火与日志，以较慢方式追上世界线 | 中立补偿入口 |

## 10. 数据模型与迁移建议

建议从 `010_dynamic_encounters_worldlines.sql` 起按单文件、可重复执行的方式新增；静态种子仍由 `bootstrap.ts` 的幂等 upsert 管理。字段类型可按现有迁移风格微调。

### 10.1 世界、区域与势力

| 表 | 核心字段 | 约束/索引 |
| --- | --- | --- |
| `worldlines` | `code`、`name`、`active_version`、`config_json` | `code` 唯一 |
| `worldline_states` | `worldline_id`、`stage`、`cycle_key`、`state_json`、`updated_at` | 每世界线一行；版本乐观锁 |
| `world_event_instances` | `worldline_id`、`cycle_key`、`stage`、`status`、`starts_at`、`ends_at` | `(worldline_id,cycle_key,stage)` 唯一 |
| `region_dynamic_states` | `region_id`、`danger`、`prosperity`、`corruption`、`tags_json`、`expires_at` | `region_id` 唯一 |
| `region_weather_profiles` | `region_id`、`climate_code`、权重/季候配置、微环境配置、`version` | 静态气候内容；每区域唯一 |
| `weather_transition_rules` | `climate_code`、`from_weather`、`to_weather`、权重、最短/最长 tick、征兆/余韵标签 | 只允许气候图中声明的常规渐变转换 |
| `region_weather_states` | `region_id`、`weather_code`、强度、天气标签、`started_at`、`ends_at`、`forecast_seed`、`cause`、`revision` | 区域当前天气快照；每区域唯一 |
| `weather_overrides` | `region_id`、`weather_code`、强度、来源类型/ID、优先级、`starts_at`、`ends_at`、`status` | 世界线/Boss/事故临时覆盖；有效窗口唯一性由服务层校验 |
| `weather_forecasts` | `region_id`、预测时段、`weather_code`、可信度、`forecast_seed` | 给玩家和 NPC 的可预报投影，不替代真实状态 |
| `weather_transition_log` | `region_id`、前后天气/阶段、`transition_kind`、`cause`、`correlation_id`、`occurred_at` | 每次渐变、骤变、覆盖、恢复都可按区域回放 |
| `factions` | `code`、`name`、`profile_json` | `code` 唯一 |
| `faction_relations` | `from_faction_id`、`to_faction_id`、`attitude`、`flags_json` | 有序复合唯一键 |
| `world_contributions` | `event_instance_id`、`character_id`、`side_code`、`score`、`source_key` | `(event_instance_id,character_id,source_key)` 唯一 |

### 10.2 NPC 与行动日志

| 表 | 核心字段 | 说明 |
| --- | --- | --- |
| `dynamic_npc_profiles` | `npc_code`、`faction_id`、`personality_json`、`goals_json`、`schedule_json` | 与 `map_npcs.code` 或未来流动 NPC code 关联 |
| `dynamic_npc_states` | `npc_id`、当前位置、`resources_json`、`knowledge_json`、`memory_json`、`status`、`last_simulated_at`、`next_action_at`、`revision` | 运行时快照；锁定/乐观更新 |
| `npc_action_plans` | `npc_id`、`action_code`、`intent_code`、`due_at`、`payload_json`、`status` | 待执行计划；`due_at,status` 索引 |
| `npc_action_log` | `id`、`npc_id`、`plan_id`、`action_code`、`outcome`、`causation_id`、`payload_json`、`occurred_at` | `plan_id` 唯一避免重复结算；按 NPC/时间索引 |
| `npc_relationships` | `npc_id`、目标类别/ID、`relation_type`、`value`、`flags_json` | NPC->NPC、NPC->势力、NPC->角色统一表达 |
| `roamer_instances` | `code`、路线版本、当前位置、路段、货物/同行者、`status`、`next_action_at` | 巡游团体的稳定身份；不随每次相遇重生 |
| `world_sites` | `code`、`region_id`、坐标、`site_type`、`owner_faction_id`、静态配置 | 地盘/建筑的内容锚点；`code` 唯一 |
| `world_site_states` | `site_id`、`state_code`、建设/治安/库存、服务/标签、`revision` | 运行时快照；与地图静态物体分离 |
| `site_incidents` | `site_id`、`incident_code`、`status`、`starts_at`、`ends_at`、因果 ID | 火灾、封锁、修缮、争夺等可追溯事件 |

`dynamic_npc_states` 不保存完整历史；`npc_action_log` 才是事实来源。若一名 NPC 永久死亡、失踪或剧情转职，不删除记录，只将状态置为 `retired`/`dead` 并写原因事件。

### 10.3 奇遇与玩家命运

| 表 | 核心字段 | 关键约束 |
| --- | --- | --- |
| `encounter_templates` | `code`、`version`、`scope`、`region_id`、`weight`、`config_json`、`enabled` | `(code,version)` 唯一，启用版本唯一 |
| `encounter_nodes` | `template_id`、`node_code`、`node_type`、`content_json` | `(template_id,node_code)` 唯一 |
| `encounter_choices` | `node_id`、`choice_code`、`conditions_json`、`effects_json`、`next_node_code` | `(node_id,choice_code)` 唯一 |
| `encounter_instances` | `id`、`template_id`、`character_id`、`party_id`、`node_code`、`seed`、`status`、`expires_at`、`revision` | `(character_id,status)` 的活跃约束由服务层保证 |
| `encounter_decisions` | `instance_id`、`node_code`、`choice_code`、`idempotency_key`、`result_json` | `(instance_id,node_code)` 与 `idempotency_key` 唯一 |
| `player_destiny_flags` | `character_id`、`flag_code`、`value_json`、`source_key`、`expires_at` | `(character_id,flag_code,source_key)` 唯一 |

| `player_exploration_budgets` | `character_id`、当前暴露度、窗口计数、最近格簇、`updated_at` | 每角色一行；事务锁定后增减 |
| `encounter_presence_instances` | `entity_type/id`、区域/坐标、`starts_at`、`ends_at`、容量、`status` | NPC、车队、建筑事故的可见场景窗口 |

| `weather_reward_claims` | `character_id`、区域、天气窗口、奖励来源、`claimed_at` | `(character_id,weather_window_source_key)` 唯一，防天气刷取 |

`player_events` 继续写入精简摘要，例如 `encounter.dawn_relay.choice`、`worldline.dawn_relay.contributed`；详情存上表 JSON 和世界/NPC 日志中，避免玩家事件表变成所有模拟动作的垃圾场。

### 10.4 因果链与可追溯性

所有可改变状态的记录都带以下关联字段或 JSON 字段：

```text
event_id        本记录自身 ID
causation_id    直接导致它的事件/决定 ID
correlation_id  一条完整奇遇、世界事件或战斗结算链的 ID
source_key      幂等来源，例如 encounter:1842:node:escort
content_version 当时使用的模板版本
```

这样可以从 Boss 变体倒查到世界事件、区域态势、NPC 行动和玩家决定；也能在内容修复后只补偿受影响的一批实例。

### 10.5 全量游戏事件账本

“所有事件有记录”不能仅依赖应用日志或玩家历史。新增不可变的 `game_event_ledger` 作为业务账本：**每一项尝试、状态变化、奖励、拒绝、错误、管理员操作和定时任务结果都写一条标准化事件**。`player_events` 继续只保存适合玩家查看的摘要。

| 字段 | 用途 |
| --- | --- |
| `id`、`occurred_at`、`event_type`、`outcome` | 唯一事件、发生时刻、分类与成功/拒绝/失败状态 |
| `actor_type/id`、`target_type/id` | 角色、NPC、势力、地盘、世界线、管理员等主体 |
| `correlation_id`、`causation_id`、`source_key`、`request_id` | 一条因果链、幂等来源与消息/任务追踪 |
| `content_code/version`、`seed` | 当时使用的模板版本与可重放随机来源 |
| `before_hash`、`after_hash`、`payload_json` | 受影响状态摘要与最小必要业务载荷 |
| `risk_flags`、`operator_id`、`retention_class` | 风险审查、管理员操作与归档策略 |

账本记录与状态更新放在同一数据库事务中；提交后通过 outbox 发送公告、邮件或异步分析，避免“已经发公告但事务回滚”。高频无价值移动可按时间分桶记录为 `movement.sampled`，但**每一次被用于抽取、奖励、贡献、拒绝或异常判定的移动都必须单独可查**。账本不存完整聊天文本、密码、令牌或原始敏感设备信息；管理员查询只显示权限允许的最小字段。

## 11. 结算、并发与失败安全

### 11.1 一次选择的事务流程

```text
1. 解析 route 参数，读取角色并校验注册、位置、非战斗、活跃奇遇。
2. 开启事务，SELECT ... FOR UPDATE 锁定 encounter_instance 与角色关键状态。
3. 校验 instance 版本、当前节点、选择存在、条件、冷却、物品与容量。
4. 用实例保存的 seed 执行一次确定性检定，编译效果计划。
5. 写入 encounter_decision（idempotency_key 唯一）。
6. 按既定顺序修改玩家/NPC/区域/回响；安排延迟后果。
7. 写入 player_events 摘要、npc_action_log/world_event_log 因果事件。
8. 提交事务；提交后再发送消息、启动异步通知或外部展示。
```

同一按钮连点、网络重试或机器人重复消费都因 `idempotency_key` 返回第一次的结果。消息发送失败不回滚已提交的游戏结果；应记录发送失败并允许玩家用 `/奇遇记录` 重看结果。

### 11.2 锁策略

- 一次玩家选择只锁自己的角色、当前奇遇、必要背包行和被影响的单个 NPC 状态；
- 世界线阶段推进使用 `worldline_states.revision` 乐观锁，失败后重读并重新判断，不能长时间锁全局行；
- 定时任务按 `FOR UPDATE SKIP LOCKED`（数据库版本支持时）领取有限数量到期计划；不支持时用状态更新抢占；
- 跨多名玩家的共同目标只写个人贡献，聚合器异步合算，不在单次选择中锁所有参与者；
- 一次事务内的锁顺序固定为：世界线 -> 区域 -> NPC -> 角色 -> 背包/库存 -> 奇遇实例。

### 11.3 数值与经济护栏

- 命运标记、区域指标、阵营声望和世界回响都有范围、衰减、每日/周期上限；
- 世界贡献按角色、模板、日和事件窗口去重，不按重复点击累积；
- 随机奖励公开奖池类别和上限，不将 Boss 核心、唯一任务物、装备实例塞进普通奇遇；
- 满背包按项目现有安全策略：拒绝且不消耗、邮件补发，或进入待领取箱；必须只选一种并全局一致；
- 重要分支有「降级收束」：稀有 NPC 死亡/离场后，档案、继承人或遗物提供必要线索与功能。

### 11.4 反串通与多角色滥用：限制收益，不封杀社交

玩家互相通知巡游 NPC、共同守建筑、组队护送是系统想要的行为；要防的是“一个人发现 -> 多个角色轮流点击 -> 反复刷新/重复领稀有奖励/刷世界贡献”。因此不以“多人同场”直接判定违规，而以**来源唯一性、有效参与、关联风险和收益递减**四层收敛。

| 场景 | 允许的社交体验 | 结算限制 |
| --- | --- | --- |
| 一人发现 NPC 后叫朋友赶来 | 朋友可目击、获得各自的对话和后续个人标记 | 同一场景的发现奖励、稀有掉落、世界贡献按角色/来源唯一 |
| 多人护送/建设/讨伐 | 每人完成不同阶段可共同推进地盘或世界线 | 需达到最低有效行动；同一来源仅一次贡献，重复仅提供观战/普通回报 |
| 同一队伍反复进出场景 | 可继续剧情、修正失败或协作战斗 | 队伍场景版本固定；不能离队重建同一首见实例 |
| 新账号/高度同步角色批量参与 | 不阻止正常体验 | 资源型奖励和世界贡献进入保守权重，保留故事与基础进度 |
| 可疑脚本折返或精确轮转 | 仍允许地图移动 | 稀有抽取与奖励降为零/冷却，写风险账本，不即时误封 |

**有效参与判定**不只看“点过按钮”。护送至少要求完成路线中的移动/战斗/物资之一；建设要求交付、采集、修理或防守中的实际贡献；调查要求不同线索或检定结果。所有贡献使用不可伪造的 `source_key`，例如 `presence:721:repair_stage_2:character:88`。

系统可产生一个仅供风控使用的 `risk_score`，信号包括：极短周期往返、重复路径熵过低、账号间同步操作、反复创建/解散队伍、同一来源的多次失败重试、现有设备服务给出的关联风险。**同设备、同 IP、同群聊或现实好友绝不能单独作为处罚证据**；它们最多用于降低高价值结算权重、触发人工复核或要求更高的有效参与度。玩家界面不显示风险分与具体信号，避免反向规避；管理员面板显示证据摘要、时间线和人工处置入口。

风险处置按软到硬分级：`observe` 仅记录 -> `throttle` 暂停稀有抽取 -> `withhold` 暂存可疑资源奖励并保留申诉/复核 -> 人工确认后才进行追回或处罚。任何自动限制都不阻断主线、基础移动、普通对话和已经开始的战斗。

## 12. 用户界面、命令与消息规范

新增入口应沿用当前 `Format`、`useEvent/useRoute/useMessage`、按键命令和 `src/index.ts` 路由注册方式。一个响应文件只做展示和参数收集，所有规则进入 service。

| 入口 | 用途 | 显示原则 |
| --- | --- | --- |
| `/探索` | 现有入口补充奇遇抽取 | 一次只出现一个活跃情境，避免信息轰炸 |
| `/奇遇` | 查看/继续当前奇遇 | 显示场景、已知风险、2～5 个真实可选项 |
| `/奇遇记录` | 查看最近已结算和错过的后果摘要 | 只显示玩家有资格知道的内容 |
| `/传闻` | 查看地区传闻与世界事件 | 用模糊进度条/叙事，不公开精确全服阈值 |
| `/世界` | 查看活跃世界线、区域态势、下一步方向 | 不强制指挥玩家站队 |

按钮示例：`/奇遇 1842 观察`。服务层不能仅凭实例 ID 结算，必须验证实例归属、版本、节点、过期时间、角色当前位置与所有条件。

### 12.1 叙事反馈层次

一次选择之后按三段显示：

1. **立即发生**：你做了什么、消耗/获得了什么；
2. **可感知影响**：阿岚对你的态度、沼泽的雾是否变浓；
3. **未解后果**：以传闻、未读线索或“日后可能再遇到”保留悬念。

不显示“世界回响 +1”“隐藏条件 2/5”等后台术语。进度条可用“微弱 / 清晰 / 强烈”表达，数值仅在管理员/测试模式可见。

### 12.2 管理面板：世界线、实体与账本查询

在现有 `/管理` 面板、`requireAdministrator` 鉴权和 `recordAdminOperation` 审计基础上增加“世界生态”入口。默认所有页面只读；影响世界状态的操作必须是 owner 权限、二次确认、明确作用范围，并额外写入管理操作与游戏事件账本。

| 管理入口 | 查询内容 | 操作权限 |
| --- | --- | --- |
| `/世界管理` | 活跃世界线、阶段、周期、贡献分布、下一次结算、Boss 前置 | 管理员只读 |
| `/世界线详情 <code>` | 阶段历史、阈值、分支比例、关联区域/NPC/地盘/场景、因果链 | 管理员只读 |
| `/区域态势 <地图代号>` | 风险/繁荣/污染、标签、活跃建筑事故、巡游路线与场景在场实例 | 管理员只读 |
| `/天气管理` | 全区域天气前线、预报、覆盖来源、临近切换、天气任务健康状态 | 管理员只读 |
| `/天气详情 <地图代号>` | 当前/未来天气、气候配置版本、关联奇遇/NPC/建筑、战斗修正与账本链 | 管理员只读 |
| `/生态NPC <code>` | 当前坐标、计划、资源、最近行动、关系、被谁中断 | 管理员只读 |
| `/事件账本` | 最近账本、失败/拒绝/异常比例、延迟任务积压 | 管理员只读 |
| `/事件追溯 <关联ID>` | 从玩家选择到 NPC 行动、区域变化、Boss 变体的完整时间线 | 管理员只读 |
| `/异常事件` | 风控标记、重复结算尝试、冻结奖励、卡住计划 | 管理员只读；可分页筛选 |
| `/世界线操作 <暂停|恢复>` | 临时暂停/恢复一个世界线的自动推进 | owner，二次确认 |
| `/世界线修复 <事件ID>` | 仅执行预定义补偿/重放计划，不允许手改 JSON | owner，二次确认与原因必填 |
| `/天气覆盖预览 <地图代号> <天气> <时长>` | 模拟覆盖将影响的 NPC、场景、建筑和战斗模板 | owner，仅读预览 |
| `/确认天气覆盖 <预览ID>` | 执行有明确过期时间的事故/活动天气覆盖 | owner，二次确认与原因必填 |

`/管理` 的“世界生态”按钮应进入总览，而不是把全部查询塞到首页。总览显示：每条线的阶段与健康色、最近 10 条重要事件、卡住的延迟后果数量、异常触发率、活跃巡游 NPC、损坏/封锁建筑、即将到期的场景窗口，以及天气前线/覆盖异常。点击后再以分页和筛选查看详情，避免消息超长。

账本筛选至少支持：时间范围、事件类型、结果、角色/NPC/地盘/世界线 code、`correlation_id`、风险等级和内容版本。查询必须分页、限定时间范围与最大返回条数；对玩家关联/设备风险信息只开放给具备审计权限的管理员。管理面板的“重放”永远是**模拟预览**：展示将修改的状态和将补/扣的记录；正式执行另走 owner 确认命令，不能让阅读页面产生写入。

2. 增加探索暴露度、格簇去重、触发尝试和来源唯一键；先以只记录模式观察一周，再启用收益限制；
3. 先实现沉星沼泽“浓雾/微雨”两种前线、地图预报、战斗快照与天气账本；
4. 在沉星沼泽实现「熄灯者的火种」一条链，包含观察/护送/离开、多人目击入口和一次天气相关的延迟后果；
5. 让 `/探索`、`/奇遇`、`/奇遇记录`、`/天气` 可完成闭环；
6. 接入现有 `player_events` 摘要与不可变游戏事件账本；
7. 完成幂等、背包满、过期、重复点击、战斗中调用、折返刷取、天气切换测试。

### 阶段 B：NPC 独立行动与区域态势

1. 落地 6 名重要 NPC、2 个巡游团体、3 个常驻地盘/建筑的档案、状态与行动日志；
2. 实现懒推进与每 5 分钟分片任务，并用框架托管定时任务补算到期天气；先只影响传闻、位置、建筑服务和奇遇可见性；
3. 引入 3 个区域指标和过期标签，制作 24 条 NPC 行动模板；
4. 加入“世界生态”管理员只读面板、事件账本和异常筛选，验证因果链与内容种子。

### 阶段 C：世界线与 Boss 变体

1. 实现一条 `dawn_relay` 世界线的 0～4 阶段、贡献聚合、周期窗口和余波；
2. 接入月蚀守望者一个受控 Boss 前置变体；
3. 提供迟到补偿、另一立场残响和关键功能的替代入口；
4. 压测并发贡献、世界阶段乐观锁和重启恢复。

### 阶段 D：全图内容扩容

按区域成组上线，每次至少包含：2 名重要 NPC、12 条普通奇遇、1 条链、1 个区域事件、1 个世界线连接点和完整测试卡。先补齐 4 个区域，再扩展到全图，禁止只有表格数量没有可玩因果。

## 15. 验收标准与测试矩阵

### 15.1 必须通过

- 同一个奇遇选择连点、重连、消息重投时，只结算一次；
- 玩家不能通过篡改命令跨地图、跨角色、战斗中或过期后结算奇遇；
- NPC 在玩家未出现时能从行动计划自然推进，重启后不会重复推进同一计划；
- 每条重要 NPC 行动可从日志回溯其条件、固定随机种子和因果来源；
- 任意世界阶段变化都有唯一事件实例、阈值来源、聚合记录和可读公告；
- 单玩家不能重复刷贡献推进全服；低人口与新玩家仍可等比例推进或在周期后得到保底发展；
- 同一角色在两格之间高频折返、换频道、断线重连或重复提交移动，不会增加稀有抽取次数、隐藏掉落或世界贡献；
- 多名玩家被通知到同一个 NPC 场景时，可各自体验分支，但发现奖励、稀有掉落和同一来源贡献不会被复制；
- 巡游 NPC、地盘与建筑的状态变化会影响地图标记、可用服务、后续事件与日志，且静态地图种子不被覆盖；
- 同一区域同一时间窗口的玩家读取到一致天气；重启、任务延迟与地图切换不会重掷天气；
- 相邻区域可共享趋势但能拥有不同天气；天气状态机只能走允许的常规渐变，除非日志中存在世界线/Boss/事故的骤变原因；
- 每场室外战斗创建且只创建一份环境快照；天气变化、重连和并发操作均不改变进行中战斗；
- 天气限定内容不能通过反复移动、切换场景或多人轮流互动重复领取；所有天气覆盖均有原因、过期与账本记录；
- Boss 激活不会生成重复核心实体，不影响已开战实例，也不吞掉既有个人奖励；
- NPC 离场、死亡、阵营敌对、世界线失败后，主线功能和关键线索仍有替代入口；
- 动态状态写入失败时事务完整回滚或进入一次性补偿任务，不能产生半结算；
- 全部新增文本、模板引用、code、条件和效果在发布前通过静态校验。

### 15.2 重点场景

| 场景 | 预期 |
| --- | --- |
| 两次并发点击“带走火种” | 一次成功；另一次返回已结算，不重复发物/改状态 |
| NPC 行动计划被玩家介入后再由定时任务领取 | 计划被中断或完成；定时任务不再重复结算 |
| 玩家离开 72 小时后回来 | 只生成压缩的、合理的 NPC 后果与当前可玩节点 |
| 世界阶段在两台实例/两次任务同时聚合 | 只创建一个阶段实例，另一方重读后退出 |
| 背包满且选择会给普通奖励 | 依既定策略安全拒绝/补发，命运标记与消耗保持一致 |
| 全服走守灯，玩家曾夺火 | 玩家可体验被追问与赎回，不会被永久锁在无内容分支 |
| 一名玩家在同一格簇来回移动 100 次 | 触发尝试全有记录，但完整抽取/稀有池/贡献不超过窗口上限 |
| 首位发现者在群里喊 20 人赶到巡游商队 | 每人可获得目击或协助入口；首见货物、隐藏奖励和同来源贡献最多各一次 |
| 同一人控制关联高风险角色轮流护送 | 保留故事与基础进度；资源收益降级/暂存并产生可复核风险时间线 |
| 灯塔被烧毁后查看地图、进入建筑、追查事件 | 地图显示损坏，服务切换为救援/修缮，账本能追到触发者与行动计划 |
| 暴雨结束时两支队伍正在河岸战斗 | 两场战斗继续使用创建时的暴雨快照；新战斗使用更新后的天气 |
| 晨露河岸下细雨、砾风石滩有潮风 | 两区域显示不同状态；两者可共享“湿润沿海”趋势，但不会被强制同步 |
| 晴朗的雷鸣断崖转为雷丝垂云 | 先出现静电征兆与预报，再进入异象；若骤变，账本必须关联 Boss/世界线/事故原因 |
| 玩家在浓雾天气中反复进出灯塔地标 | 可继续看见环境与余波，但天气限定首见奖励和贡献只结算一次 |
| 世界线触发月蚀暗潮 | 预报被标记为异常，关联研究所/NPC/奇遇变化可追溯，结束后恢复气候前线 |
| owner 提交天气覆盖 | 先看到影响预览；确认后写覆盖、账本与管理审计；到期自动撤销 |
| 管理员按关联 ID 追溯 Boss 变体 | 可从 Boss 实例回查世界阶段、贡献聚合、地盘事件、NPC 行动和玩家选择 |
| Boss 已被队伍挑战时世界窗口结束 | 当前战斗按创建时快照结算，不中途切换变体 |
| 内容模板修订到新版本 | 已开始实例固定旧版本；新实例用新版本；历史可回放 |

## 16. 性能、运营与内容安全

- 每次探索最多评估固定数量（例如 40 条）已按区域/阶段预筛选的候选，不扫描全库 JSON；
- 天气读取走区域快照；只有前线边界、世界线覆盖或管理员确认时才更新，正常移动不得触发天气全表计算；
- 移动格簇、探索预算与模板冷却走小表/缓存化快照，账本只追加不参与高频抽取判断；
- 用关系表和生成列/冗余索引存高频筛选键（区域、世界线、阶段、启用、时间段），JSON 只存低频内容；
- 到期计划任务分批处理并有每轮上限；失败指数退避、记录错误，不阻塞整轮；
- `npc_action_log` 保留完整摘要，低价值细节可按月归档；世界、奖励和玩家决定不做无审计删除；
- `game_event_ledger` 按月分区或归档表管理，线上查询默认限制 31 天与 100 条；跨期审计走异步导出，不拖慢游戏指令；
- 管理后台只读展示世界阶段、活跃计划、卡住的延迟后果、内容校验错误和异常重复率；人工修复必须写审计事件；
- 不将玩家真实聊天正文、群名或敏感平台字段写入奇遇/NPC 日志；只保留角色 ID、频道范围（必要时哈希）和业务结果；
- 概率、冷却、贡献上限、Boss 变体规则应在帮助页说明类别与边界，不能把随机奖励伪装为必得。

## 17. 明确不做的内容

- 不进行无边界的 AI 自由生成剧情；所有可结算内容必须来自审核过的模板与白名单效果；
- 不以真实时间每秒模拟数百 NPC，也不将 NPC 行动全部推送打扰玩家；
- 不让世界线多数派永久删除少数派内容、关键 Boss 或基础成长；
- 不把世界事件变成必须全天在线、必须组队、必须付费才可参与的活动；
- 不让命运标记悄悄永久降低角色数值或强制其参与 PvP；
- 不用动态奇遇绕开现有背包、战斗、掉落、任务和权限校验；
- 不把模板脚本执行权交给数据库文本或普通管理员输入。

## 18. 上线后的衡量指标

| 指标 | 观察目的 |
| --- | --- |
| 奇遇看到率、选择率、完成率、主动离开率 | 判断触发频率和选项是否有意义 |
| 有效探索率、折返拒绝率、触发预算耗尽率 | 校准反刷取门槛，避免误伤正常移动 |
| 天气覆盖率、天气限定事件完成率、预报命中率 | 校准天气存在感、可理解性与异常天气频度 |
| 48 小时内二次相遇率 | 判断延迟后果是否真正被玩家感知 |
| 分支占比与收束率 | 防止某条“最优解”吞没全部内容 |
| NPC 行动中断/重试率 | 判断计划与模拟稳定性 |
| 世界线贡献的角色分布 | 防止少量玩家刷爆全服进度 |
| Boss 变体参与率与战斗失败率 | 检查机制差异是否公平 |
| 奖励/回响幂等冲突数 | 监控并发和重复消费问题 |
| 同场景参与者数、有效贡献比例、收益降级率 | 判断社交协作是否健康，识别串通式刷取 |
| 账本写入延迟、计划积压、查询超时 | 确保审计不拖慢游戏主流程 |
| 模板静态校验失败、无出口节点、死链数 | 内容发布质量门槛 |

## 19. 实施前检查清单

1. 确认现有 MySQL 版本是否支持所选的 `SKIP LOCKED`；若不支持，采用状态抢占方案；
2. 盘点 `player_events`、背包满、邮件补偿、任务与 Boss 刷新的既有事务边界，避免重复实现；
3. 先建立内容 schema 校验器与测试种子，再录入首条故事链；
4. 先上线 A 阶段并观察真实选择数据，再调整世界贡献阈值，不预先拍死全服数值；
5. 每次新增世界线都补齐余波、替代入口、Boss 规则、管理员回放与至少一组并发测试；
6. 代码改动完成后按项目约定执行：

```bash
npx tsc --noEmit
```

这套结构的重点不在于让地图随时弹出更多事件，而在于每一次相遇都能解释：**谁为什么会在这里、玩家做了什么、谁记住了这件事，以及它后来如何改变了这片世界。**
