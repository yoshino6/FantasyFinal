# 窥尘问心实装成果（2026-09-14）

状态：**问心功能已编码并通过静态与数值规则测试；尚未执行真实数据库迁移、机器人重启或 QQ 客户端验收。** [全量有效操作育成实现方案](人物问心与全量有效操作育成实现方案V1.md)中的行迹事实账本、六维行为积分和质变兑换仍未实装，本文件不把它们计为已完成。

## 本轮已接入

| 范围 | 实际行为 |
| --- | --- |
| 升级出票 | 窥尘角色仅在实际升到 Lv.11～Lv.20 时，每级产生一张独立问心票；一次连升跨过该区间时按目标等级逐级出票。升到 Lv.21 及以后不再出票。普通经验与进化注射等实际升级路径执行同一范围判断；等级修复和管理员测试造级不出票。每张票的角色、目标等级唯一，并保存题目和六个选项快照。 |
| 题库 | V3 从 10 个逐题 TSV 素材生成 500 道运行时深层事件。题干全部采用事件陈述，不含问号或面向玩家的“你”式提问；每个片段从具体异世界冲突延伸到责任、牺牲、身份、真相、自由、秩序与后果。3000 个选项分别写出看破、承担与行动，并保留各自倾向／排斥。六种倾向对其余五种排斥组合均有覆盖；A—F 顺序依题号稳定打散。抽题排除该角色近 20 张票用过的事件。 |
| 升级消息与阻断 | 玩家主动操作造成升级后，当前操作的原消息之外再发一条问心题目消息。活动问心票未回答时，普通匹配指令及机巧形象图片上传被挡下并反复显示该题；后台结算产生的票在玩家下一次普通操作时显示。菜单、状态及管理员维护等既有高优先级指令仍可通行。 |
| ABCDEF／跳过 | 六个选项对应六个按键，服务端按角色归属、题号、未答状态校验。先跳过只把当前票变为待补答，解除普通操作阻断；连升多级的待展示题按顺序继续出现。重复或旧按钮不会重复结算。 |
| 面板补答 | 打开 `/角色` 或 `/我` 时，会为功能上线前已经超过 Lv.10 的窥尘角色幂等补齐 Lv.11～Lv.20 中缺失的问心票。只要仍有活动、待展示或已跳过的票，等级右边就显示 `[窥尘问心]`，点击后按等级顺序打开一张待答题；全部回答后不显示。待答状态不阻断人物面板与角色详情，但仍阻断其他普通操作。 |
| 题库换版 | 问心卡带内容版本号。打开人物面板、问心或触发普通操作检查时，V2 及更早的活动、排队、已跳过票会按原 `event_code` 刷新为 V3 快照，使已生成但未回答的角色实际看到新题；已经回答的票不改写，保留玩家当时看到和选择的历史内容。 |
| 数值 | 出生可塑成长与职业外源成长分别保存。普通结果概率 80%，倾向目标增量为该维现值 10% 且至少 1.0 点；实际增量受排斥维余额限制，同量转移。大成功概率 20%，不扣排斥维，只在六维出生预算 12.0 内增加倾向维。全部按 0.1 点整数单位结算。作答时保存历史等级补偿，因此当下六维属性不因过去等级回算而跳变，之后升级才生效。 |
| 结果 | 从 24 条普通、12 条大成功氛围文案中按结果类别抽取。玩家仅看到文案和实际发生变化的方向，例如 `智力成长↑，力量成长↓`；无变化时明确显示 `六维成长未发生变化`。概率类别、增减值和前后快照只保存在问心票结算 JSON 中，不出现在结果消息。 |

主要代码：`src/game/heart-question.service.ts`（票据、状态与事务结算）、`src/game/heart-question-rules.ts`（纯数值规则）、`src/game/heart-question-content.ts`（自动生成的 500 题与 36 条结果文案）、`src/middleware/heart-question.ts`（普通操作阻断）、`src/response/heart-question.ts`（题目与结果消息）。数据结构在 `src/database/bootstrap.ts`，升级路径分别接入 `src/game/adventure.service.ts` 与 `src/game/evolution.service.ts`，面板入口在 `src/response/character.ts`。运行时题库由 `scripts/build-heart-question-data.py` 从现有素材生成。

- `python scripts/render-question-bank.py`：V3 题库验证为 500 个独立陈述事件、3000 个不同立场选项、30 组完整倾向／排斥组合；所有题干无问号且不使用“你”向玩家提问。

- `test/heart-question-backfill.test.ts`：3 项通过，覆盖旧 Lv.20+ 角色只补 Lv.11～Lv.20、重复检查不重复出票、Lv.10 不出票，以及待答状态下人物面板入口仍可打开并显示在等级同行。

- `npm run build`：退出码 0，946 个模块完成转换；构建产物中的问心题库为 500 张 V3 卡片。打包器仍提示既有 TS5096 配置告警与循环依赖告警，未在本轮改动打包配置。

未执行实际数据库启动迁移或真实 QQ 按钮回调，因此上述通过不等同于已上线。首次启动时 `initializeSchema` 会创建两张新表；旧角色首次打开人物面板、主动打开问心或尝试普通操作时，系统会补齐其 Lv.11～Lv.20 中缺失的问心票，并从当前六维成长扣除已知职业成长，回建出生可塑成长。若角色已超过 Lv.20，也只补该十级区间。若历史成长来源无法解释或超出 12.0，服务会拒绝补票，不会猜测或静默截断；需要先核对该角色成长来源。发布前应在数据库副本上做旧角色补票预演，并走普通升级、连升、注射、跳过补答和并发旧按钮的真实业务路径。

## 未完成的原方案范围

本轮**没有**建立“人物所有有效操作”统一事实账本，也没有把买卖、委托接取／完成、战斗最终结算、NPC 交互、制作等全部业务结果接入六维倾向积分，更没有开放积分质变和行迹分页详情。现有问心票只记录问心本身的独立结算，不能代替全量行迹。旧实现方案对这部分的交付条件仍有效，后续完成时须逐项核对业务结果与账本事实，不得用指令日志充数。
